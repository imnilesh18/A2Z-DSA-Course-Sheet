## 📖 Problem Statement

You are given a binary string `s` and a positive integer `k`.

A substring of `s` is **beautiful** if the number of `1`'s in it is exactly `k`.

Let `len` be the length of the shortest beautiful substring.
Return the **lexicographically smallest beautiful substring** of string `s` with length equal to `len`. If `s` doesn't contain a beautiful substring, return an empty string.

> **Lexicographical Order:** A string `a` is lexicographically larger than a string `b` (of the same length) if in the first position where `a` and `b` differ, `a` has a character strictly larger than the corresponding character in `b`. For example, `"abcd"` is lexicographically larger than `"abcc"` because the first position they differ is at the fourth character, and `d` is greater than `c`.

---

## 🚦 Constraints

- `1 <= s.length <= 100`
- `1 <= k <= s.length`

---

## 📊 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "100011001"`, `k = 3` | `"11001"` | There are 7 beautiful substrings. The shortest length is 5. Among all length 5 beautiful substrings, `"11001"` is the lexicographically smallest. |
| **2** | `s = "1011"`, `k = 2` | `"11"` | The shortest beautiful substring has a length of 2. The lexicographically smallest is `"11"`. |
| **3** | `s = "000"`, `k = 1` | `""` | There are no `1`s in the string, so no beautiful substring exists. |

## 💡 Approach & Walkthrough

<details>
<summary><b>Method 1: Brute Force (Iterative Length Check)</b></summary>
<br>

Since the maximum length of the string is very small (`N = 100`), an $O(N^3)$ approach is completely viable. 
1. The shortest possible length for a valid string is exactly `k`. We can start searching for substrings of length `k`.
2. Iterate through all possible lengths from `k` up to `N`. 
3. For a given length, extract every possible substring of that size.
4. Count the number of `1`s. If it exactly matches `k`, we evaluate it.
5. Keep track of the lexicographically smallest valid substring.
6. The moment we find a valid substring for a specific length, we immediately return it because we are iterating from the smallest lengths upward.

</details>

<details open>
<summary><b>Method 2: Optimized Sliding Window (Recommended)</b></summary>
<br>

To optimize the search, we can utilize a Sliding Window approach.
1. Expand our window by dragging a right pointer `j` across the string, adding characters to our current substring and counting `1`s.
2. The critical step is **shrinking the window**. We shrink from the left (using pointer `i`) under two conditions:
   - If our count of `1`s exceeds `k` (we need exactly `k`).
   - If the character at our left pointer `i` is `'0'`. Leading zeros do not contribute to the `1` count but unnecessarily increase the length of our substring, making it suboptimal.
3. Every time our window holds exactly `k` ones, we extract the substring and update our best result if the current window is shorter or lexicographically smaller than the existing result.

</details>

## 💻 Solution Code

### Brute Force Solution

```cpp
// Intuition: To find the shortest substring, we can try checking all possible lengths starting from the minimum possible length, which is `k`.
// Approach:
// 1. Iterate over all possible lengths `len` from `k` up to `n`.
// 2. For each length, generate all possible substrings of that size.
// 3. Count the number of '1's in the substring.
// 4. If a substring has exactly `k` ones, compare it with the current best result.
// 5. Update the result if the new string is lexicographically smaller or if the result is empty.
// 6. Return the result immediately if found, since we process smaller lengths first.
// Time Complexity: O(n^3) - Outer loop for length, inner loop for start index, and string creation/counting takes O(n).
// Space Complexity: O(n) - For storing the temporary substring of length up to n.
class Solution {
public:
    string shortestBeautifulSubstring(string s, int k) {
        int n = s.length();

        // Try all possible substring lengths starting from minimum required (k)
        for(int len = k; len <= n; len++) {

            string result = "";

            // Generate all substrings of current length 'len'
            for(int start = 0; start + len <= n; start++) { 
                string temp = s.substr(start, len); //[start ... start+len]

                int ones = 0;
                // Count number of '1's in the current substring
                for (char ch : temp) {
                    ones += (ch == '1') ? 1 : 0;
                }

                // Keep it if it's beautiful and lexicographically smaller than current best
                if (ones == k) {
                    if (result.empty() || temp < result)
                        result = temp;
                }
            }
            
            // If we found a result of current length, it's guaranteed to be the shortest
            if(!result.empty())
                return result;
        }
        return "";
    }
};

/*
*
* Dry Run
* s = "1011", k = 2
* len = 2:
*   start = 0, temp = "10", ones = 1 (!= 2)
*   start = 1, temp = "01", ones = 1 (!= 2)
*   start = 2, temp = "11", ones = 2 (== 2). result = "11"
* Returns "11" because we found the shortest length.
*
*/
```

### Optimized Sliding Window Solution

```cpp
// Intuition: We can use a sliding window to dynamically expand and shrink the substring, maintaining the count of '1's.
// Approach:
// 1. Use two pointers `i` and `j` to represent a sliding window `[i, j]`.
// 2. Expand the window by moving `j` to the right and incrementing the '1's count.
// 3. Shrink the window from the left by moving `i` if `ones > k` or if `s[i] == '0'` (since leading zeroes don't help in finding the shortest valid string).
// 4. When the window contains exactly `k` ones, check its length and lexicographical order against the best result.
// 5. Update the result if the current window is strictly shorter, or of the same length but lexicographically smaller.
// Time Complexity: O(n^2) - Both pointers `i` and `j` traverse the string in O(n) time, but `substr` and string comparison take O(n) inside the loop.
// Space Complexity: O(1) auxiliary, O(n) considering the space used to extract substrings.
class Solution {
public:
    string shortestBeautifulSubstring(string s, int k) {
        int n = s.length();
        int i = 0;
        int ones = 0;     // Tracks number of '1's in current window [i, j]
        string result = "";

        for (int j = 0; j < n; j++) {
            // Expand window and count '1's
            if (s[j] == '1') 
                ones++;

            // Shrink window to remove extra '1's and trim leading '0's
            while (ones > k || s[i] == '0') {
                if (s[i] == '1') 
                    ones--;
                i++;
            }

            // If window has exactly 'k' ones, check if it's the best answer
            if (ones == k) {
                string temp = s.substr(i, j - i + 1);
                
                // Update result if it's empty, shorter, or lexicographically smaller
                if (result.empty()
                    || j - i + 1 < result.length()
                    || (j - i + 1 == result.length() && temp < result)) {

                    result = temp;
                }
            }
        }

        return result;
    }
};

/*
*
* Dry Run
* s = "100011001", k = 3
* j=0 (1), ones=1.
* j=1..3 (000), ones=1.
* j=4 (1), ones=2.
* j=5 (1), ones=3. Window: "100011" (length 6). Trim '0's? No, i=0 is '1'. temp="100011". result="100011"
* j=6,7 (00). ones=3. temp="10001100". Length is 8 > 6, ignored.
* j=8 (1). ones=4.
*   ones>3: shrink! i=0 ('1') -> ones=3, i=1.
*   s[i]=='0': shrink! i=2, 3, 4 ('1') -> i stops at 4.
*   Window [4, 8]: "11001". ones=3.
*   temp="11001". Length 5 < 6. result="11001"
* Returns "11001"
*
*/
```

## 🧠 Key Insights

* **Shrinking Logic is King:** The core of most sliding window problems lies in the conditions to shrink the window. Here, knowing that `s[i] == '0'` can safely be removed from the left side (since it contributes nothing to the `k` requirement but bloats the substring length) is the 'aha!' moment.
* **Lexicographical Fallback:** Always compare lengths first. If lengths are tied, default to lexicographical comparison. C++'s standard string operators `<` handle lexicographical comparisons out of the box natively.
