## 📖 Problem Statement

You are given a **0-indexed** array of integers `nums`.

A prefix `nums[0..i]` is considered **sequential** if, for all $1 \le j \le i$, `nums[j] = nums[j - 1] + 1`. In particular, the prefix consisting only of `nums[0]` is automatically sequential.

Return the *smallest integer* `x` missing from `nums` such that `x` is greater than or equal to the sum of the longest sequential prefix.

---

## 🚦 Constraints

- $1 \le \text{nums.length} \le 50$
- $1 \le \text{nums}[i] \le 50$

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [1,2,3,2,5]` | `6` | The longest sequential prefix of `nums` is `[1,2,3]` with a sum of 6. Since `6` is not in the array, `6` is the smallest missing integer greater than or equal to the sum. |
| **2** | `nums = [3,4,5,1,12,14,13]` | `15` | The longest sequential prefix is `[3,4,5]` with a sum of `12`. `12`, `13`, and `14` are present in the array, but `15` is missing. Thus, `15` is the answer. |

---

## 🧠 Approach & Explanation

To conquer this problem, you need to understand the definition of a **sequential prefix**. A prefix is sequential if it strictly starts at index `0` and every subsequent element is exactly $1$ greater than its previous element (i.e., `nums[j] == nums[j-1] + 1`).

**Step-by-step breakdown:**
1. **Find the Sequential Prefix Sum:** 
   Start at index `0` and initialize your `sequential` sum with `nums[0]`. Iterate through the array starting from index `1`. As long as the current number is exactly $1$ more than the previous number, add it to your `sequential` sum. The moment this condition breaks, you stop. This gives you the sum of the longest valid prefix.
2. **Find the Smallest Missing Integer:**
   Once you have the `sequential` sum, you need to check if this exact sum exists in the original `nums` array.
   - If it **does not** exist, this sum is your answer!
   - If it **does** exist, you must look for the next smallest integer (i.e., `sum + 1`). You keep incrementing your target and searching the array until you find a number that is entirely missing.

To search efficiently:
* **Approach 1 (Set):** Dump all elements into an `unordered_set`. Checking if an element exists takes $O(1)$ time on average. 
* **Approach 2 (Sorting):** Sort the array first. Iterate through the sorted array and whenever you see your current target `sequential`, increment it by $1$. This uses $O(1)$ auxiliary space.

## 💻 Solution Code

### 1️⃣ Brute-force / Set Solution (C++)

<details>
<summary>Click to reveal Approach 1: Using Hash Set (O(n) Space)</summary>

```cpp
// Intuition: The problem requires finding the sum of the longest sequential prefix starting from index 0. Once we have the sum, we must find the smallest number >= this sum that is absent from the array. A hash set allows O(1) lookups to quickly check for the missing integer.
// Approach: 
// 1. Store all elements of 'nums' in an unordered_set.
// 2. Initialize 'sequential' sum with nums[0].
// 3. Loop from index 1. If nums[j] == nums[j-1] + 1, add it to 'sequential'. Else, break.
// 4. Continuously increment 'sequential' while it exists in the set.
// Time Complexity: O(n) - We iterate through the array to find the prefix and then check the set. Average set lookup is O(1).
// Space Complexity: O(n) - We use an unordered_set to store up to n elements.
class Solution {
public:
    int missingInteger(vector<int>& nums) {
        int n = nums.size(); // Get the total number of elements

        // Populate a set for O(1) average time lookups
        unordered_set<int> st(begin(nums), end(nums));

        int sequential = nums[0]; // Initialize sum with the first element
        
        // Traverse to find the longest sequential prefix
        for(int j = 1; j < n; j++) {
            if(nums[j] == nums[j-1] + 1) {
                sequential += nums[j]; // Add valid sequential elements
            } else {
                break; // Stop at the first non-sequential break
            }
        }

        // Search for the smallest missing integer
        while(st.count(sequential)) { // O(1) average complexity per check
            sequential++; // Increment until a missing number is found
        }

        return sequential;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3, 2, 5]
* 1. Initialize sequential = 1 (nums[0]).
* 2. j = 1: nums[1](2) == nums[0]+1. sequential = 1 + 2 = 3.
* 3. j = 2: nums[2](3) == nums[1]+1. sequential = 3 + 3 = 6.
* 4. j = 3: nums[3](2) != nums[2]+1. Loop breaks.
* 5. Set populated with {1, 2, 3, 5}.
* 6. Check if 6 is in set -> False. Loop breaks.
* 7. Return 6.
*
*/
```

### 2️⃣ Optimized Solution (C++)

<details open>
<summary>Click to reveal Approach 2: Using Sorting (O(1) Space)</summary>

```cpp
// Intuition: We can optimize the space complexity by avoiding the hash set. Instead, after finding the sequential sum, we sort the array. We can then iterate through the sorted array to easily find the first missing integer.
// Approach:
// 1. Initialize 'sequential' sum with nums[0].
// 2. Loop from index 1. If nums[j] == nums[j-1] + 1, add it to 'sequential'. Else, break.
// 3. Sort the array in ascending order.
// 4. Iterate through the array. If the current element equals 'sequential', increment 'sequential'.
// Time Complexity: O(n log n) - Sorting the array dominates the time complexity.
// Space Complexity: O(1) - Sorting is done in-place, requiring no extra space.
class Solution {
public:
    int missingInteger(vector<int>& nums) {
        int n = nums.size(); // Get the total number of elements

        int sequential = nums[0]; // Initialize sum with the first element
        
        // Traverse to find the longest sequential prefix
        for(int j = 1; j < n; j++) {
            if(nums[j] == nums[j-1] + 1) {
                sequential += nums[j]; // Add valid sequential elements
            } else {
                break; // Stop at the first non-sequential break
            }
        }

        // Sort array to find the missing integer in O(1) space
        sort(begin(nums), end(nums));
        
        // Traverse sorted array to increment past existing numbers
        for(int i = 0; i < n; i++) {
            if(nums[i] == sequential)
                sequential++; // Move to the next integer if current is found
        }

        return sequential;
    }
};

/*
*
* Dry Run
* Input: nums = [3, 4, 5, 1, 12, 14, 13]
* 1. Initialize sequential = 3.
* 2. j = 1: nums[1](4) == nums[0]+1. sequential = 3 + 4 = 7.
* 3. j = 2: nums[2](5) == nums[1]+1. sequential = 7 + 5 = 12.
* 4. j = 3: nums[3](1) != nums[2]+1. Loop breaks.
* 5. Sort nums array -> [1, 3, 4, 5, 12, 13, 14].
* 6. Loop i = 0 to 6:
*    - matches 12 at index 4, sequential becomes 13.
*    - matches 13 at index 5, sequential becomes 14.
*    - matches 14 at index 6, sequential becomes 15.
* 7. Return 15.
*
*/
```

## 🔑 Key Insights

- **Prefix Requirement:** The problem specifically asks for a sequential *prefix*. This means it strictly must start at index `0`. Do not look for sequential subarrays in the middle of the array!
- **Space-Time Trade-off:** Using an `unordered_set` yields the optimal $O(N)$ time complexity but costs $O(N)$ auxiliary space. Sorting reduces space to $O(1)$ but bumps time complexity up to $O(N \log N)$. Given the very small constraints ($N \le 50$), both run practically instantaneously (0ms on LeetCode).
