# 2958. Length of Longest Subarray With at Most K Frequency

**Problem Link:** [2958. Length of Longest Subarray With at Most K Frequency](https://leetcode.com/problems/length-of-longest-subarray-with-at-most-k-frequency/description)
**Difficulty:** Medium
**Tags:** `Array`, `Hash Table`, `Sliding Window`

---

## 📖 Problem Statement

You are given an integer array `nums` and an integer `k`.

The frequency of an element `x` is the number of times it occurs in an array.

An array is called **good** if the frequency of each element in this array is **less than or equal** to `k`.

Return *the length of the longest good subarray of* `nums`.

A **subarray** is a contiguous non-empty sequence of elements within an array.

---

## 🛑 Constraints

* `1 <= nums.length <= 10^5`
* `1 <= nums[i] <= 10^9`
* `1 <= k <= nums.length`

### Approach 1: Classic Sliding Window Template
This is a standard sliding window problem. We use two pointers, `i` (left) and `j` (right), starting at the 0th index. 
As `j` moves forward, we continuously add elements to our window and update their frequencies in a Hash Map. If we encounter a situation where the frequency of the newly added element `nums[j]` exceeds `k`, our current window becomes invalid. To make it valid again, we begin shrinking the window from the left by moving the `i` pointer and decrementing the frequencies of `nums[i]` until the frequency of the violating element drops back down to `k`. At every valid step, we record the maximum length encountered using `j - i + 1`.

### Approach 2: Optimized Single-Pass Window (Without Nested Loops)
We can eliminate the inner `while` loop to make the transitions smoother and purely single-pass for both pointers. 
Instead of actively shrinking the window back to a valid state immediately, we keep track of the number of "culprits" (elements whose frequency has exceeded `k`). When an element's frequency hits `k + 1`, we increment our `culprit` counter. If `culprit > 0`, the current window is invalid. Instead of shrinking the window in a loop, we simply shift the entire window to the right: we increment `j` (which expands the right) and simultaneously increment `i` (which trims the left), maintaining the *same maximum length window size* we've found so far. We decrement `nums[i]`'s frequency as we shift, and if its frequency drops to exactly `k`, we know a culprit was resolved, so we decrement the `culprit` counter. We only update our `result` when `culprit == 0`.

## 💻 Solution Code

### Approach 1: Classic Sliding Window Template (C++)

```cpp
// Intuition: The problem requires finding the longest contiguous subarray where no element appears more than k times. A sliding window is ideal here. We expand to the right and if any element's count exceeds k, we shrink from the left until the window is valid.
// Approach: 
// 1. Initialize left pointer i and right pointer j to 0. Use a hash map to store frequencies.
// 2. Traverse the array with j, incrementing the frequency of nums[j].
// 3. While the frequency of nums[j] is strictly greater than k, shrink the window from the left by decrementing the frequency of nums[i] and moving i forward.
// 4. Update the maximum window length at each valid configuration.
// Time Complexity: O(n) where n is the size of the array. Each element is visited at most twice (once by j, once by i).
// Space Complexity: O(n) in the worst case to store the frequencies of all unique elements in the hash map.
class Solution {
public:
    int maxSubarrayLength(vector<int>& nums, int k) {
        int n = nums.size();
        
        unordered_map<int, int> mp; // Stores element frequencies in current window
        
        int i = 0; // Left boundary of window
        int j = 0; // Right boundary of window
        int result = 0; // Tracks maximum valid subarray length
        
        while(j < n) {
            
            mp[nums[j]]++; // Add new element to window
            
            // Shrink window from left if current element violates the <= k condition
            while(i < j && mp[nums[j]] > k) {
                mp[nums[i]]--; // Remove left-most element from window
                i++; // Contract window size
            }
            
            // Record the max length of valid window
            result = max(result, j - i + 1);
            j++; // Expand window to the right
        }
        
        return result;
    }
};

/*
*
* Dry Run
*
* nums = [1,2,1,2,1,2,1,2], k = 1
* j=0, nums[0]=1, mp[1]=1. Valid. result = max(0, 1) = 1.
* j=1, nums[1]=2, mp[2]=1. Valid. result = max(1, 2) = 2.
* j=2, nums[2]=1, mp[1]=2. Invalid! mp[1] > 1. 
* Shrink: i=0, nums[0]=1, mp[1]=1, i=1. Valid again. result = max(2, 2) = 2.
* j=3, nums[3]=2, mp[2]=2. Invalid! mp[2] > 1.
* Shrink: i=1, nums[1]=2, mp[2]=1, i=2. Valid again. result = max(2, 2) = 2.
* Loop continues, window size never exceeds 2.
* Final result is 2.
*
*/
```

### Approach 2: Without Nested Loop (C++)

```cpp
// Intuition: We can avoid the inner while loop by introducing a "culprit" counter. If our window becomes invalid, we simply shift the entire window to the right without expanding its size until the culprit is resolved.
// Approach:
// 1. Maintain a culprit counter for elements whose frequency strictly exceeds k.
// 2. Expand window with j. If the new element's frequency hits k + 1, increment culprit count.
// 3. If there are culprits, the window is invalid. Shift the window by incrementing i.
// 4. When shifting, if the removed nums[i]'s frequency drops back down to k, decrement culprit count.
// 5. Update the result length only when culprit count is exactly 0.
// Time Complexity: O(n) as it operates in a single pass. Both i and j pointers iterate through the array simultaneously without inner loops.
// Space Complexity: O(n) to keep track of the frequency of elements in the hash map.
class Solution {
public:
    int maxSubarrayLength(vector<int>& nums, int k) {
        int n = nums.size();
        unordered_map<int, int> mp; // Frequency map
        
        int i = 0; // Left pointer
        int j = 0; // Right pointer
        int result = 0; // Max length tracker
        
        int culprit = 0; // Count of elements exceeding allowed frequency k
        
        while(j < n) {
            
            mp[nums[j]]++; // Include right-most element
            
            // Check if adding this element creates a new culprit
            if(mp[nums[j]] == k + 1) {
                culprit++;
            }
            
            // If window is invalid, slide the whole window forward without growing it
            if(culprit > 0) {
                mp[nums[i]]--; // Remove left-most element
                
                // If the removed element was a culprit, resolve it
                if(mp[nums[i]] == k) {
                    culprit--;
                }
                i++; // Slide left edge
            }
            
            // Only update max length if window is entirely valid
            if(culprit == 0) {
                result = max(result, j - i + 1);
            }
            j++; // Always advance right edge
        }
        
        return result;
    }
};

/*
*
* Dry Run
*
* nums = [1,2,3,1,2,3,1,2], k = 2
* j=0 to j=5: Window expands safely. Elements 1, 2, and 3 all have frequency <= 2. culprit=0. result=6.
* j=6: nums[6]=1. mp[1]=3. mp[1] == 3 (k+1), culprit=1.
* culprit > 0: mp[nums[0]] (which is 1) is decremented. mp[1]=2. mp[1] == 2, so culprit=0. i=1.
* culprit == 0: result = max(6, 6-1+1) = 6. 
* j=7: nums[7]=2. mp[2]=3. mp[2] == 3 (k+1), culprit=1.
* culprit > 0: mp[nums[1]] (which is 2) is decremented. mp[2]=2. mp[2] == 2, so culprit=0. i=2.
* culprit == 0: result = max(6, 7-2+1) = 6.
* Final result is 6.
*
*/
```

## 📌 Notes & Key Insights

* **Sliding Window Optimization:** The difference between Approach 1 and Approach 2 highlights a beautiful optimization pattern. While Approach 1 aggressively shrinks the window using a `while` loop, Approach 2 keeps the window at its maximum discovered length and merely shifts it forward (sliding it like a fixed frame) until the condition is met again. 
* **Complexity Clarification:** Some developers get confused thinking nested `while` loops imply $O(N^2)$ time complexity. It is important to trace pointer movements. Since the `i` pointer only moves forward and never resets, it travels across the array a maximum of $N$ times globally. Therefore, $O(N)$ for `j` + $O(N)$ for `i` results in a total Time Complexity of $O(N)$.
