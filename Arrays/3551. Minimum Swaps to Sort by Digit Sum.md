# 3551. Minimum Swaps to Sort by Digit Sum

## 📝 Problem Statement

You are given an array `nums` of distinct positive integers. You need to sort the array in increasing order based on the sum of the digits of each number. If two numbers have the same digit sum, the smaller number appears first in the sorted order.

Return the minimum number of swaps required to rearrange `nums` into this sorted order.

A swap is defined as exchanging the values at two distinct positions in the array.

### 🎯 Constraints:
- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `nums` consists of distinct positive integers.

## 🚀 Approach

### Brute Force (Conceptual)
A naive approach would be to find all possible permutations of the array, calculate the number of swaps to reach each, and check which one matches the target sorted state. This takes $O(N!)$ time and is completely unfeasible for array sizes up to $10^5$.

### Optimized Approach (Sort, Map, and Swap)
1. **Determine Target Array:** Create a copy of the original array and sort it based on the custom rules (digit sum first; if tied, actual value). This gives us the "expected" array.
2. **Index Mapping:** Since all elements are distinct, store the index of each element from the original array in a Hash Map (`unordered_map`). This allows $O(1)$ lookups for an element's current position.
3. **Cycle Sorting / Greedy Swapping:** Iterate through the original array. If the element at the current index does not match the expected element from the sorted array:
   - Use the Hash Map to find where the expected element currently resides.
   - Swap the current element with the expected element.
   - Update the Hash Map with the new indices for both swapped elements.
   - Increment the swap counter.
4. Each swap guarantees that at least one element is placed in its absolute correct final position, achieving the minimum number of swaps.

## 💻 Solution Code

```cpp
// Intuition: To find the minimum swaps to reach a specific sorted configuration, we can pre-calculate the target sorted array. By tracking elements using a hash map, we can greedily swap elements into their correct positions in a cycle-sort-like manner, guaranteeing minimal swaps.
// Approach: 
// 1. Create `afterSorted` as a copy of `nums` and sort it using a custom lambda function based on digit sums.
// 2. Map each element to its current index in `nums` using an `unordered_map`.
// 3. Iterate through `nums`. For each index `i`, compare `currVal` with `expectedVal`.
// 4. If they differ, find the index of `expectedVal` using the map, perform a swap, update the map, and increment `swapCount`.
// Time Complexity: O(n log n * N) where n is the length of nums and N is log10(max_num) for extracting digits during the sort.
// Space Complexity: O(n) for the hash map and the copied array.

class Solution {
public:

    // Helper function to calculate the sum of digits
    int getDigitSum(int num) {
        int sum = 0;

        while(num > 0) {
            sum += (num % 10); // Extract last digit
            num /= 10;         // Remove last digit
        }

        return sum;
    }

    int minSwaps(vector<int>& nums) {
        int n = nums.size();

        // Copy array to determine the target sorted order
        vector<int> afterSorted(nums);

        // Custom comparator for sorting based on digit sums
        auto lambda = [&](int num1, int num2) {
            int num1DigitSum = getDigitSum(num1); // log10(num)
            int num2DigitSum = getDigitSum(num2);

            // Sort by digit sum if they are different
            if(num1DigitSum != num2DigitSum) {
                return num1DigitSum < num2DigitSum;
            }

            // If digit sums are equal, smaller number comes first
            return num1 < num2;
        };

        // Sort the copied array to get the expected sequence
        sort(begin(afterSorted), end(afterSorted), lambda); // nlogn * N

        // Track current positions of all elements
        unordered_map<int, int> valToIdx;
        for(int i = 0; i < n; i++) { // O(n)
            valToIdx[nums[i]] = i;
        }
        
        int swapCount = 0;
        
        // Greedily place elements in their correct positions
        for(int i = 0; i < n; i++) { // O(n)
            int expectedVal = afterSorted[i];
            int currVal     = nums[i];

            // Element is already in the correct position
            if(expectedVal == currVal) continue;

            // Find where the expected value currently is
            int idx = valToIdx[expectedVal];

            // Perform the swap in the array
            nums[i] = expectedVal;
            nums[idx] = currVal;

            // Update the map to reflect the new positions
            valToIdx[expectedVal] = i;
            valToIdx[currVal] = idx;

            swapCount++; // Increment swap counter
        }

        return swapCount;
    }
};

/*
*
* Dry Run
* Input: nums = [18, 43, 34, 16]
* 1. Target array generation:
*    Digit sums -> 18:9, 43:7, 34:7, 16:7
*    Sorted expected array (afterSorted) -> [16, 34, 43, 18]
* 2. Hash Map initialization:
*    valToIdx = {18:0, 43:1, 34:2, 16:3}
* 3. Iteration step-by-step:
*    i = 0: expected = 16, current = 18.
*           Find 16 at index 3. Swap nums[0] and nums[3].
*           nums becomes [16, 43, 34, 18].
*           valToIdx updated: {16:0, 18:3}. swapCount = 1.
*    i = 1: expected = 34, current = 43.
*           Find 34 at index 2. Swap nums[1] and nums[2].
*           nums becomes [16, 34, 43, 18].
*           valToIdx updated: {34:1, 43:2}. swapCount = 2.
*    i = 2: expected = 43, current = 43. Match. Continue.
*    i = 3: expected = 18, current = 18. Match. Continue.
* 4. Return swapCount = 2.
*
*/
```

## 🧠 Key Insights
- **Custom Sorting:** Capturing custom comparator logic in C++ requires careful handling. A lambda function safely encapsulates this logic, but if capturing variables from the outer scope, `[&]` must be used.
- **Cycle Sort Variation:** The minimum swaps to sort a distinct array usually involves finding cycles in a permutation graph. By using an expected state array alongside a hash map for $O(1)$ index lookups, we implicitly resolve these cycles swap by swap, locking exactly one target element into place per operation.
- **Distinct Integer Guarantee:** The constraint that all elements are strictly distinct allows the hash map to function flawlessly without collision handling for duplicate values.

## 🔗 Further Exploration
- **Graph Theory in Arrays:** This problem strongly relates to finding connected components (cycles) in a directed graph where edges exist between current indexes and target indexes.
- **Custom Sorts in Different Languages:** Implementing the custom comparator translates cleanly into Python via `list.sort(key=...)` and Java via `Arrays.sort()` with custom `Comparator` objects.
