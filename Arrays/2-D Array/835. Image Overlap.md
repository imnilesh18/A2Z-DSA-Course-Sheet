## 📝 Problem Statement

You are given two images, `img1` and `img2`, represented as binary, square matrices of size `n x n`. A binary matrix has only `0`s and `1`s as values.

We translate one image however we choose by sliding all the `1` bits left, right, up, and/or down any number of units. We then place it on top of the other image. We can then calculate the **overlap** by counting the number of positions that have a `1` in both images.

*Note also that a translation does not include any kind of rotation. Any `1` bits that are translated outside of the matrix borders are erased.*

Return the largest possible overlap.

---

## 🚦 Constraints

| Constraint | Value |
| :--- | :--- |
| **Grid Size** | `n == img1.length == img1[i].length` <br> `n == img2.length == img2[i].length` |
| **Size Limit** | `1 <= n <= 30` |
| **Value Domain** | `img1[i][j]` is either `0` or `1`. <br> `img2[i][j]` is either `0` or `1`. |

## 🧠 Explanation

This problem frequently appears in Google interviews and requires strong spatial visualization. 

Instead of trying to shift matrices infinitely, we can deduce the mathematical limits of an overlap. If we keep `img1` fixed and slide `img2` over it:
1. The maximum we can slide `img2` *up* or *left* before it completely stops overlapping is `n - 1`. 
2. The maximum we can slide `img2` *down* or *right* is also `n - 1`.

This gives us a definitive range for our shifts (offsets):
- **Row Offset (`rowOff`)**: Ranges from `-(n - 1)` to `n - 1`.
- **Column Offset (`colOff`)**: Ranges from `-(n - 1)` to `n - 1`.

For any given offset configuration, we can determine overlapping cells by matching cell `(row, col)` from `img1` to cell `(row + rowOff, col + colOff)` in `img2`. 
- If the shifted coordinates fall outside the boundaries of `img2`, that part of the image has slid out of view, so we ignore it.
- If it is within bounds, multiplying the cell values (`img1[row][col] * img2[row+rowOff][col+colOff]`) will act as a perfect filter: it results in `1` *only* if both original cells contain a `1`.

## 💻 Brute-force Solution (C++)

```cpp
// Intuition: We can determine the maximum overlap by testing all valid spatial translations of matrix B over matrix A. The maximum shift in any axis is bounded by (n-1).
// Approach:
// 1. Iterate through all possible row shifts from -(n-1) to (n-1).
// 2. Iterate through all possible column shifts from -(n-1) to (n-1).
// 3. For every (rowOff, colOff) pair, count overlaps by traversing matrix A and matching it to shifted coordinates in matrix B.
// 4. Update the global maximum overlap.
// Time Complexity: O(n^4), since there are roughly 4n^2 offsets to test, and checking each offset involves traversing the n x n matrix.
// Space Complexity: O(1), as no auxiliary data structures scaling with input size are used.
class Solution {
public:
    int countOverlaps(vector<vector<int>>& A, vector<vector<int>>& B, int rowOff, int colOff) {
        int n = A.size();
        int count = 0;
        
        // Traverse every cell in the stationary matrix A
        for(int row = 0; row < n; row++) {
            for(int col = 0; col < n; col++) {
                // Ensure the shifted coordinates map to valid cells in matrix B
                if(row+rowOff < 0 || row+rowOff >= n || col+colOff < 0 || col+colOff >= n)
                    continue;
                
                // Multiplication ensures we only add 1 if both A and B have 1 at overlapping positions
                count += A[row][col]*B[row+rowOff][col+colOff];
            }
        }
        
        return count;
    }

    int largestOverlap(vector<vector<int>>& A, vector<vector<int>>& B) {
        int n = A.size();
        int maxOverlap = 0;
        
        // rowOff limits: -(n-1) to (n-1) sliding from bottom-left
        for(int rowOff = -n+1; rowOff<n; rowOff++) {
            // colOff limits: -(n-1) to (n-1) sliding horizontally
            for(int collOff = -n+1; collOff<n; collOff++) {
                // Determine the overlap for this configuration and update max
                maxOverlap = max(maxOverlap, countOverlaps(A, B, rowOff, collOff));
            }
        }
        
        return maxOverlap;
    }
};

/*
*
* Dry Run
* A = [[0,1],[0,0]], B = [[0,0],[1,0]], n = 2
* maxOverlap = 0
* 
* Loop rowOff = -1:
*   Loop colOff = -1:
*     countOverlaps calls with rowOff=-1, colOff=-1
*     Valid coordinate mapping:
*     A[1][1] -> B[0][0] => 0 * 0 = 0
*     count = 0. maxOverlap = 0.
*   
*   Loop colOff = 0:
*     Valid coordinate mappings:
*     A[1][0] -> B[0][0] => 0 * 0 = 0
*     A[1][1] -> B[0][1] => 0 * 0 = 0
*     count = 0. maxOverlap = 0.
* 
* ...
* 
* Loop rowOff = 1:
*   Loop colOff = -1:
*     countOverlaps calls with rowOff=1, colOff=-1
*     Valid coordinate mapping:
*     A[0][1] -> B[1][0] => 1 * 1 = 1
*     count = 1.
*     maxOverlap = max(0, 1) = 1.
* 
* End loops. Return maxOverlap (1).
*
*/

```

## 🚀 Optimized Solution (C++)

```cpp
// Intuition: Instead of shifting the entire grid and checking all n^2 cells every time, we can extract coordinates of '1's in both images and find identical translation vectors.
// Approach:
// 1. Traverse both matrices and store the coordinates of all '1' bits for img1 and img2.
// 2. Calculate the difference vector (translation vector) between every '1' in img1 and every '1' in img2.
// 3. Keep a frequency count of these translation vectors using a Hash Map.
// 4. The vector with the highest frequency represents the shift that aligns the maximum number of '1's.
// Time Complexity: O(n^2 + V_A * V_B) where V_A and V_B are the total number of '1' bits in img1 and img2 respectively. In the worst case it approaches O(n^4) but is drastically faster for sparse matrices.
// Space Complexity: O(n^2) to store the vectors and the hash map.
class Solution {
public:
    int largestOverlap(vector<vector<int>>& img1, vector<vector<int>>& img2) {
        int n = img1.size();
        vector<pair<int, int>> onesImg1;
        vector<pair<int, int>> onesImg2;
        
        // Extract coordinates of all 1s from img1
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (img1[i][j] == 1) onesImg1.push_back({i, j});
                if (img2[i][j] == 1) onesImg2.push_back({i, j});
            }
        }
        
        unordered_map<string, int> vectorCounts;
        int maxOverlap = 0;
        
        // Calculate all translation vectors bridging a 1 in img1 to a 1 in img2
        for (auto& pa : onesImg1) {
            for (auto& pb : onesImg2) {
                // Encode the translation vector as a string key
                string key = to_string(pa.first - pb.first) + "_" + to_string(pa.second - pb.second);
                vectorCounts[key]++;
                maxOverlap = max(maxOverlap, vectorCounts[key]);
            }
        }
        
        return maxOverlap;
    }
};

/*
*
* Dry Run
* img1 = [[1,1,0],[0,1,0],[0,1,0]], img2 = [[0,0,0],[0,1,1],[0,0,1]]
* onesImg1 = [(0,0), (0,1), (1,1), (2,1)]
* onesImg2 = [(1,1), (1,2), (2,2)]
* 
* pa=(0,0), pb=(1,1) -> key: "-1_-1" => count: 1
* pa=(0,1), pb=(1,2) -> key: "-1_-1" => count: 2
* pa=(1,1), pb=(2,2) -> key: "-1_-1" => count: 3 
* 
* maxOverlap updates to 3 for translation vector (-1, -1).
* Result: 3
*
*/

```

## 📝 Notes & Key Insights

* **Sparse vs. Dense Strategy:** If the matrices are heavily populated with 1s (dense), the Brute-Force grid shifting strategy $O(n^4)$ is straightforward and avoids expensive hash map overheads. If the matrices are sparse, mapping out the `1`s and computing translation vectors is substantially faster in practice.
* **Why `2N - 1`?:** When sliding an $N \times N$ matrix completely from edge to edge against another $N \times N$ matrix, the number of distinct overlapping steps on a 1D axis is exactly $2N - 1$.
* **Boundary Handling:** Avoiding matrix out-of-bounds errors is the primary logical trap in this question. Doing inline constraint checks `(row+rowOff < 0)` ensures we don't cause segment faults.
