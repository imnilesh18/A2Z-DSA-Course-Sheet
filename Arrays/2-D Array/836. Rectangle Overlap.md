## 📖 Problem Statement

An axis-aligned rectangle is represented as a list `[x1, y1, x2, y2]`, where `(x1, y1)` is the coordinate of its bottom-left corner, and `(x2, y2)` is the coordinate of its top-right corner. Its top and bottom edges are parallel to the X-axis, and its left and right edges are parallel to the Y-axis.

Two rectangles overlap if the area of their intersection is positive. To be clear, two rectangles that only touch at the corner or edges **do not** overlap.

Given two axis-aligned rectangles `rec1` and `rec2`, return `true` if they overlap, otherwise return `false`.

---

## 📊 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `rec1 = [0,0,2,2]`, `rec2 = [1,1,3,3]` | `true` | The rectangles share a positive overlapping area. |
| **2** | `rec1 = [0,0,1,1]`, `rec2 = [1,0,2,1]` | `false` | The rectangles only touch at the edge/corner. |
| **3** | `rec1 = [0,0,1,1]`, `rec2 = [2,2,3,3]` | `false` | The rectangles are completely separated. |

---

## 🚫 Constraints

- `rec1.length == 4`
- `rec2.length == 4`
- `-10^9 <= rec1[i], rec2[i] <= 10^9`
- `rec1` and `rec2` represent a valid rectangle with a non-zero area.

## 🧠 Approach

<details>
<summary>Click to view the step-by-step logical breakdown</summary>

1. **Understanding Rectangle Intersections:** For two axis-aligned rectangles to overlap, their projections on **both** the X-axis and Y-axis must overlap.
2. **The Inverse Logic (Brute Force equivalent):** It is often easier to determine when two rectangles *do not* overlap. They do not overlap if one is completely to the left, right, top, or bottom of the other. Negating this disjoint condition gives us the overlap.
3. **The Direct Logic (Optimized):** We can directly verify if the intersection forms a valid rectangle. A valid overlap occurs when the `left_max < right_min` and `bottom_max < top_min`. 
4. Applying this directly means we ensure that `rec1`'s left side is strictly less than `rec2`'s right side, and vice versa. We do the exact same check for the top and bottom edges.

</details>

## 💻 Solution Code (Brute Force & Optimized)

```cpp
// Intuition: Two rectangles overlap only if their horizontal ranges and vertical ranges overlap. So, check that neither rectangle is completely to the left/right or above/below the other.
// Approach: 
// 1. A rectangle is completely to the left if its right edge is <= the other's left edge.
// 2. Apply this inverse logic for right, top, and bottom to build a brute-force disqualifier.
// 3. For the optimized approach, directly check the positive overlap condition: left < right and bottom < top across both shapes.
// Time Complexity: O(1) - Constant time complexity as we only perform a few mathematical comparisons.
// Space Complexity: O(1) - No extra space is required, only primitive variables are evaluated.

class Solution {
public:
    // Brute-force / Inverse check approach
    bool isRectangleOverlap(vector<int>& rec1, vector<int>& rec2) {
        // Check if rec1 is completely outside rec2
        bool isLeft = rec1[2] <= rec2[0];
        bool isRight = rec1[0] >= rec2[2];
        bool isBelow = rec1[3] <= rec2[1];
        bool isAbove = rec1[1] >= rec2[3];
        
        // Overlap happens if it's NOT entirely outside
        return !(isLeft || isRight || isBelow || isAbove);
    }
};
```
```cpp
class Solution {
public:
    // Optimized Approach
    bool isRectangleOverlap(vector<int>& rec1, vector<int>& rec2) {
        // Directly check if projections on both X and Y axes overlap
        return rec1[0] < rec2[2] && rec2[0] < rec1[2] &&
               rec1[1] < rec2[3] && rec2[1] < rec1[3];
    }
};

/*
*
* Dry Run
*
* Input: rec1 = [0,0,2,2], rec2 = [1,1,3,3] (Testing Optimized Solution)
* 
* Step 1: Check X-axis projection overlap
* -> rec1[0] < rec2[2] => 0 < 3 (True)
* -> rec2[0] < rec1[2] => 1 < 2 (True)
* 
* Step 2: Check Y-axis projection overlap
* -> rec1[1] < rec2[3] => 0 < 3 (True)
* -> rec2[1] < rec1[3] => 1 < 2 (True)
* 
* All conditions are met (True && True && True && True).
* Result: true
*
*/
```

## 📝 Notes
- Since the constraints specify that the inputs will always represent valid rectangles with non-zero areas, we do not need to implement safety checks for invalid lines or points.
- Checking conditions on a 1D line projection first (X-axis) and then applying the same principles to the Y-axis simplifies most 2D geometric problems.

## 💡 Key Insights
- **De Morgan's Laws in Geometry:** The optimized logic is mathematically equivalent to the negated disjoint logic (Brute Force) through De Morgan's laws. Proving that something *is* overlapping is the exact inverse of proving it *isn't*.
- Because the coordinates can go up to `10^9`, ensure you don't calculate the actual area (which could cause integer overflow). Direct coordinate comparisons avoid overflow completely.
