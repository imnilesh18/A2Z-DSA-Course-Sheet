# 1464. Maximum Product of Two Elements in an Array

**Difficulty:** Easy
**Problem Link:** [LeetCode 1464](https://leetcode.com/problems/maximum-product-of-two-elements-in-an-array/)

---

## 📝 Problem Statement

Given the array of integers `nums`, you will choose two different indices `i` and `j` of that array. 

Return the maximum value of $(nums[i]-1) \times (nums[j]-1)$.

---

## 🚦 Constraints

*   $2 \le nums.length \le 500$
*   $1 \le nums[i] \le 10^3$

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [3,4,5,2]` | `12` | If you choose the indices $i=1$ and $j=2$ (indexed from 0), you will get the maximum value, that is, $(nums[1]-1) \times (nums[2]-1) = (4-1) \times (5-1) = 3 \times 4 = 12$. |
| **2** | `nums = [1,5,4,5]` | `16` | Choosing the indices $i=1$ and $j=3$ (indexed from 0), you will get the maximum value of $(5-1) \times (5-1) = 16$. |
| **3** | `nums = [3,7]` | `12` | Choosing indices 0 and 1 gives $(3-1) \times (7-1) = 2 \times 6 = 12$. |

## 🧠 Approach

### Brute Force Approach
The most straightforward way is to check every possible pair in the array using two nested loops. We calculate $(nums[i]-1) \times (nums[j]-1)$ for all pairs and keep track of the maximum result. However, this yields a time complexity of $O(N^2)$, which is inefficient for larger arrays.

### Optimized Approach
To maximize the product $(nums[i]-1) \times (nums[j]-1)$, we simply need to find the **two largest numbers** in the array. Since the array contains only positive integers ($1 \le nums[i]$), the largest product will always come from the two maximum values. We can find these two values in a single pass ($O(N)$ time) by maintaining two variables: `largest` and `sec_largest`. 
1. Iterate through the array.
2. If the current number is greater than `largest`, update `sec_largest` to the old `largest`, and set `largest` to the current number.
3. Otherwise, if the current number is greater than `sec_largest`, update only `sec_largest`.
4. Finally, return $(largest - 1) \times (sec_largest - 1)$.
</details>

## 💻 Solution Code

```cpp
// Intuition: The maximum product will always come from the two largest elements in the array.
// Approach: Traverse the array once to find the maximum (largest) and second maximum (sec_largest) elements, then calculate the required product.
// Time Complexity: O(N), where N is the number of elements in the array. We are doing a single pass.
// Space Complexity: O(1), as we only use a couple of variables regardless of the input size.
class Solution {
public:
    int maxProduct(vector<int>& nums) {
        // Initialize variables to track the top two maximum values
        int largest = 0;
        int sec_largest = 0;

        // Iterate through each number in the array
        for(int &num : nums) {
            // If we find a new maximum, push the old maximum to second place
            if(num > largest) {
                sec_largest = largest;
                largest = num;
            } else {
                // Otherwise, check if it qualifies for the second maximum spot
                sec_largest = max(sec_largest, num);
            }
        }

        // Return the product as required by the problem statement
        return (largest-1) * (sec_largest-1);
    }
};

/*
*
* Dry Run
* Input: nums = [3, 4, 5, 2]
* Initialization: largest = 0, sec_largest = 0
* 
* Iteration 1: num = 3
* - num > largest (3 > 0) -> True
* - sec_largest = 0
* - largest = 3
* 
* Iteration 2: num = 4
* - num > largest (4 > 3) -> True
* - sec_largest = 3
* - largest = 4
* 
* Iteration 3: num = 5
* - num > largest (5 > 4) -> True
* - sec_largest = 4
* - largest = 5
* 
* Iteration 4: num = 2
* - num > largest (2 > 5) -> False
* - sec_largest = max(4, 2) = 4
* 
* Final Calculation:
* (largest - 1) * (sec_largest - 1) 
* = (5 - 1) * (4 - 1) 
* = 4 * 3 
* = 12
* Output: 12
*
*/
```

## 📌 Notes
* Sorting the array is another viable approach ($O(N \log N)$), but it is unnecessarily slow compared to the single-pass $O(N)$ linear scan.
* Priority Queues (Max Heap) could also be used to extract the top two elements, yielding $O(N + K \log N)$ where $K=2$. This is overkill for this specific problem but a good pattern to remember for finding the "$K$ largest elements".

## 🎯 Key Insights
* Identifying that the mathematical product of $(a-1) \times (b-1)$ for positive integers is maximized when $a$ and $b$ are as large as possible allows us to bypass calculating all pairs. 
* Single-pass algorithms for tracking multiple minimums or maximums are common optimization techniques in array problems.
