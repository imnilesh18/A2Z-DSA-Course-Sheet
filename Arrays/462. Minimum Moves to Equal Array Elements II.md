## 📝 Problem Statement

Given an integer array `nums` of size `n`, return the minimum number of moves required to make all array elements equal.

In one move, you can **increment or decrement** an element of the array by 1.

> *Test cases are designed so that the answer will fit in a 32-bit integer.*

### 🚦 Constraints

- `n == nums.length`
- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

### 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [1,2,3]` | `2` | Only two moves are needed to make all elements 2: <br/> `[1,2,3] => [2,2,3] => [2,2,2]` |
| **2** | `nums = [1,10,2,9]` | `16` | Making all elements 9 takes 16 total moves. |

## 🧠 Explanation & Approach

To find the minimum number of moves to make all elements equal, the fundamental question is: **Which element should we make everyone equal to?** 

1. **Why not an arbitrary number?** If we pick a target number that isn't already present in the array, we are forcing elements to travel extra distance. Picking an existing element guarantees at least one element requires $0$ moves.
2. **Why not the smallest or largest?** If we make all elements equal to the minimum value, the maximum value has to cover a massive distance. The same applies if we pick the maximum value.
3. **The Sweet Spot (Median):** To minimize the total distance traveled by all elements, we must pick the middle path—the **median** of the array. The median naturally balances the number of elements that need to be incremented and decremented. 

### 🛠️ Step-by-Step Evolution

<details>
<summary><b>1️⃣ Approach 1: Sorting to find the Median (Brute-Force / Base Idea)</b></summary>
First, we sort the array. This allows us to instantly find the median element at index `n/2`. Then, we iterate through every single element in the array, compute its absolute difference from the median, and add it to our total `moves` tally.
</details>

<details>
<summary><b>2️⃣ Approach 2: Optimized Loop Traversal</b></summary>
Once the array is sorted, we know the elements are symmetrically distributed around the median. Instead of looping through all $N$ elements, we can loop up to $N/2$. In each iteration, we calculate the difference for the element on the left (`nums[i]`) and the corresponding element on the right (`nums[n-i-1]`). This cuts loop iterations in half.
</details>

<details>
<summary><b>3️⃣ Approach 3: Linear Average Time using `nth_element` (Highly Optimized)</b></summary>
Do we really need to sort the *entire* array? No! We only care about finding the median value. In C++, we can use the `nth_element` STL function. It rearranges the array so that the element at the $N/2$ index is exactly what it would be if the array was fully sorted, placing smaller elements to its left and larger to its right. This achieves our goal in **Average $O(N)$ time** instead of $O(N \log N)$.
</details>

## 💻 Solution Code

### 🐌 Approach 1: Greedily Pick Mid Element (Sorting)

```cpp
// Intuition: The optimal target to make all elements equal with the minimum number of moves is the median of the array. Sorting helps us easily locate this median element.
// Approach: Sort the array, find the median at index `n/2`, and then iterate through all elements to calculate the sum of absolute differences between each element and the median.
// Time Complexity: O(n log n) due to the sorting step. The subsequent loop runs in O(n) time.
// Space Complexity: O(1) as we only use a few extra variables for calculations.
class Solution {
public:
    int minMoves2(vector<int>& nums) {
        int n = nums.size(); // Get the size of the array

        sort(begin(nums), end(nums)); // Sort to find the median

        int mid = nums[n/2]; // The median element is our optimal target

        int moves = 0; // Initialize total moves to 0
        for(int i = 0; i < n; i++) {
            moves += abs(nums[i] - mid); // Add the absolute difference to moves
        }

        return moves;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 10, 2, 9]
* 1. Sort nums: [1, 2, 9, 10]
* 2. n = 4, mid = nums[4/2] = nums[2] = 9
* 3. i=0, nums[0]=1, abs(1-9)=8, moves=8
* 4. i=1, nums[1]=2, abs(2-9)=7, moves=15
* 5. i=2, nums[2]=9, abs(9-9)=0, moves=15
* 6. i=3, nums[3]=10, abs(10-9)=1, moves=16
* Output: 16
*
*/

```

### 🏃 Approach 2: Iterate till N/2 (Loop Optimization)

```cpp
// Intuition: Similar to the first approach, the median is our target. We can slightly optimize the loop by traversing only half of the array and calculating differences from both ends simultaneously.
// Approach: Sort the array and find the median. Iterate up to `n/2` and calculate the absolute difference for the element on the left side and its corresponding element on the right side.
// Time Complexity: O(n log n) for sorting the array. The loop runs in O(n/2) time.
// Space Complexity: O(1) as we are modifying in-place and using constant extra space.
class Solution {
public:
    int minMoves2(vector<int>& nums) {
        int n = nums.size(); // Get the size of the array

        sort(begin(nums), end(nums)); // Sort the array to find the median

        int mid = nums[n/2]; // Select the median element

        int moves = 0; // Initialize total moves
        for(int i = 0; i < n/2; i++) {
            moves += abs(nums[i] - mid); // Difference for the left-side element
            moves += abs(nums[n-i-1] - mid); // Difference for the right-side element
        }

        return moves;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3]
* 1. Sort nums: [1, 2, 3]
* 2. n = 3, mid = nums[3/2] = nums[1] = 2
* 3. Loop up to n/2 (3/2 = 1), so loop runs for i=0 only
* 4. i=0:
*    - left diff = abs(nums[0] - 2) = abs(1 - 2) = 1, moves = 1
*    - right diff = abs(nums[2] - 2) = abs(3 - 2) = 1, moves = 2
* Output: 2
*
*/

```

### 🚀 Optimized Solution: Use `nth_element` (Linear Average Time)

```cpp
// Intuition: We don't actually need to fully sort the array; we only need the element that would be at the median index if it were sorted. C++ provides `nth_element` which does exactly this in linear average time.
// Approach: Use `nth_element` to place the median element at index `n/2`. All elements to its left will be smaller or equal, and right will be greater or equal. Then calculate differences using the optimized loop.
// Time Complexity: Average O(n) because `nth_element` uses an algorithm similar to QuickSelect. Worst case is O(n^2), but highly unlikely.
// Space Complexity: O(1) as the reordering happens in-place without auxiliary data structures.
class Solution {
public:
    int minMoves2(vector<int>& nums) {
        int n = nums.size(); // Size of the array

        nth_element(begin(nums), begin(nums)+n/2, end(nums)); // O(n) average to find median

        int mid = nums[n/2]; // Retrieve the median

        int moves = 0; // Track the total operations needed
        for(int i = 0; i < n/2; i++) {
            moves += abs(nums[i] - mid); // Difference for left part
            moves += abs(nums[n-i-1] - mid); // Difference for right part
        }

        return moves;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 10, 2, 9]
* 1. n = 4, median index = 4/2 = 2
* 2. nth_element rearranges nums so nums[2] is the 3rd smallest. Array might become [1, 2, 9, 10], ensuring nums[2] is 9.
* 3. mid = nums[2] = 9
* 4. Loop runs for i=0, 1 (since n/2 = 2)
* 5. i=0:
*    - left diff = abs(nums[0] - 9) = abs(1 - 9) = 8, moves = 8
*    - right diff = abs(nums[3] - 9) = abs(10 - 9) = 1, moves = 9
* 6. i=1:
*    - left diff = abs(nums[1] - 9) = abs(2 - 9) = 7, moves = 16
*    - right diff = abs(nums[2] - 9) = abs(9 - 9) = 0, moves = 16
* Output: 16
*
*/

```

## 🔍 Key Insights

* **Mathematical Proof of Median:** The problem asks to minimize $\sum |nums[i] - X|$. Mathematically, the function $f(X) = \sum |nums[i] - X|$ is minimized when $X$ is the median of the array, not the mean (average). The mean minimizes the sum of squared differences, but the median minimizes the sum of absolute differences.
* **Language Specific Utilities:** C++ has the highly efficient `std::nth_element` built-in, but Java does not have an exact equivalent. Java developers would need to manually implement the **QuickSelect algorithm** to achieve the $O(N)$ average time complexity for this approach.
