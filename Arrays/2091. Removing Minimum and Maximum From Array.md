## 📝 Problem Statement

You are given a **0-indexed** array of **distinct** integers `nums`.

There is an element in `nums` that has the lowest value and an element that has the highest value. We call them the **minimum** and **maximum** respectively. Your goal is to remove both these elements from the array.

A **deletion** is defined as either removing an element from the **front** of the array or removing an element from the **back** of the array.

Return the *minimum number of deletions it would take to remove both the minimum and maximum element from the array.*

---

## ⚠️ Constraints

- `1 <= nums.length <= 10^5`
- `-10^5 <= nums[i] <= 10^5`
- The integers in `nums` are **distinct**.

## 🧠 Approach

To find the most efficient way to remove both the maximum and minimum elements, we need to locate their indices first. Once we have the positions of both elements, we can establish three possible strategies for removal:

<details>
<summary><b>Click to expand the detailed walkthrough</b></summary>

1. **Find the Targets:** Identify the indices of the minimum and maximum elements in the array. 
2. **Order the Indices:** Determine which index is closer to the left (`left`) and which is closer to the right (`right`).
3. **Evaluate the 3 Scenarios:**
   - **Scenario 1 (Both from Left):** We delete elements from the front until we reach the right-most target. Total deletions = `right + 1`.
   - **Scenario 2 (Both from Right):** We delete elements from the back until we reach the left-most target. Total deletions = `n - left`.
   - **Scenario 3 (One from each side):** We delete elements from the front to reach the left target, and from the back to reach the right target. Total deletions = `(left + 1) + (n - right)`.
4. **Result:** The optimal solution is simply the minimum value among these three scenarios.

</details>

## 💻 Solution Code

### Brute-Force Concept
The brute force approach would involve simulating every possible combination of left and right deletions recursively (a decision tree exploring `pop_front` and `pop_back`) until both targets are removed. This results in an exponential time complexity $O(2^n)$, which will result in a Time Limit Exceeded (TLE) error. 

### Optimized Solution (C++)

```cpp
// Intuition:
// Instead of simulating deletions step-by-step, we can mathematically calculate the optimal deletions.
// Since we only have two target elements, there are strictly three distinct ways to remove both of them:
// 1. Remove both by deleting only from the front.
// 2. Remove both by deleting only from the back.
// 3. Remove one from the front and the other from the back.
// By calculating the cost of all three routes, we can greedily select the minimum cost.

// Approach:
// 1. Find the indices of the minimum and maximum elements in the array.
// 2. Assign the smaller index to 'left' and the larger index to 'right'.
// 3. Calculate the deletions for the three scenarios:
//    - Both from left: 'right + 1'
//    - Both from right: 'n - left'
//    - Left from left, right from right: '(left + 1) + (n - right)'
// 4. Return the minimum value among these three calculations.

// Time Complexity: O(n) - We traverse the array to find the min and max elements.
// Space Complexity: O(1) - We only store a few integer variables, requiring constant extra space.

class Solution {
public:
    int minimumDeletions(vector<int>& nums) {
        int n = nums.size();

        // Locate indices of min and max elements
        int minEleIdx = min_element(begin(nums), end(nums)) - begin(nums);
        int maxEleIdx = max_element(begin(nums), end(nums)) - begin(nums);

        // Identify the left-most and right-most target indices
        int left = min(minEleIdx, maxEleIdx);
        int right = max(minEleIdx, maxEleIdx);

        // Evaluate all 3 strategies and return the minimum deletions
        return min({left + 1 + n - right, right + 1, n - left});
    }
};

/*
*
* Dry Run
*
* Input: nums = [2, 10, 7, 5, 4, 1, 8, 6], n = 8
* 
* min_element is 1, found at index 5. (minEleIdx = 5)
* max_element is 10, found at index 1. (maxEleIdx = 1)
* 
* left = min(5, 1) = 1
* right = max(5, 1) = 5
* 
* Scenarios:
* 1. Remove one from each side: (left + 1) + (n - right) = (1 + 1) + (8 - 5) = 2 + 3 = 5
* 2. Remove both from the left: right + 1 = 5 + 1 = 6
* 3. Remove both from the right: n - left = 8 - 1 = 7
* 
* Result: min(5, 6, 7) = 5
*
*/
```

## 🔑 Key Insights
- **Constant Options:** No matter the array size, dealing with two elements from the edges always boils down to exactly 3 deletion patterns.
- **Greedy Calculation:** By calculating the distance from boundaries (`index + 1` for the left side, `n - index` for the right side), we bypass the need for any actual array manipulation or simulation.
