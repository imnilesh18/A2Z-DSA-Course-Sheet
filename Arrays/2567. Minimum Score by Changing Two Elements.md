## 📝 Problem Statement

You are given a **0-indexed** integer array `nums`.

- The **low score** of `nums` is the **minimum** absolute difference between any two integers in the array.
- The **high score** of `nums` is the **maximum** absolute difference between any two integers in the array.
- The **score** of `nums` is defined as the **sum** of the high score and the low score:

$$\text{Score} = \text{High Score} + \text{Low Score}$$

Your task is to return the **minimum possible score** after changing **at most two elements** of `nums` to any integer values.

---

## 🔒 Constraints

- $3 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

## 💡 Approach

### 1. Breaking Down the Goal

We want to minimize:

$$\text{Total Score} = \text{High Score} + \text{Low Score}$$

Since both scores are absolute differences, neither can be negative ($\ge 0$). Therefore, to minimize their sum, we should minimize **each score independently**.

---

### 2. Step 1: Minimizing the Low Score (`Low Score = 0`)

- The **low score** is the minimum absolute difference between any two elements in `nums`.
- Because we are permitted to modify **two elements**, we can **always force the low score to become `0`**.
- **How?** Whenever we change an element, we simply set it **equal to another existing element** in the array. Having at least two identical elements guarantees:

$$\text{Low Score} = \vert{}x - x\vert{} = 0$$

With `Low Score` fixed at `0`, the problem simplifies completely to **minimizing the High Score**.

---

### 3. Step 2: Minimizing the High Score via Sorting

- The **high score** is the maximum absolute difference between any two elements in the array, which is always:

$$\text{High Score} = \max(\text{nums}) - \min(\text{nums})$$

- If we **sort `nums` in ascending order**, the smallest elements sit at the left end (`nums[0], nums[1], nums[2]`) and the largest elements sit at the right end (`nums[n-3], nums[n-2], nums[n-1]`):

$$\text{nums}[0] \le \text{nums}[1] \le \text{nums}[2] \le \dots \le \text{nums}[n-3] \le \text{nums}[n-2] \le \text{nums}[n-1]$$

- Currently, the range is `nums[n-1] - nums[0]`. To shrink this gap using **2 modifications** while simultaneously creating duplicate elements (keeping `Low Score = 0`), there are **exactly 3 optimal greedy choices**:

| Strategy | Elements Modified | New Values Assigned | New Min | New Max | Resulting High Score |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **Case 1: Shrink from Right** | Two largest (`nums[n-1]`, `nums[n-2]`) | Both set to `nums[n-3]` | `nums[0]` | `nums[n-3]` | `nums[n-3] - nums[0]` |
| **Case 2: Shrink from Left** | Two smallest (`nums[0]`, `nums[1]`) | Both set to `nums[2]` | `nums[2]` | `nums[n-1]` | `nums[n-1] - nums[2]` |
| **Case 3: Shrink Both Ends** | One smallest (`nums[0]`) & one largest (`nums[n-1]`) | `nums[0] = nums[1]`, `nums[n-1] = nums[n-2]` | `nums[1]` | `nums[n-2]` | `nums[n-2] - nums[1]` |

> **Why does every case preserve `Low Score = 0`?**
> - In **Case 1**, `nums[n-1]`, `nums[n-2]`, and `nums[n-3]` all become equal.
> - In **Case 2**, `nums[0]`, `nums[1]`, and `nums[2]` all become equal.
> - In **Case 3**, `nums[0] == nums[1]` and `nums[n-1] == nums[n-2]`. (Even when $n = 3$, all three elements become equal to `nums[1]`, giving `0`.)

### 5. Complexity Comparison

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :---: | :---: | :--- |
| **Brute Force (Pair Removal Simulation)** | $O(n^3)$ | $O(1)$ | Checks all $\binom{n}{2}$ pairs of indices to replace; TLE for $n = 10^5$. |
| **Sorting + Greedy (Optimal)** | $O(n \log n)$ | $O(1)$ / $O(\log n)$ | Sorts once and evaluates the 3 boundary cases in $O(1)$ time. |

## 💻 Solution Code

### 1. Brute Force Approach

```cpp
// Intuition: Replacing any two elements with copies of a remaining element forces the low score to 0 while leaving the high score determined purely by the minimum and maximum of the remaining n - 2 elements.
// Approach: Iterate through every possible pair of indices (i, j) to modify, compute the minimum and maximum among the remaining elements, and track the smallest resulting high score.
// Time Complexity: O(n^3) because there are O(n^2) pairs of indices and finding the min/max of remaining elements takes O(n) time per pair.
// Space Complexity: O(1) as only a few scalar variables are used.

class Solution {
public:
    int minimizeSum(vector<int>& nums) {
        int n = nums.size();
        int minScore = INT_MAX;

        // Try choosing every pair of indices (i, j) as the two modified elements
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int currMin = INT_MAX;
                int currMax = INT_MIN;

                // Find min and max among the untouched n - 2 elements
                for (int k = 0; k < n; k++) {
                    if (k == i || k == j) continue;
                    currMin = min(currMin, nums[k]);
                    currMax = max(currMax, nums[k]);
                }

                // Setting nums[i] and nums[j] equal to currMin makes low score = 0
                minScore = min(minScore, currMax - currMin);
            }
        }

        return minScore;
    }
};

/*
*
* Dry Run
*
* Input: nums = [1, 4, 7, 8, 5], n = 5
*
* Pair (i=0, j=1) excluded -> remaining = [7, 8, 5] -> currMin = 5, currMax = 8 -> score = 3
* Pair (i=0, j=2) excluded -> remaining = [4, 8, 5] -> currMin = 4, currMax = 8 -> score = 4
* Pair (i=0, j=3) excluded -> remaining = [4, 7, 5] -> currMin = 4, currMax = 7 -> score = 3
* All other pairs yield scores >= 3
*
* Final Answer: minScore = 3
*
*/
```

### 2. Optimized Approach (Sorting + Greedy)

```cpp
// Intuition: We can always make the low score 0 by setting modified elements equal to existing elements, so we only need to minimize the high score (max - min) after sorting.
// Approach: Sort the array in ascending order and return the minimum high score among the three valid ways to eliminate two extreme elements (remove two largest, remove two smallest, or remove one from each end).
// Time Complexity: O(n log n) due to sorting the array of size n.
// Space Complexity: O(1) auxiliary space (or O(log n) for the internal sorting recursion stack).

//Approach (Sort and minimize low and high)
//T.C : O(nlogn)
//S.C : O(1)
class Solution {
public:
    int minimizeSum(vector<int>& nums) {
        int n = nums.size();
        
        // Sort the array to easily access smallest and largest elements
        sort(begin(nums), end(nums));

        // Low score is guaranteed to be 0; minimize the high score across 3 cases
        return min({
            nums[n-3] - nums[0], // Change the two largest elements to nums[n-3]
            nums[n-1] - nums[2], // Change the two smallest elements to nums[2]
            nums[n-2] - nums[1]  // Change largest to nums[n-2] and smallest to nums[1]
        });
    }
};

/*
*
* Dry Run
*
* Input: nums = [1, 4, 7, 8, 5]
* n = 5
*
* Step 1: Sort nums -> [1, 4, 5, 7, 8]
* Indices: nums[0]=1, nums[1]=4, nums[2]=5, nums[3]=7, nums[4]=8
*
* Step 2: Evaluate the 3 cases
* Case 1 (nums[2] - nums[0]): 5 - 1 = 4
* Case 2 (nums[4] - nums[2]): 8 - 5 = 3
* Case 3 (nums[3] - nums[1]): 7 - 4 = 3
*
* Step 3: Return min({4, 3, 3}) = 3
*
*/
```

## 📌 Notes

- **Why don't we need to modify the array in place after sorting?** Because we only need the final score, not the modified array itself. Once we know that setting the changed elements equal to neighboring values makes `low_score = 0`, the resulting `high_score` depends solely on the new boundary elements in the sorted order.
- **Can we achieve $O(n)$ time complexity?** Yes! Since we only care about the 3 smallest elements (`nums[0]`, `nums[1]`, `nums[2]`) and the 3 largest elements (`nums[n-3]`, `nums[n-2]`, `nums[n-1]`), we could find those 6 boundary values in a single linear pass ($O(n)$) without fully sorting the array. However, `std::sort` is concise, clean, and easily passes within $O(n \log n)$ for $n \le 10^5$.

---

## 🔑 Key Insights

1. **Decoupling the Objective Function:** Whenever a problem asks to minimize `A + B` where both `A >= 0` and `B >= 0`, check whether one term can be independently driven to `0`. Here, a single duplicate pair forces `Low Score = 0`.
2. **Duplicate Assignment Trick:** Changing an element to a brand-new arbitrary number can never outperform setting it equal to an adjacent element in the sorted array, because matching an existing element achieves the same range reduction *while also* guaranteeing a zero minimum difference.
3. **Boundary Window Thinking:** Changing $k$ elements to minimize `max - min` in a sorted array is equivalent to dropping $k$ elements from the left and right ends combined—meaning we retain a contiguous subarray of length $n - k$. For $k = 2$, there are $k + 1 = 3$ windows of length $n - 2$.
