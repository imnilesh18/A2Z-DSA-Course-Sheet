# 3016. Minimum Number of Pushes to Type Word II

**Problem Name:** Minimum Number of Pushes to Type Word II  
**Difficulty:** Medium  
**Tags:** Hash Table, String, Greedy, Sorting, Counting  

---

## 📝 Problem Statement

You are given a string `word` containing lowercase English letters. 

Telephone keypads have keys mapped with distinct collections of lowercase English letters, which can be used to form words by pushing them. For example, the key `2` is mapped with `["a","b","c"]`. We need to push the key one time to type `"a"`, two times to type `"b"`, and three times to type `"c"`.

It is allowed to remap the keys numbered `2` to `9` to distinct collections of letters. The keys can be remapped to any amount of letters, but each letter must be mapped to exactly one key. You need to find the minimum number of times the keys will be pushed to type the string `word`.

Return the *minimum number of pushes needed to type `word` after remapping the keys*.

*Note that 1, \*, #, and 0 do not map to any letters.*

---

## ⚙️ Constraints

| Constraint | Details |
| :--- | :--- |
| **String Length** | `1 <= word.length <= 10^5` |
| **Character Set** | `word` consists of lowercase English letters. |

## 💡 Examples

### Example 1
**Input:** `word = "abcde"`  
**Output:** `5`  
**Explanation:** 
The remapped keypad provides the minimum cost.
- "a" -> one push on key 2
- "b" -> one push on key 3
- "c" -> one push on key 4
- "d" -> one push on key 5
- "e" -> one push on key 6
Total cost is 1 + 1 + 1 + 1 + 1 = 5. It can be shown that no other mapping can provide a lower cost.

### Example 2
**Input:** `word = "xyzxyzxyzxyz"`  
**Output:** `12`  
**Explanation:** 
The remapped keypad provides the minimum cost.
- "x" -> one push on key 2
- "y" -> one push on key 3
- "z" -> one push on key 4
Total cost is 1 * 4 + 1 * 4 + 1 * 4 = 12. Note that the key 9 is not mapped to any letter: it is not necessary to map letters to every key, but to map all the letters.

### Example 3
**Input:** `word = "aabbccddeeffgghhiiiiii"`  
**Output:** `24`  
**Explanation:** 
The remapped keypad provides the minimum cost.
- "a" to "g" -> one push each on keys 2 to 8
- "h" -> two pushes on key 9
- "i" -> one push on key 9
Total cost is `1 * 2 + 1 * 2 + 1 * 2 + 1 * 2 + 1 * 2 + 1 * 2 + 1 * 2 + 2 * 2 + 6 * 1 = 24`.

## 🧠 Approach & Explanation

### Key Insights
To minimize the overall number of key pushes, we need to take a **greedy approach**. Characters that appear most frequently in the string should require the fewest number of key presses. Since we only have 8 keys available for mapping (keys `2` through `9`), we can place a maximum of 8 distinct characters in the optimal "1-push" position. The next 8 characters will inevitably need to go into the "2-push" position, and so forth.

### Step-by-Step Logic
1. **Frequency Calculation:** First, we calculate how many times each character appears in the given string `word`.
2. **Greedy Sorting:** We sort these character frequencies in descending order. This ensures that the characters demanding the most key presses are prioritized for the cheapest slots (1 push).
3. **Slot Assignment (Math formulation):** 
   * The highest 8 frequencies will cost 1 push each. 
   * The next 8 highest frequencies (indices 8 to 15 in a sorted 0-indexed array) will cost 2 pushes each.
   * This mathematically translates to: for a character at sorted index `i`, the number of pushes required is `(i / 8) + 1`.
4. **Total Cost:** Multiply the frequency of the character by its respective push cost and sum these values up.

## 💻 Solution Code

### Brute-force / Simulation Approach (C++)
```cpp
// Intuition: To minimize the total key pushes, characters that appear most frequently in the string should be mapped to a single push on the keypad keys (2 through 9). Less frequent characters can take 2 or more pushes.
// Approach: Calculate the frequency of each character, sort them in descending order based on frequency. Iterate through the characters and assign them sequentially to keys 2-9, keeping track of how many characters are already assigned to each key to calculate the required pushes.
// Time Complexity: O(n + k log k) where n is the length of the string and k is the number of unique characters (max 26). Sorting takes O(26 log 26) which is O(1). Overall O(n).
// Space Complexity: O(k) for storing frequencies and keypad mappings, where k is at most 26. Overall O(1) auxiliary space.
class Solution {
public:
    // I am sorting to give priority to the char which has highest frequency
    // Because I would want it to come first in any button(key)
    void sortFunc(string &word) {
        unordered_map<char, int> mp;
        
        // Calculate frequency of each character
        for(const char &ch : word) {
            mp[ch]++;
        }
        
        // Custom lambda to sort in descending order based on frequencies
        auto lambda=[&](const char &ch1, const char &ch2){
            return mp[ch1] > mp[ch2];
        };
        
        sort(begin(word), end(word), lambda);
    }
    
    int minimumPushes(string word) {
        // If length is 8 or less, each distinct character can occupy a 1-push slot
        if(word.length() <= 8) {
            return word.length();
        }
        
        // Rearrange word prioritizing frequent characters
        sortFunc(word);
        
        unordered_map<int, unordered_set<char>> myMap;
        unordered_map<char, pair<int, int>> mp; // char is stored in which key in myMap and at what position it came
        
        int result = 0 ;
        int assign = 2; // Keypad buttons start from 2
        
        for(char &ch : word) {
            // Reset to key 2 after reaching key 9
            if(assign > 9) {
                assign = 2;
            }
            
            // If character is mapped for the very first time
            if(mp.find(ch) == mp.end()) {
                myMap[assign].insert(ch);
                mp[ch] = {assign, (int)myMap[assign].size()};
                
                result += mp[ch].second;
                assign++; // Move assignment to the next button
            } else {
                // If already mapped, just add its pre-calculated push cost
                result += mp[ch].second;
            }
        }
        
        return result;
        
    }
};

/*
*
* Dry Run
* Word: "xyzxyzxyzxyz"
* Frequencies: x=4, y=4, z=4
* Sorted Word: x, x, x, x, y, y, y, y, z, z, z, z
*
* Processing 'x': Not mapped. Assign to key 2. Position = 1. Add 1 to result. Next key = 3.
* Processing next 'x's: Already mapped. Add 1 to result for each.
* Total for 'x' = 4 pushes.
* 
* Processing 'y': Not mapped. Assign to key 3. Position = 1. Add 1 to result for each 'y'.
* Total for 'y' = 4 pushes. Next key = 4.
* 
* Processing 'z': Not mapped. Assign to key 4. Position = 1. Add 1 to result for each 'z'.
* Total for 'z' = 4 pushes. Next key = 5.
* 
* Final Result: 4 + 4 + 4 = 12
*
*/
```

### Optimized Mathematical Approach (C++)
```cpp
// Intuition: Since there are 8 usable keys (2-9), the first 8 most frequent characters can be typed with 1 push. The next 8 frequent characters will require 2 pushes, and so on.
// Approach: Count frequencies of all characters using a fixed-size array. Sort the frequencies in descending order. Multiply each frequency by its corresponding push cost calculated mathematically as (index / 8) + 1.
// Time Complexity: O(n + 26 log 26) where n is the length of the string. The sorting takes constant time since the array size is always 26. Overall O(n).
// Space Complexity: O(1) because we only use a fixed-size array of 26 integers, regardless of the input size.
class Solution {
public:
    int minimumPushes(string word) {
        
        // Generic solution using fixed array for 26 alphabets
        vector<int> mp(26, 0);
        
        // Calculate frequency map
        for(char &ch: word)
            mp[ch - 'a']++; // Mentioned in qn, all letters will be distinct or lowercase
    
        // Sort in descending order of frequency
        sort(begin(mp), end(mp), greater<int>()); 
        
        int ans = 0;
        
        // Calculate total pushes based on sorted index positions
        for(int i = 0; i < 26; i++){
            // For first 8 (i: 0-7), pushes = 1. Next 8 (i: 8-15), pushes = 2, etc.
            ans += mp[i]*((i/8) + 1);
        }
        
        return ans;
    }
};

/*
*
* Dry Run
* Word: "abcde"
* Frequency array (first 5): a=1, b=1, c=1, d=1, e=1 (rest 0)
* Sorted array: 1, 1, 1, 1, 1, 0, 0...
* 
* i = 0: ans += 1 * (0/8 + 1) => ans += 1 * 1 => 1
* i = 1: ans += 1 * (1/8 + 1) => ans += 1 * 1 => 2
* i = 2: ans += 1 * (2/8 + 1) => ans += 1 * 1 => 3
* i = 3: ans += 1 * (3/8 + 1) => ans += 1 * 1 => 4
* i = 4: ans += 1 * (4/8 + 1) => ans += 1 * 1 => 5
* i = 5 to 25: mp[i] is 0, so ans += 0
* 
* Final ans = 5
*
*/
```

## 📌 Notes & Further Exploration
* **Why `(i / 8) + 1` works:** The integer division correctly groups blocks of 8 numbers. Indices 0 to 7 divided by 8 yield 0. Adding 1 provides the exact number of keypresses needed for that specific block. 
* **Extension:** This logic easily solves part one of the problem (LeetCode 3014) since the character distribution logic remains completely the same whether characters repeat or are strictly distinct.
