# 3727. Maximum Alternating Sum of Squares

**Problem Link:** [Maximum Alternating Sum of Squares](https://leetcode.com/problems/maximum-alternating-sum-of-squares/description/)
**Difficulty:** Medium
**Tags:** Array, Greedy, Sorting

---

## 📝 Problem Statement

You are given an integer array `nums`[cite: 1]. You may rearrange the elements in any order[cite: 1].

The alternating score of an array `arr` is defined as:
`score = arr[0]² - arr[1]² + arr[2]² - arr[3]² + ...`[cite: 1]

Return an integer denoting the maximum possible alternating score of `nums` after rearranging its elements[cite: 1].

---

## 💡 Constraints

* `1 <= nums.length <= 10^5`[cite: 1]
* `-4 * 10^4 <= nums[i] <= 4 * 10^4`[cite: 1]

The alternating score is calculated as: `score = (-3)² - (-1)² + (-2)² - (1)² + (3)² - (2)² = 9 - 1 + 4 - 1 + 9 - 4 = 16`[cite: 1]. |

## 🧠 Approach & Explanation

To achieve the maximum alternating score, we must analyze the problem's mathematical formula[cite: 1]. The score formula `a² - b² + c² - d² ...` essentially breaks down into the sum of some squared elements minus the sum of other squared elements[cite: 1]. 

To maximize this difference, we should:
1. **Square all elements:** First, calculate the squares of all elements in the given array[cite: 1].
2. **Maximize the positive sums:** We want the values being added to be as large as possible[cite: 1].
3. **Minimize the negative sums:** We want the values being subtracted to be as small as possible[cite: 1].

We can achieve this by dividing the array into two halves based on the values of the squares[cite: 1]. The smaller squared values (left half) should be subtracted, and the larger squared values (right half) should be added[cite: 1]. 

### Two Distinct Strategies:
1. **Full Sorting (O(n log n)):** Sort the squared array so all large numbers are on the right side and all small numbers are on the left[cite: 1]. We then take the sum of the larger half (from index `n/2` to the end) and subtract the sum of the smaller half (from index `0` to `n/2`)[cite: 1].
2. **Partial Sorting (Average O(n)):** Fully sorting the array is unnecessary[cite: 1]. We only need to guarantee that the `n/2` smallest elements are on the left side and the rest are on the right side[cite: 1]. We can use C++'s `std::nth_element` to partition the array around the middle index in linear time[cite: 1]. Once partitioned, we compute the sums of both halves and find the difference[cite: 1].

## 💻 Solution Code

### Approach 1: Brute Force / Full Sort

```cpp
// Intuition: To maximize the alternating sum of squares, we should add the largest squared values and subtract the smallest squared values.
// Approach: Square all elements, sort the array, sum the larger half, sum the smaller half, and return their difference.
// Time Complexity: O(n log n) due to the sorting step.
// Space Complexity: O(1) as we modify the array in-place.
class Solution {
public:
    long long maxAlternatingSum(vector<int>& nums) {
        int n = nums.size();

        // Square all elements in the array
        for(int i = 0; i < n; i++ ){
            nums[i] = nums[i]*nums[i];
        }

        // Sort the squared array
        sort(begin(nums), end(nums));

        // Sum the larger half (right side) and smaller half (left side)
        long long largeHalf = accumulate(begin(nums)+n/2, end(nums), 0LL);
        long long smallHalf = accumulate(begin(nums), begin(nums)+n/2, 0LL);

        // Return the maximized difference
        return largeHalf - smallHalf;
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3]
* Step 1 (Square): nums becomes [1, 4, 9]
* Step 2 (Sort): nums remains [1, 4, 9]
* Step 3 (Variables): n = 3, n/2 = 1
* Step 4 (Large Half): Sum from index 1 to 2 -> 4 + 9 = 13
* Step 5 (Small Half): Sum from index 0 to 0 -> 1
* Step 6 (Result): largeHalf (13) - smallHalf (1) = 12
* Output: 12
*
*/
```

### Approach 2: Optimized / Partial Sort

```cpp
// Intuition: We don't need a perfectly sorted array, just a clean partition where the smallest n/2 elements are on the left and the largest on the right.
// Approach: Square all elements, use nth_element to partition the array exactly at the n/2 index, sum both sides, and return the difference.
// Time Complexity: Average O(n) because nth_element operates in linear time on average.
// Space Complexity: O(1) as we modify the array in-place.
class Solution {
public:
    long long maxAlternatingSum(vector<int>& nums) {
        int n = nums.size();

        // Square all elements in the array
        for(int i = 0; i < n; i++ ){
            nums[i] = nums[i]*nums[i];
        }

        // Partially sort to place the middle element in its correct sorted position
        nth_element(begin(nums), begin(nums)+n/2, end(nums));

        // Sum the larger partitioned half and the smaller partitioned half
        long long largeHalf = accumulate(begin(nums)+n/2, end(nums), 0LL);
        long long smallHalf = accumulate(begin(nums), begin(nums)+n/2, 0LL);

        // Return the maximized difference
        return largeHalf - smallHalf;
    }
};

/*
*
* Dry Run
* Input: nums = [1, -1, 2, -2, 3, -3]
* Step 1 (Square): nums becomes [1, 1, 4, 4, 9, 9]
* Step 2 (Variables): n = 6, n/2 = 3
* Step 3 (Partition): nth_element at index 3 groups smaller elements to the left. 
*          Partitioned nums could look like [1, 1, 4, 4, 9, 9] (order may vary within halves)
* Step 4 (Large Half): Sum from index 3 to 5 -> 4 + 9 + 9 = 22
* Step 5 (Small Half): Sum from index 0 to 2 -> 1 + 1 + 4 = 6
* Step 6 (Result): largeHalf (22) - smallHalf (6) = 16
* Output: 16
*
*/
```

## 🔑 Key Insights
- **Greedy Placement:** By grouping the absolute largest elements to be strictly additive and the absolute smallest elements to be subtractive, we guarantee the mathematical maximum[cite: 1].
- **Exclusive Halves:** The `std::accumulate` logic cleverly uses `begin(nums) + n/2`[cite: 1]. When `n` is odd, this perfectly allocates the "extra" element to the larger half, maximizing the total.
- **nth_element Efficiency:** `std::nth_element` uses the QuickSelect algorithm under the hood, heavily optimizing our time complexity from $O(n \log n)$ to average $O(n)$ without requiring extra space[cite: 1].

## 📝 Notes & Further Exploration
- If asked not to modify the input array, you will need to allocate an auxiliary array of size $O(n)$ to store the squared values before partitioning[cite: 1].
- Java does not have a direct equivalent to C++'s `std::nth_element` out of the box, so you would either have to use standard sorting or manually implement a `QuickSelect` function[cite: 1]. Java Streams can also be used to handle the summation cleanly[cite: 1].
- Since the problem's constraints limit `nums[i]` values from `-4 * 10^4` to `4 * 10^4`, counting sort is also a viable and highly efficient alternative to standard sorting techniques[cite: 1].
