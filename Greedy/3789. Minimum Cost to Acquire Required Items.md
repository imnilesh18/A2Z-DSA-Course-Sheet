# 3789. Minimum Cost to Acquire Required Items

**Problem Link:** [Minimum Cost to Acquire Required Items](https://leetcode.com/problems/minimum-cost-to-acquire-required-items/description/)
**Difficulty:** Medium
**Tags:** Math, Greedy

---

## 📝 Problem Statement

You are given five integers `cost1`, `cost2`, `costBoth`, `need1`, and `need2`.

There are three types of items available:
*   An item of type 1 costs `cost1` and contributes 1 unit to the type 1 requirement only.
*   An item of type 2 costs `cost2` and contributes 1 unit to the type 2 requirement only.
*   An item of type 3 costs `costBoth` and contributes 1 unit to **both** type 1 and type 2 requirements.

You must collect enough items so that the total contribution toward type 1 is at least `need1` and the total contribution toward type 2 is at least `need2`.

Return an integer representing the **minimum possible total cost** to achieve these requirements.

---

## ⚙️ Constraints

*   `1 <= cost1, cost2, costBoth <= 10^6`
*   `0 <= need1, need2 <= 10^9`

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `cost1 = 3, cost2 = 2, costBoth = 1, need1 = 3, need2 = 2` | `3` | After buying three type 3 items (cost 3 * 1 = 3), total contribution to type 1 is 3 (>= 3) and to type 2 is 3 (>= 2). Minimum cost is 3. |
| **2** | `cost1 = 5, cost2 = 4, costBoth = 15, need1 = 2, need2 = 3` | `22` | We buy 2 items of type 1 and 3 items of type 2: 2 * 5 + 3 * 4 = 10 + 12 = 22. Any other combination costs more. |
| **3** | `cost1 = 5, cost2 = 4, costBoth = 15, need1 = 0, need2 = 0` | `0` | Since no items are required, we buy nothing and pay 0. |

---

## 🧠 Approach & Key Insights

This problem can be efficiently solved using a **Greedy Approach**. The core idea is to always pick the most cost-effective method to fulfill our needs by comparing the cost of buying items individually versus buying them as a bundle.

### Logical Breakdown:

**Case 1: Buying separately is cheaper or equal (`cost1 + cost2 <= costBoth`)**
If buying one Type 1 item and one Type 2 item separately costs less than or equal to buying a bundle that provides both, there is absolutely no benefit to buying the bundle. We simply fulfill our requirements by purchasing exactly `need1` Type 1 items and `need2` Type 2 items. 
*   *Cost Calculation:* `(cost1 * need1) + (cost2 * need2)`

**Case 2: The bundle is cheaper (`costBoth < cost1 + cost2`)**
If the bundled item is cheaper than buying them separately, we should maximize our use of it. 
1.  **Maximize Bundles:** We buy bundles until one of the needs (either `need1` or `need2`) drops to zero. The maximum number of useful bundles we can buy to simultaneously satisfy both needs is the minimum of the two requirements: `min(need1, need2)`.
2.  **Fulfill Remaining Need:** After buying the bundles, one requirement will be completely satisfied, but the other might still have some remaining required amount.
    *   If `need1` is remaining, we check the absolute cheapest way to get another Type 1 item. We can either buy a Type 1 item explicitly (`cost1`), or just buy another bundle (`costBoth`) if it happens to be even cheaper than `cost1` alone. So, we multiply the remaining `need1` by `min(cost1, costBoth)`.
    *   If `need2` is remaining, we apply the exact same logic: multiply the remaining `need2` by `min(cost2, costBoth)`.

*Note: Since the variables like cost can be up to $10^6$ and needs up to $10^9$, multiplying them can exceed standard 32-bit integer limits. We must use `long long` (or multiply by `1LL`) to prevent integer overflow.*

## 💻 Solution Code (C++)

```cpp
// Intuition: Always pick the most cost-effective way to acquire items, prioritizing bundles if they are cheaper than buying individually.
// Approach: Check if cost1 + cost2 <= costBoth. If true, buy items separately. If false, buy maximum possible bundles to cover both needs simultaneously, then fulfill any remaining individual need with the cheapest available option.
// Time Complexity: O(1) - The solution relies on a few constant-time mathematical comparisons and arithmetic operations.
// Space Complexity: O(1) - No extra space is utilized; we only use primitive variables.
class Solution {
public:
    typedef long long ll;

    ll minimumCost(int cost1, int cost2, int costBoth, int need1, int need2) {
        // Case A: Buying individual items is cheaper than or equal to the bundle
        if (cost1 + cost2 <= costBoth) {
            return 1LL * cost1 * need1 + 1LL * cost2 * need2; // Multiply by 1LL to prevent integer overflow
        }

        // Case B: Bundle is more cost-effective
        // Buy as many bundles as possible to satisfy both needs simultaneously
        int both = min(need1, need2);
        ll total = 1LL * both * costBoth;

        // Deduct the acquired amounts from our total needs
        need1 -= both;
        need2 -= both;

        // Fulfill any pending requirements with the absolute cheapest option
        if(need1 > 0)
            total += 1LL * need1 * min(cost1, costBoth); // Might be cheaper to just buy another bundle
        else if(need2 > 0)
            total += 1LL * need2 * min(cost2, costBoth);

        return total;
    }
};

/*
*
* Dry Run
*
* Input: cost1 = 3, cost2 = 2, costBoth = 1, need1 = 3, need2 = 2
* 
* 1. Check Condition: (cost1 + cost2) <= costBoth -> (3 + 2) <= 1 -> 5 <= 1 (False). Move to Case B.
* 2. Calculate Bundles: both = min(need1, need2) -> min(3, 2) = 2.
* 3. Initial Total Cost: total = 2 * 1 = 2.
* 4. Update Needs: need1 = 3 - 2 = 1. need2 = 2 - 2 = 0.
* 5. Check Pending Needs: need1 (1) is > 0.
* 6. Fulfill Pending: total += 1 * min(cost1, costBoth) -> total += 1 * min(3, 1) -> total += 1 * 1 = 1.
* 7. Final Total: 2 + 1 = 3. Return 3.
*
*/
```
