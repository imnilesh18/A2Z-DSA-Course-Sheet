# 2333. Minimum Sum of Squared Difference

**Problem Link:** [LeetCode 2333](https://leetcode.com/problems/minimum-sum-of-squared-difference) 
**Difficulty:** Medium 
**Tags:** Array, Binary Search, Greedy, Sorting, Heap (Priority Queue)

## 📝 Problem Statement

You are given two positive 0-indexed integer arrays `nums1` and `nums2`, both of length `n` .

The **sum of squared difference** of arrays `nums1` and `nums2` is defined as the sum of `(nums1[i] - nums2[i])^2` for each `0 <= i < n` .

You are also given two positive integers `k1` and `k2` . You can modify any of the elements of `nums1` by `+1` or `-1` at most `k1` times . Similarly, you can modify any of the elements of `nums2` by `+1` or `-1` at most `k2` times .

Return the minimum sum of squared difference after modifying array `nums1` at most `k1` times and modifying array `nums2` at most `k2` times .

*Note: You are allowed to modify the array elements to become negative integers.*

## 🔐 Constraints

* `n == nums1.length == nums2.length` 
* `1 <= n <= 10^5` 
* `0 <= nums1[i], nums2[i] <= 10^5` 
* `0 <= k1, k2 <= 10^9`

### The Core Observation
The problem asks us to minimize the sum of squared differences . 
Whether we increment/decrement an element in `nums1` using `k1` or `nums2` using `k2`, the net effect is identical: we are simply trying to reduce the absolute difference `|nums1[i] - nums2[i]|` by 1 . Thus, we do not need to track `k1` and `k2` separately; instead, we have a total pool of operations `K = k1 + k2` .

### Brute Force (Max-Heap)
To minimize the sum of squares, mathematical logic dictates that we must greedily target and reduce the largest differences first .
1. Calculate the absolute differences for all elements and push them into a Max-Heap (Priority Queue) .
2. While we have available operations (`K > 0`) and the maximum difference is greater than `0`, pop the largest difference, decrement it by `1`, and push it back .
3. Sum the squares of the final elements in the heap .
*Why it fails:* `K` can be up to $10^9$ . Decrementing one by one results in a time complexity of $O((N + K) \log N)$, causing a Time Limit Exceeded (TLE) error .

### Optimized Approach (Counting Sort / Frequency Array)
Instead of reducing differences one at a time, we can group identical differences and reduce them in bulk .
1. The maximum possible difference is bounded by $10^5$ (since array elements are up to $10^5$) .
2. Create a frequency array `countDiff` where the index represents the difference value and the value represents its frequency .
3. Iterate from `maxDiff` down to `1`. If we encounter a difference `currDiff` that has a frequency `count`, we can apply operations to as many of these elements as possible .
4. The number of elements we can reduce is `min(count, K)`. We subtract this amount from `countDiff[currDiff]`, add it to `countDiff[currDiff - 1]`, and decrement `K` .
5. This bulk reduction ensures we process each difference value efficiently in $O(N + maxDiff)$ time .

## 💻 Solution Code

### 1. Brute-force Solution (TLE)

```cpp
// Intuition: To minimize the sum of squares, we must greedily reduce the largest absolute differences. We can combine k1 and k2 into a total operation pool K.
// Approach: Calculate all absolute differences and push them into a Max-Heap. Extract the largest difference, decrease it by 1, and push it back. Repeat this K times.
// Time Complexity: O((n + k1 + k2) * log n), where n is array length and k is operations. This causes TLE because K can be up to 10^9.
// Space Complexity: O(n) to store the differences in the priority queue.
//Approach-1 (Brute Force - TLE)
//T.C : O((n + k1 + k2) * log n), k is huge
//S.C : O(n)
class Solution {
public:
    long long minSumSquareDiff(vector<int>& nums1, vector<int>& nums2, int k1, int k2) {
        int n = nums1.size(); // Get length of arrays

        priority_queue<int> pq; // Max-heap to keep track of largest differences
        for (int i = 0; i < n; ++i) {
            pq.push(abs(nums1[i] - nums2[i])); // Store absolute difference
        }

        int K = k1 + k2; // Combine total allowed operations

        // Greedily reduce the largest difference by 1, up to K times
        while (K > 0 && pq.top() > 0) {
            int largestDiff = pq.top();
            pq.pop();
            pq.push(largestDiff - 1); // Push reduced difference back
            K--; // Consume one operation
        }

        long long result = 0;
        // Calculate the sum of squares of the remaining differences
        while (!pq.empty()) {
            long long d = pq.top();
            pq.pop();
            result += d * d; 
        }

        return result;
    }
};

/*
*
* Dry Run
* Input: nums1 = [1,2], nums2 = [5,6], k1 = 1, k2 = 1. Diff: [4, 4], K = 2.
* Heap: [4, 4]. K = 2.
* Pop 4, push 3. Heap: [4, 3]. K = 1.
* Pop 4, push 3. Heap: [3, 3]. K = 0.
* Loop ends. Result: 3^2 + 3^2 = 9 + 9 = 18.
*
*/
```

### 2. Optimized Solution (Counting Sort)

```cpp
// Intuition: Instead of decrementing the largest differences one by one (which is too slow for large K), we can group them by frequency and apply operations in bulk.
// Approach: Find the max difference and use a frequency array to count occurrences of each difference. Iterate downwards from max difference, reducing occurrences of `currDiff` to `currDiff - 1` in bulk based on available K.
// Time Complexity: O(n + maxDiff), where maxDiff <= 10^5. This easily passes all test cases.
// Space Complexity: O(maxDiff) to store the frequency array representing counts of each difference.
//Approach-2 (Using Counting Sort)
//T.C : O(n + maxDiff), maxDiff <= 10^5
//S.C : O(n)
class Solution {
public:
    long long minSumSquareDiff(vector<int>& nums1, vector<int>& nums2, int k1, int k2) {
        int n = nums1.size(); // Get length of arrays

        vector<int> diff(n);
        // Calculate absolute differences
        for (int i = 0; i < n; ++i) {
            diff[i] = abs(nums1[i] - nums2[i]);
        }

        // Find the maximum difference to size our frequency array optimally
        int maxDiff = *max_element(diff.begin(), diff.end());

        // countDiff[d] = count of each diff
        vector<int> countDiff(maxDiff + 1, 0);
        for (int d : diff) {
            countDiff[d]++; // Populate frequency map
        }

        int K = k1 + k2; // Combine total allowed operations

        // Iterate from highest difference downwards, applying bulk reductions
        for (int currDiff = maxDiff; currDiff > 0 && K > 0; currDiff--) {
            // How many instances of currDiff can we reduce? Limited by K or available frequency
            int countOps             = min(countDiff[currDiff], K); 

            countDiff[currDiff]     -= countOps; // Reduce frequency of current diff
            countDiff[currDiff - 1] += countOps; // Increase frequency of the next lower diff
            K                       -= countOps; // Consume the operations from K
        }
        
        long long result = 0;
        // Calculate the final sum of squared differences
        for (long long d = 1; d <= maxDiff; ++d) {
            result += countDiff[d] * d * d; // (frequency * value^2)
        }

        return result;
    }
};

/*
*
* Dry Run
* nums1=[1,4,10,12], nums2=[5,8,6,9], K=2. Diffs=[4,4,4,3]. maxDiff=4.
* countDiff: [0, 0, 0, 1, 3] (index is difference, value is frequency).
* currDiff = 4: Ops possible = min(countDiff[4], K) = min(3, 2) = 2.
* countDiff[4] -= 2 (becomes 1). countDiff[3] += 2 (becomes 3). K -= 2 (becomes 0).
* K is now 0, loop terminates.
* Result: (countDiff[3] * 3^2) + (countDiff[4] * 4^2) = (3 * 9) + (1 * 16) = 27 + 16 = 43.
*
*/
```

## 🔑 Key Insights
* **Unification of Operations:** `k1` (adjusting `nums1`) and `k2` (adjusting `nums2`) accomplish the exact same goal—they both decrease the absolute difference by 1. Therefore, combining them into a single $K$ is the critical first step .
* **Greedy Principle:** For any numbers $a$ and $b$ where $a > b$, $(a-1)^2 + b^2 < a^2 + (b-1)^2$. Minimizing the largest terms always yields the smallest overall sum of squares .
* **Bulk Operations:** A Max-Heap works conceptually but fails practically due to constraints. Grouping differences by frequency (Counting Sort) transforms the operation from $O(K \log N)$ to $O(maxDiff)$, bypassing the bottleneck .
