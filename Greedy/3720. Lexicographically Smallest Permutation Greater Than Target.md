## 📝 Problem Statement

You are given two strings `s` and `target`, both having length `n`, consisting of lowercase English letters.

Return the lexicographically smallest permutation of `s` that is strictly greater than `target`. If no permutation of `s` is lexicographically strictly greater than `target`, return an empty string `""`.

> **Note:** A string `a` is lexicographically strictly greater than a string `b` (of the same length) if in the first position where `a` and `b` differ, string `a` has a letter that appears later in the alphabet than the corresponding letter in `b`.

---

## 🎯 Constraints

- `1 <= s.length == target.length <= 300`
- `s` and `target` consist of only lowercase English letters.

## 🧠 Approach & Explanation

### The Brute-Force Idea
A naive approach would be to generate all possible permutations of string `s`, sort them lexicographically, and linearly search for the first permutation that is strictly greater than `target`. However, string lengths can go up to 300. The total number of permutations is $300!$, which will instantly result in a Time Limit Exceeded (TLE) error.

### The Optimized Idea (Greedy + Backtracking)
To build the *lexicographically smallest* string that is *strictly greater*, we should avoid rushing to place the largest character right away. Instead:
1. **Match as long as possible:** Attempt to keep the characters identical to the `target` string for as long as you can. 
2. **Branch out carefully:** When a character must be strictly greater than the `target`, find the absolute smallest available character in `s` that is still strictly greater than `target[i]`.
3. **Greedy fill for the rest:** Once a strictly greater character is placed, the prefix is already greater. For all remaining positions, we greedily insert the smallest available characters from `'a'` to `'z'`. 
4. **Backtracking:** If we encounter a dead-end (e.g., no valid characters available that satisfy the constraint), we backtrack by undoing our choice and trying the next available character.

By exploring characters in alphabetical order (`'a'` to `'z'`) at each step, the first valid permutation we completely construct is mathematically guaranteed to be the lexicographically smallest answer.

</details>

## 💻 Solution Code

### Brute-Force Solution (C++)
```cpp
// Intuition: Generate all unique permutations in sorted order and find the first valid one.
// Approach: Sort the string and use C++ next_permutation to sequentially evaluate them.
// Time Complexity: O(N! * N), causing TLE for large N.
// Space Complexity: O(N) auxiliary space.
class Solution {
public:
    string lexGreaterPermutation(string s, string target) {
        // Start with the lexicographically smallest permutation
        sort(s.begin(), s.end());
        
        do {
            // Return the first strictly greater permutation
            if (s > target) {
                return s;
            }
        } while (next_permutation(s.begin(), s.end()));
        
        return "";
    }
};

/*
*
* Dry Run
*
* Input: s = "abc", target = "bba"
* Sorted permutations generated in order:
* "abc" > "bba" -> False
* "acb" > "bba" -> False
* "bac" > "bba" -> False
* "bca" > "bba" -> True. Returns "bca".
*
*/
```

### Optimized Solution (C++)
```cpp
// Intuition: Construct the optimal permutation character-by-character. Match the target as long as possible, then append the smallest available characters once the string is guaranteed to be strictly greater.
// Approach: Use a frequency map and recursive backtracking. Iterate from 'a' to 'z' at each index to naturally form the lexicographically smallest sequence. Short-circuit the recursion as soon as a valid sequence is found.
// Time Complexity: O(N), where N is the length of the string. With short-circuiting and a max branching factor of 26, the optimal path is found linearly.
// Space Complexity: O(N), representing the recursion stack depth and the current string builder.

class Solution {
public:
    string result = "";

    bool solve(string& curr, vector<int>& count, string& target, int i, bool greater) {
        // Base case: check if we successfully built a permutation of target's length
        if(i == target.length()) {
            if(greater) {
                result = curr;
                return true;
            }
            return false;
        }

        // Try placing characters from smallest to largest to guarantee optimal lexicographical order
        for(char ch = 'a'; ch <= 'z'; ch++) {
            // Skip if character frequency is exhausted
            if(count[ch-'a'] == 0)
                continue;
            
            // If prefix matches target exactly, we cannot place a character smaller than target[i]
            if(greater == false && ch < target[i])
                continue;
            
            // DO step: Apply character
            curr.push_back(ch);
            count[ch-'a']--;

            // Determine if placing this character makes our current string strictly greater
            bool isGreater = greater || ch > target[i];

            // EXPLORE step: Proceed to the next index
            if(solve(curr, count, target, i+1, isGreater)) {
                return true; // Short-circuit upon finding the first valid permutation
            }

            // UNDO step: Backtrack and restore frequency if the path fails
            curr.pop_back();
            count[ch-'a']++;
        }

        // Return false if no valid characters can be placed at this state
        return false;
    }

    string lexGreaterPermutation(string s, string target) {
        vector<int> count(26, 0);

        // Store frequencies of characters in s
        for(char &ch : s)
            count[ch-'a']++;
        
        string curr;

        // Initiate backtracking
        solve(curr, count, target, 0, false);

        return result;
    }
};

/*
*
* Dry Run
*
* Input: s = "abc", target = "bba"
* Initial Frequencies: a:1, b:1, c:1
*
* Recursive Step 1 (i=0, greater=false, target[0]='b'):
* - Try 'a': skipped ('a' < 'b').
* - Try 'b': available. curr="b", count[b]=0. isGreater=(false || 'b'>'b') = false.
*   - Recurse to i=1.
*
* Recursive Step 2 (i=1, greater=false, target[1]='b'):
* - Try 'a': skipped ('a' < 'b').
* - Try 'b': skipped (count[b] == 0).
* - Try 'c': available. curr="bc", count[c]=0. isGreater=(false || 'c'>'b') = true.
*   - Recurse to i=2.
*
* Recursive Step 3 (i=2, greater=true, target[2]='a'):
* - greater is true, so no lower-bound restriction. Pick smallest available!
* - Try 'a': available. curr="bca", count[a]=0. isGreater=true.
*   - Recurse to i=3.
*
* Recursive Step 4 (i=3, greater=true):
* - i == target.length(). greater == true.
* - result assigned "bca".
* - Short circuits up the stack returning true.
*
* Final Output: "bca"
*
*/
```

## 📌 Notes & Key Insights
- **Short-circuit Evaluation:** Since we traverse characters from `'a'` to `'z'`, the very first permutation that reaches the base case with `greater == true` is completely guaranteed to be the *lexicographically smallest* valid permutation. Thus, we can safely return `true` to immediately collapse the recursion tree.
- **Dynamic Bounding:** The `greater` boolean acts as an intelligent constraint bypass. As long as `greater == false`, we are bound by the characters of `target`. The moment `greater == true`, all bounds are lifted, transforming the operation into a pure greedy minimum-fill.
