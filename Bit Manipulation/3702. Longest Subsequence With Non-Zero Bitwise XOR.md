Problem Statement: 
You are given an integer array `nums`. Return the length of the longest subsequence in `nums` whose bitwise XOR is non-zero. If no such subsequence exists, return `0`.

Constraints: 
* `1 <= nums.length <= 10^5`
* `0 <= nums[i] <= 10^9`

Examples: 

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [1,2,3]` | `2` | One longest subsequence is `[2, 3]`. The bitwise XOR is `2 XOR 3 = 1`, which is non-zero. |
| **2** | `nums = [2,3,4]` | `3` | The longest subsequence is `[2, 3, 4]`. The bitwise XOR is `2 XOR 3 XOR 4 = 5`, which is non-zero. |

Explanation:
The core problem asks for the maximum length of a subsequence whose elements XOR to a value greater than 0. The constraints dictates that an $O(N)$ solution is required, as $O(N^2)$ or exponential solutions will result in a Time Limit Exceeded (TLE) error.

---

## 💡 Approach

### Brute Force
The most straightforward approach is to try every single possible subsequence (all subsets). For each subset, calculate the XOR of its elements. If the XOR is not zero, record the length of that subset, and finally return the maximum length found. Because each element can either be included or excluded, there are $2^N$ possible subsequences. This exponential time complexity will fail given $N \le 10^5$.

### Optimized Mathematical Observation
Instead of evaluating all subsequences, consider the best-case scenario: the longest possible subsequence is the entire array itself (length $N$). 
1. **Case 1: Total XOR is Non-Zero**
   If we calculate the XOR of all elements in the array and it is non-zero, then the answer is simply $N$. We take the whole array.
2. **Case 2: Total XOR is Zero**
   If the total XOR is zero, it implies that the elements perfectly cancel each other out ($A \oplus A = 0$). By removing *just one* element that is non-zero from the array, the XOR of the remaining elements will no longer be zero (it will equal the value of the removed element). Thus, the maximum length we can achieve is $N - 1$.
3. **Corner Case: All Elements are Zero**
   If every element in the array is `0`, then any subsequence you pick will always yield an XOR of `0`. In this specific scenario, it is impossible to get a non-zero XOR, so the answer must be `0`.

## 💻 Solution Code

### Brute-force Solution (C++)

```cpp
// Intuition: Generate all possible subsequences to find the maximum length with non-zero XOR.
// Approach: Recursively include or exclude each element. If we reach the end and XOR is > 0, return the subset length.
// Time Complexity: O(2^N), where N is the length of the array, due to generating all subsets. Will cause TLE.
// Space Complexity: O(N), for the recursion stack space.

class Solution {
public:
    int solve(int idx, int currentXor, int len, vector<int>& nums) {
        if (idx == nums.size()) {
            return currentXor != 0 ? len : 0;
        }
        
        // Include the current element
        int take = solve(idx + 1, currentXor ^ nums[idx], len + 1, nums);
        // Exclude the current element
        int skip = solve(idx + 1, currentXor, len, nums);
        
        return max(take, skip);
    }
    
    int longestSubsequence(vector<int>& nums) {
        return solve(0, 0, 0, nums);
    }
};
```

### Optimized Solution (C++)

```cpp
// Intuition: The maximum length is either N (if total XOR != 0) or N-1 (if total XOR == 0). The only exception is an array of all zeros.
// Approach: 
// 1. Calculate the XOR of the entire array.
// 2. Track if all elements are strictly zero.
// 3. If all elements are zero, return 0.
// 4. If total XOR is 0, return N - 1. Otherwise, return N.
// Time Complexity: O(N), where N is the number of elements in nums, as we iterate through the array once.
// Space Complexity: O(1), as we only use a few variables for XOR accumulation and flag checking.

class Solution {
public:
    int longestSubsequence(vector<int>& nums) {
        int n = nums.size(); // Get the size of the array

        int resultXor = 0;   // To store the overall XOR of all elements
        bool allZero = true; // Flag to check if all elements are strictly zero

        for(int &x : nums) {
            resultXor = (resultXor ^ x); // Compute cumulative XOR

            if(x != 0) {
                allZero = false; // We found at least one non-zero element
            }
        }

        // If the array consists entirely of zeros, no valid subsequence exists
        if(allZero) {
            return 0;
        }

        // If total XOR is 0, drop one non-zero element (length N - 1). Otherwise, take all (length N).
        return (resultXor == 0) ? n - 1 : n;
    }
};

/*
*
* Dry Run
* 
* Input: nums = [1, 2, 3]
* Initialization: n = 3, resultXor = 0, allZero = true
* 
* Iteration 1:
* x = 1
* resultXor = 0 ^ 1 = 1
* x != 0, so allZero = false
* 
* Iteration 2:
* x = 2
* resultXor = 1 ^ 2 = 3
* x != 0, so allZero = false
* 
* Iteration 3:
* x = 3
* resultXor = 3 ^ 3 = 0
* x != 0, so allZero = false
* 
* Loop completes.
* allZero is false, so we don't return 0.
* resultXor is 0.
* Return: (resultXor == 0) ? 3 - 1 : 3  => returns 2.
* Final Output: 2
*
*/
```

## 📝 Notes
* Recognizing bitwise properties often converts $O(2^N)$ subset problems into $O(N)$ or even $O(1)$ arithmetic observations.
* Always carefully check the problem constraints to see if the value `0` is possible. Missing the `nums[i] == 0` constraint leads to failing the all-zero array corner case.

## 🔍 Key Insights
1. **XOR Self-Inverse Property:** $A \oplus A = 0$. If an array totals to $0$, any single non-zero element $X$ can be removed to shift the total sum to $0 \oplus X = X$.
2. **Subsequence vs. Subarray:** Because the problem asks for a subsequence, we can freely pick and choose which elements to exclude. Removing *any* single non-zero element conceptually drops our length by exactly 1 without violating order constraints.
