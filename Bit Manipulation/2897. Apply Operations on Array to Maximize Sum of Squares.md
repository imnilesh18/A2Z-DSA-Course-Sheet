## 📜 Problem Statement

You are given a **0-indexed** integer array `nums` and a positive integer `k`.

You can do the following operation on the array **any number of times**:

*   Choose any two distinct indices `i` and `j` and simultaneously update the values of `nums[i]` to `(nums[i] AND nums[j])` and `nums[j]` to `(nums[i] OR nums[j])`. Here, `OR` denotes the bitwise OR operation, and `AND` denotes the bitwise AND operation.

You have to choose `k` elements from the final array and calculate the sum of their squares.

Return the **maximum sum of squares** you can achieve.

Since the answer can be very large, return it **modulo** $10^9 + 7$.

---

## 🧮 Constraints

- $1 \le k \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

## 🧠 Approach & Explanation

When working with bitwise `AND` and `OR` operations applied simultaneously to two numbers, a fascinating pattern emerges: the operations act simply as a "transfer" mechanism for set bits (`1`s) between the two numbers. No bits are ever destroyed or created.

If you perform `nums[i] AND nums[j]`, you keep only the bits that are set in **both** numbers.
If you perform `nums[i] OR nums[j]`, you keep the bits that are set in **either** number.
In essence, any `1` bit present in the smaller number gets shifted to the corresponding bit position in the larger number, while the total frequency of `1`s across all numbers in the array remains strictly constant.

### The Greedy Mathematical Proof
Why do we want to shift bits to make some numbers extremely large at the expense of making others smaller?
Let’s assume we have two numbers, $x$ and $y$ (where $y > x$). If we transfer a bit value $d$ from $x$ to $y$, our new numbers become $(x - d)$ and $(y + d)$.
If we evaluate the sum of their squares:
New Sum = $(x - d)^2 + (y + d)^2 = x^2 + y^2 + 2d^2 + 2dy - 2dx$
Since $y > x$ and $d > 0$, the expression $2dy - 2dx$ is inherently positive.
Thus, **$(x - d)^2 + (y + d)^2 > x^2 + y^2$**.
This mathematically proves that to maximize the sum of squares, we should greedily make the largest numbers as large as physically possible.

### Step-by-Step Implementation
1. **Count Bit Frequencies:** Iterate through the array and count how many times a `1` appears at every bit position (from `0` to `31`) across all numbers. Store this in an array of size 32.
2. **Greedy Construction:** We need to select `k` numbers. To make each of these `k` numbers as large as possible, we iterate from bit `0` to `31`. If our frequency count for a bit is greater than `0`, we set that bit to `1` in our current number and decrement the count.
3. **Accumulate Result:** Square the greedily constructed number, apply the modulo $10^9 + 7$, and add it to the final result. Repeat this process `k` times.

---

## 🔑 Key Insights

- The sum of elements in the array never changes after the operation, and neither does the frequency of `1`s at any bit position.
- Squaring a larger number yields a much greater increase than squaring two smaller, evenly distributed numbers. Thus, concentrating all available bits into the fewest numbers possible yields the maximum sum of squares.

## 💻 Solution Code

```cpp
// Intuition: The bitwise AND and OR operations between two numbers simply shift '1' bits from one number to the other. To maximize the sum of squares, we should greedily accumulate as many '1's as possible into single numbers to make them as large as possible.
// Approach: 
// 1. Count the frequency of '1's at each bit position (0 to 31) across all numbers in the array.
// 2. Greedily construct k numbers. For each number, iterate through all 32 bit positions.
// 3. If a bit position has a count > 0, set that bit in the current number and decrement the count.
// 4. Add the square of each constructed number to the total sum, modulo 10^9 + 7.
// Time Complexity: O(N + K) where N is the length of nums. We iterate over N numbers (32 bits each) and then loop K times (32 bits each).
// Space Complexity: O(1) as we only use a fixed size array of 32 integers to store bit counts.

//Approach (Bits Observation + Greedy)
//T.C : O(n+k)
//S.C : O(1)
class Solution {
public:
    int MOD = 1e9+7;

    int maxSum(vector<int>& nums, int k) {
        vector<int> count(32, 0); // Array to store the frequency of '1's at each bit position

        // Count the set bits at each bit position for all numbers
        for(int &num : nums) {
            for(int b = 0; b < 32; b++) {
                if(num & (1 << b)) {
                    count[b]++; // found a '1' in this bit position b
                }
            }
        }

        long long result = 0;

        // Greedily construct k numbers to maximize their values
        while(k--) {
            long long curr = 0;

            // Try to set every bit position from 0 to 31
            for(int b = 0; b < 32; b++) {
                if(count[b] > 0) {
                    count[b]--; // Use one '1' from this bit position

                    curr = (curr | (1 << b)); // Set the b-th bit in the current number
                }
            }

            // Add the square of the constructed number to the result, applying modulo
            result = (result + (curr*curr)) % MOD;
        }

        return result;

    }
};

/*
*
* Dry Run
*
* Input: nums = [2,6,5,8], k = 2
*
* 1. Binary representations & initial bit counts:
*    2 = 0010
*    6 = 0110
*    5 = 0101
*    8 = 1000
*
*    count array for bits [0, 1, 2, 3]:
*    bit 0: 1 (from 5)
*    bit 1: 2 (from 2, 6)
*    bit 2: 2 (from 6, 5)
*    bit 3: 1 (from 8)
*    count = [1, 2, 2, 1]
*
* 2. Constructing numbers (k = 2):
*    First number (k=2):
*    - bit 0: count is 1 -> use it, count[0]=0, curr = 1
*    - bit 1: count is 2 -> use it, count[1]=1, curr = 3
*    - bit 2: count is 2 -> use it, count[2]=1, curr = 7
*    - bit 3: count is 1 -> use it, count[3]=0, curr = 15
*    First number = 15 (1111 in binary). result = (0 + 15^2) = 225
*
*    Second number (k=1):
*    - bit 0: count is 0 -> skip, curr = 0
*    - bit 1: count is 1 -> use it, count[1]=0, curr = 2
*    - bit 2: count is 1 -> use it, count[2]=0, curr = 6
*    - bit 3: count is 0 -> skip, curr = 6
*    Second number = 6 (0110 in binary). result = (225 + 6^2) = 225 + 36 = 261
*
* 3. Return result: 261
*
*/
```
