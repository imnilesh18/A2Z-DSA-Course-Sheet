# 115. Distinct Subsequences

**Difficulty:** `Hard`

**Tags:** `String`, `Dynamic Programming`

## 📝 Problem Statement

Given two strings `s` and `t`, return the number of distinct subsequences of `s` which equals `t`.

The test cases are generated so that the answer fits on a 32-bit signed integer.

### Constraints:
- `1 <= s.length, t.length <= 1000`
- `s` and `t` consist of English letters.

## 🧠 Approach

### Core Idea
The problem asks us to find all possible ways to form string `t` by deleting some (or no) characters from string `s`. This fundamentally requires exploring all character-matching possibilities, making it a perfect candidate for **Dynamic Programming**. 

At any point, if we use pointers `i` and `j` to represent our current position in `s` and `t` respectively:
1. **If the characters mismatch (`s[i] != t[j]`):** We have no choice but to ignore the current character in `s` and move our `s` pointer forward to find a valid match.
2. **If the characters match (`s[i] == t[j]`):** We branch into two choices:
   - **Take it:** Use this character to match `t[j]`, moving both pointers forward.
   - **Leave it:** Don't use this match, hoping to find another matching character later in `s`. (This is crucial for finding *multiple* distinct subsequences).

### Base Cases
- If we successfully traverse all characters of `t` (`n == 0`), we have found a valid subsequence! Return `1`.
- If we exhaust string `s` (`m == 0`) but still have characters left in `t`, it's impossible to form the sequence. Return `0`.

## 💻 Solution Codes

### Approach 1: Recursion + Memoization

```cpp
// Intuition: We need to find the number of ways a string `t` can be formed as a subsequence of `s`. We can use a recursive approach to explore all possibilities, making decisions at each character. If characters match, we can either use it or skip it to find another match. We memoize overlapping subproblems to avoid redundant calculations.
// Approach: 
// 1. Use two pointers/lengths `m` and `n` for strings `s` and `t` respectively.
// 2. Base case: if `n == 0`, we found a match (return 1). If `m == 0` (and `n > 0`), no match is possible (return 0).
// 3. If `s[m-1] == t[n-1]`, we have two choices: take the character (move both pointers) or leave it (move only `m`). Sum both possibilities.
// 4. If `s[m-1] != t[n-1]`, we must skip the character in `s` (move only `m`).
// 5. Store the results in a 2D `dp` array where `dp[m][n]` holds the answer for lengths `m` and `n`.
// Time Complexity: O(m*n) where m and n are lengths of strings s and t. Each state is computed at most once.
// Space Complexity: O(m*n) for the memoization table + O(m) for the recursion stack depth.
class Solution {
public:

    int dp[1001][1001];
    int solve(string& s, string& t, int m, int n) {
        // Base case: successfully matched all characters in t
        if(n == 0)
            return dp[m][n] = 1;
        // Base case: exhausted string s before finishing t
        if(m == 0)
            return dp[m][n] = 0;
        
        // Return pre-calculated result if it exists
        if(dp[m][n] != -1)
            return dp[m][n];
        
        /*
            (rabb) b (it)
            (ra)   b (bbit)
            (rab)  b (bit)
            This can help to understand the if condition below
        */
        // If characters match, explore both taking and leaving the character
        if(s[m-1] == t[n-1])
            return dp[m][n] = solve(s, t, m-1, n) + solve(s, t, m-1, n-1);
        else
            // If mismatch, we can only skip the current character in s
            return dp[m][n] = solve(s, t, m-1, n);
    }

    int numDistinct(string s, string t) {
        int m = s.length();
        int n = t.length();
        // Impossible to form t if s is strictly shorter
        if(m < n)
            return 0;
        // Initialize DP table with -1
        memset(dp, -1, sizeof(dp));
        return solve(s, t, m, n);
    }
};

/*
*
* Dry Run
* s = "babgbag", t = "bag", m = 7, n = 3
* solve(7, 3): s[6] ('g') == t[2] ('g') -> branch to solve(6, 3) + solve(6, 2)
* solve(6, 2): s[5] ('a') == t[1] ('a') -> branch to solve(5, 2) + solve(5, 1)
* Tree expands until n=0 (return 1) or m=0 (return 0).
* Overlapping subproblems are fetched directly from dp[][] in O(1) time.
*
*/
```

### Approach 2: Bottom-Up DP

```cpp
// Intuition: The recursive solution can be converted to an iterative bottom-up approach to avoid recursion stack overflow. We build a 2D DP table iteratively, where `dp[i][j]` represents the number of distinct subsequences of `s[0..i-1]` matching `t[0..j-1]`.
// Approach: 
// 1. Create a 2D vector `dp` of size `(m+1) x (n+1)`. Use `unsigned long long` to prevent overflow.
// 2. Initialize the first column `dp[row][0]` to 1 because an empty string `t` can be formed in 1 way from any prefix of `s`.
// 3. Initialize the first row `dp[0][col]` to 0 because a non-empty `t` cannot be formed from an empty `s`.
// 4. Iterate through the table. If `s[i-1] == t[j-1]`, `dp[i][j] = dp[i-1][j-1] + dp[i-1][j]`.
// 5. If `s[i-1] != t[j-1]`, `dp[i][j] = dp[i-1][j]`.
// 6. Return `dp[m][n]`.
// Time Complexity: O(m*n) since we traverse the entire 2D table once.
// Space Complexity: O(m*n) to store the 2D DP table.
class Solution {
public:
    typedef unsigned long long ull;
    int numDistinct(string s, string t) {
        int m = s.length();
        int n = t.length();
        
        // 2D DP table initialized to 0
        vector<vector<ull>> dp(m+1, vector<ull>(n+1));
        
        //There is one way to generate empty string from given s
        for(int row = 0; row<m+1; row++) {
            dp[row][0] = 1;
        }
        
        //There is zero way to generate non-empty string from given empty s
        for(int col = 1; col<n+1; col++) {
            dp[0][col] = 0;
        }
        
        // Build the table iteratively
        for(int i = 1; i<m+1; i++) {
            for(int j = 1; j<n+1; j++) {
                // If characters match, add ways from taking and leaving
                if(s[i-1] == t[j-1])
                    dp[i][j] = dp[i-1][j-1] + dp[i-1][j];
                else
                    // If no match, inherit ways from the previous substring of s
                    dp[i][j] = dp[i-1][j];
            }
        }
        
        // Final state holds the total distinct subsequences
        return dp[m][n];
    }
};

/*
*
* Dry Run
* s = "rabbbit", t = "rabbit", m = 7, n = 6
* Initialize dp[0..7][0] = 1 (column 0)
* Initialize dp[0][1..6] = 0 (row 0)
* i=1 ('r'), j=1 ('r'): match -> dp[1][1] = dp[0][0] + dp[0][1] = 1 + 0 = 1
* i=2 ('a'), j=2 ('a'): match -> dp[2][2] = dp[1][1] + dp[1][2] = 1 + 0 = 1
* Process repeats row by row; final count accumulates at dp[7][6] yielding 3.
*
*/
```

### Approach 3: Optimized Bottom-Up DP

```cpp
// Intuition: Notice that in the 2D DP approach, calculating the current row `i` only requires the values from the previous row `i-1`. We do not need to keep the entire `m x n` table in memory; two 1D arrays (`prev` and `curr`) of size `n+1` are sufficient.
// Approach: 
// 1. Create two 1D vectors `curr` and `prev` of size `n+1`.
// 2. Initialize `prev[0] = 1` and `curr[0] = 1` to represent matching an empty `t`.
// 3. Iterate through `s`. For each character, iterate through `t`.
// 4. Update `curr[j]` using values from `prev[j-1]` and `prev[j]`.
// 5. After finishing the inner loop, make `prev = curr` to move to the next row.
// 6. Return `prev[n]`.
// Time Complexity: O(m*n) as we still process all character pairs.
// Space Complexity: O(n) because we only keep two 1D arrays of size n+1.
/*
    If you notice, you are just requiring the previous row's value
    See the if condition    - dp[i-1][j-1] + dp[i-1][j]; //(i-1) points to previous row
    
    See the else condition  - dp[i-1][j]; //(i-1) points to previous row
    
    So, why not simply store previous value in a 1-D array
    We can then solve this qn, using O(m+n) space complexity
*/
class Solution {
public:
    typedef unsigned long long ull;
    
    int numDistinct(string s, string t) {
        int m = s.length();
        int n = t.length();

        vector<ull> curr(n+1, 0); //Replace dp[i] with curr
        vector<ull> prev(n+1, 0); //Replace dp[i-1] with prev
        
        // Base cases for empty string t
        prev[0] = curr[0] = 1;
        
        for(int i = 1; i<m+1; i++) {
            
            for(int j = 1; j<n+1; j++) {
                
                // If match: fetch diagonal + top from previous row
                if(s[i-1] == t[j-1])
                    curr[j] = prev[j-1] + prev[j];
                else
                    // If mismatch: carry down from top
                    curr[j] = prev[j];
            }
            // Update previous array for the next iteration
            prev = curr;
        }

        // The answer bubbles down to the end of the prev array
        return prev[n];
    }
};

/*
*
* Dry Run
* s = "babgbag", t = "bag", m = 7, n = 3
* Initial state: prev = [1, 0, 0, 0], curr = [1, 0, 0, 0]
* i=1 ('b'): curr becomes [1, 1, 0, 0]. Set prev = curr.
* i=2 ('a'): curr becomes [1, 1, 1, 0]. Set prev = curr.
* i=3 ('b'): curr becomes [1, 2, 1, 0]. Set prev = curr.
* Iterations continue, updating the 1D arrays efficiently.
* Final answer extracted from prev[3] = 5.
*
*/
```

* **The "Make Today Count" Principle:** Sometimes delaying learning DP concepts causes them to pile up. Tackling problems like this head-on solidifies core string-matching techniques.
* **1D Space Optimization:** As you push past 1250+ solved problems on coding platforms, transforming 2D tabular DP into 1D arrays becomes second nature. It's a critical pattern to master for technical interviews.

<details>
<summary><b>Why `unsigned long long`?</b></summary>
The problem states the final answer fits in a 32-bit signed integer, but intermediate overlapping calculations in a bottom-up DP table can momentarily exceed standard integer limits depending on how the loops evaluate. Using `unsigned long long` safely guards against this.
</details>
