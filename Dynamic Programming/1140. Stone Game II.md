## 📌 Problem Overview

**Problem Link:** [LeetCode 1140 - Stone Game II](https://leetcode.com/problems/stone-game-ii/description/)  
**Difficulty:** Medium  
**Category:** Dynamic Programming / Game Theory / Minimax / Array / Prefix Sum  

Alice and Bob continue their games with piles of stones. There are a number of piles arranged in a row, and each pile has a positive integer number of stones `piles[i]`. The objective of the game is to end with the most stones.

Alice and Bob take turns, with **Alice starting first**.

On each player's turn, that player can take all the stones in the first $X$ remaining piles, where $1 \le X \le 2M$. Then, we set $M = \max(M, X)$. Initially, $M = 1$.

The game continues until all the stones have been taken.

Assuming Alice and Bob play optimally, return the **maximum number of stones Alice can get**.

## 🧠 Strategic Approach & Explanation

### 1. Understanding Game Theory & Optimal Play

In game theory problems involving two players playing optimally:
* **When it is Alice's Turn (`person = 1`):**  
  Alice wants to **maximize** her total score. She explores all valid choices of $X$ ($1 \le X \le 2M$), adds the sum of stones from the chosen $X$ piles to her score, and passes the turn to Bob. She chooses the path that maximizes `stones + future_score`.
* **When it is Bob's Turn (`person = 0`):**  
  Bob plays optimally to maximize his own score, which translates to **minimizing** Alice's remaining score from this point forward. On Bob's turn, Bob takes $X$ piles, but those stones belong to Bob (they are **not** added to Alice's total). When Bob passes the turn back to Alice, Alice gets the **minimum** outcome among all choices Bob could make.

### 2. State Representation

We represent our dynamic state using three parameters:
1. `person`: `1` if it is Alice's turn, `0` if it is Bob's turn.
2. `i`: The current starting pile index ($0 \le i \le N$).
3. `M`: The current multiplier determining how many piles can be taken ($1 \le X \le 2M$).

### 3. Transition Relations

For a state `(person, i, M)`:
* **Base Case:** If $i \ge N$, no piles remain, return `0`.
* **Choices for $X$:** $1 \le X \le \min(2M, N - i)$.
* **Accumulating Stones:** Compute the prefix sum of stones taken in the current turn:
  $$\text{stones} = \sum_{k=0}^{X-1} \text{piles}[i + k]$$
* **Alice's Decision (`person == 1`):**
  $$\text{result} = \max_{X} \left( \text{stones} + \text{solve}(person = 0,\, i' = i + X,\, M' = \max(M, X)) \right)$$
* **Bob's Decision (`person == 0`):**
  $$\text{result} = \min_{X} \left( \text{solve}(person = 1,\, i' = i + X,\, M' = \max(M, X)) \right)$$

### 4. Overlapping Subproblems & Memoization

Notice that multiple decision branches will evaluate the same state `(person, i, M)`. Without memoization, the recursion explodes exponentially.  
By storing the results in a 3D memoization table `t[2][101][101]`, we ensure each unique state is computed **only once**.

## 💻 Solution Code

### Brute Force Solution (Pure Recursion)

```cpp
// Intuition:
// Explore all valid game choices for Alice and Bob recursively. Alice tries to maximize her total stones,
// while Bob plays optimally to minimize Alice's remaining score.
// Approach:
// Use recursive branching where Alice maximizes (stones + recursive call) and Bob minimizes (recursive call).
// Time Complexity: O(2^N) - Exponential tree of game states without memoization.
// Space Complexity: O(N) - Recursion stack depth proportional to the number of piles.

class Solution {
public:
    int n;

    int solveForAlice(vector<int>& piles, int person, int i, int M) {
        // Base case: If index exceeds array bounds, no stones remain
        if (i >= n)
            return 0;

        // Initialize best result: maximize for Alice, minimize for Bob
        int result = (person == 1) ? -1 : INT_MAX;
        int stones = 0;

        // Try taking X piles where 1 <= X <= min(2*M, n-i)
        for (int x = 1; x <= min(2 * M, n - i); x++) {
            stones += piles[i + x - 1]; // Accumulate stones taken in current turn

            if (person == 1) { // Alice's turn: maximize Alice's total score
                result = max(result, stones + solveForAlice(piles, 0, i + x, max(M, x)));
            } else { // Bob's turn: minimize Alice's future total score
                result = min(result, solveForAlice(piles, 1, i + x, max(M, x)));
            }
        }

        return result;
    }

    int stoneGameII(vector<int>& piles) {
        n = piles.size();
        return solveForAlice(piles, 1, 0, 1); // Game starts with Alice, index 0, M = 1
    }
};

/*
*
* Dry Run
*
* Input: piles = [2, 7, 9, 4, 4], n = 5
* Start: solveForAlice(piles, person=1, i=0, M=1)
*   Loop x = 1 to min(2*1, 5-0) = 2:
*   - x = 1: stones = 2 (piles[0])
*            Call solveForAlice(piles, person=0, i=1, M=max(1,1)=1)
*            Bob branches x=1, x=2 to minimize score for Alice.
*   - x = 2: stones = 2 + 7 = 9 (piles[0] + piles[1])
*            Call solveForAlice(piles, person=0, i=2, M=max(1,2)=2)
*            Bob takes remaining piles [9, 4, 4], leaving 0 for Alice.
*   Alice selects max(10, 9) = 10.
* Output: 10
*
*/
```

### Optimized Solution (Recursion + Dynamic Programming Memoization)

```cpp
// Intuition:
// The recursive game tree contains overlapping subproblems defined by state (person, i, M).
// Memoizing state outcomes avoids redundant computations and drastically reduces running time.
// Approach:
// 1. Maintain a 3D DP array t[2][101][101] initialized to -1.
// 2. Return cached result if t[person][i][M] is already computed.
// 3. For Alice (person = 1), compute max(stones + recursive call for Bob).
// 4. For Bob (person = 0), compute min(recursive call for Alice).
// 5. Store and return the computed optimal value for state (person, i, M).
// Time Complexity: O(N^3) - 2 * N * N states, each taking at most O(N) operations in loop.
// Space Complexity: O(N^3) - Memoization table t[2][101][101] plus recursion stack depth O(N).

class Solution {
public:
    int n;
    int t[2][101][101]; // t[person][i][M] - stores memoized game outcomes

    int solveForAlice(vector<int>& piles, int person, int i, int M) {
        // Base case: No piles left to take
        if (i >= n)
            return 0;

        // Return memoized result if state has already been evaluated
        if (t[person][i][M] != -1)
            return t[person][i][M];

        // Initialize optimal value based on active player
        int result = (person == 1) ? -1 : INT_MAX;
        int stones = 0;

        // Explore all valid choices of X piles
        for (int x = 1; x <= min(2 * M, n - i); x++) {
            stones += piles[i + x - 1]; // Incrementally add stone count for X piles

            if (person == 1) { // Alice's turn: maximize score
                result = max(result, stones + solveForAlice(piles, 0, i + x, max(M, x)));
            } else { // Bob's turn: minimize Alice's remaining score
                result = min(result, solveForAlice(piles, 1, i + x, max(M, x)));
            }
        }

        // Memoize and return the computed result
        return t[person][i][M] = result;
    }

    int stoneGameII(vector<int>& piles) {
        n = piles.size();

        // Initialize memoization table with -1
        memset(t, -1, sizeof(t));

        // Start game with Alice (person=1), index 0, M=1
        return solveForAlice(piles, 1, 0, 1);
    }
};

/*
*
* Dry Run
*
* Input: piles = [1, 2, 3, 4, 5, 100], n = 6
* Initial Call: solveForAlice(piles, person=1, i=0, M=1)
*   State space: t[2][101][101] initialized to -1
*   Alice evaluates choices x=1..2:
*   - x=1: stones=1, calls Bob at i=1, M=1
*   - x=2: stones=3, calls Bob at i=2, M=2
*   Sub-calls check t[person][i][M] first before performing recursive loops.
*   Once Bob minimizes and Alice maximizes at each layer, optimal result 104 is computed and cached.
* Output: 104
*
*/
```

## 🔑 Key Insights

1. **Zero-Sum Game Perspective:**  
   Alice's gain is Bob's loss. When tracking Alice's total score, Bob's choices act as a **minimizing force** against Alice's future accumulated stones.
2. **Incremental Sum Optimization:**  
   Instead of recomputing pile sums from scratch inside the loop, using `stones += piles[i + x - 1]` maintains an efficient running prefix total.
3. **Upper Bound Constraint on $X$:**  
   Limiting $X$ to $\min(2M, N - i)$ prevents out-of-bounds array access and eliminates invalid state exploration.
