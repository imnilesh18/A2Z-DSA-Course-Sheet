## 📝 Problem Statement

There are several stones arranged in a row, and each stone has an associated value which is an integer given in the array `stoneValue`.

In each round of the game, Alice divides the row into **two non-empty rows** (i.e., left row and right row). Then, Bob calculates the value of each row, which is the sum of the values of all the stones in this row. Bob throws away the row which has the **maximum value**, and Alice's score increases by the value of the remaining row. 

* If the values of the two rows are equal, Bob lets Alice decide which row will be thrown away. 
* The next round starts with the remaining row.

The game ends when there is only **one stone remaining**. Alice's score is initially zero.

**Return the maximum score that Alice can obtain.**

---

## ⚠️ Constraints

* `1 <= stoneValue.length <= 500`
* `1 <= stoneValue[i] <= 10^6`

## 🧠 Approach & Explanation

The problem asks us to find the optimal way to divide the array to maximize Alice's score. Since Alice can choose to draw the dividing line anywhere between the stones, we have multiple choices at each step. This naturally suggests a **Recursion** approach, and since we encounter overlapping subproblems, we can optimize it using **Dynamic Programming (Memoization or Tabulation)**.

### Step-by-Step Logic:
1. **Prefix Sum for Quick Queries**: To calculate the sum of any subarray `[L...R]` in $O(1)$ time, we precompute a cumulative/prefix sum array.
2. **Recursive Choices**: For a segment spanning indices `L` to `R`, Alice can divide the array at any `mid` index where $L \leq mid < R$.
   - **Left Array**: Elements from `L` to `mid`.
   - **Right Array**: Elements from `mid + 1` to `R`.
3. **Bob's Rule**: 
   - If `sum(Left) < sum(Right)`, Bob discards the Right array. Alice gets `sum(Left)` and plays the next round on the Left array.
   - If `sum(Left) > sum(Right)`, Bob discards the Left array. Alice gets `sum(Right)` and plays the next round on the Right array.
   - If `sum(Left) == sum(Right)`, Bob lets Alice choose. Alice will pick the side that gives her the absolute maximum potential score.
4. **Base Case**: The game stops when `L >= R` (i.e., only 1 element remains). The score gained in this base case is `0`.
5. **Optimization**:
   - **Top-Down (Memoization)**: Use a 2D array `t[L][R]` to store computed maximum scores for subarrays.
   - **Bottom-Up (Tabulation)**: Build the results iteratively by defining interval lengths, traversing from smaller subproblems to larger ones.

## 💻 Solution Code

### 1️⃣ Optimized Solution (Top-Down DP: Recursion + Memoization)

```cpp
// Intuition: Since Alice has multiple valid split points at each round, we need to explore all possibilities to find the maximum score. Overlapping subproblems hint at using Dynamic Programming.
// Approach: Precompute prefix sums to get range sums in O(1). Use recursion to explore all partition points (mid) for a range [l..r]. Depending on which partition sum is strictly smaller, make the recursive call on that partition. If equal, try both. Cache results in a 2D array to avoid redundant work.
// Time Complexity: O(n^3) - O(n^2) distinct states, and an O(n) loop inside to find the optimal mid point.
// Space Complexity: O(n^2) - O(n^2) for the 2D memoization array and O(n) for the recursion stack.
class Solution {
public:
    int t[501][501]; // Memoization table
    
    int solve(int l, int r, vector<int>& cumSum) {
        // Base case: If segment has 1 or fewer elements
        if(l >= r) {
            return 0; // Zero score. No further division possible
        }

        // Return precalculated state if available
        if(t[l][r] != -1) {
            return t[l][r];
        }

        int score = 0;
        
        // Explore every possible split point
        for(int mid = l; mid <= r-1; mid++) {
            // Compute sums for the two halves in O(1)
            int leftSum  = cumSum[mid] - (l-1 >= 0 ? cumSum[l-1] : 0); //[l..mid]
            int rightSum = cumSum[r] - cumSum[mid]; //mid+1, r

            // Bob's rules: take the strictly smaller half
            if(leftSum < rightSum) {
                score = max(score, leftSum + solve(l, mid, cumSum));
            } else if(leftSum > rightSum) {
                score = max(score, rightSum + solve(mid+1, r, cumSum));
            } else {
                // If equal, Alice plays optimally by testing both halves
                score = max({score, leftSum + solve(l, mid, cumSum), rightSum + solve(mid+1, r, cumSum)});
            }
        }

        // Save and return maximum score
        return t[l][r] = score;
    }

    int stoneGameV(vector<int>& stoneValue) {
        int n = stoneValue.size();

        // Create prefix sum array for fast range queries
        vector<int> cumSum(n, 0);
        cumSum[0] = stoneValue[0];
        for(int i = 1; i < n; i++) {
            cumSum[i] = cumSum[i-1] + stoneValue[i];
        }

        // Initialize memoization table with -1
        memset(t, -1, sizeof(t));
        
        // Start game with the full array boundary
        return solve(0, n-1, cumSum);
    }
};

/*
*
* Dry Run
* Input: stoneValue = [6, 2, 3] -> cumSum = [6, 8, 11]
* Call: solve(0, 2)
* mid = 0: leftSum = 6, rightSum = 5
* leftSum > rightSum -> score = max(0, 5 + solve(1, 2))
*   Call: solve(1, 2)
*   mid = 1: leftSum = 2, rightSum = 3
*   leftSum < rightSum -> score = max(0, 2 + solve(1, 1))
*     Call: solve(1, 1) -> Base case hit, returns 0
*   solve(1, 2) returns 2 + 0 = 2
* mid = 0 evaluates to 5 + 2 = 7
* mid = 1: leftSum = 8, rightSum = 3
* leftSum > rightSum -> score = max(7, 3 + solve(2, 2))
*   Call: solve(2, 2) -> Base case hit, returns 0
* mid = 1 evaluates to max(7, 3 + 0) = 7
* solve(0, 2) returns 7
*
*/

```

### 2️⃣ Optimized Solution (Bottom-Up DP: Tabulation)

```cpp
// Intuition: We can eliminate recursion overhead by solving smaller subproblems first and building up to the final solution using a bottom-up DP table.
// Approach: Construct the DP table dynamically. Iterate `l` backward from `n-1` to `0`, and `r` forward from `l+1` to `n`. This guarantees that by the time we calculate `t[l][r]`, smaller segments `t[l][mid]` and `t[mid+1][r]` are already evaluated.
// Time Complexity: O(n^3) - Three nested loops: `l`, `r`, and `mid` to explore partitions.
// Space Complexity: O(n^2) - O(n^2) required to maintain the 2D DP table.
class Solution {
public:
    int stoneGameV(vector<int>& stoneValue) {
        int n = stoneValue.size();

        // Create prefix sum array
        vector<int> cumSum(n, 0);
        cumSum[0] = stoneValue[0];
        for (int i = 1; i < n; i++) {
            cumSum[i] = cumSum[i - 1] + stoneValue[i];
        }

        // DP table initialized to 0
        vector<vector<int>> t(n+1, vector<int>(n+1, 0));

        // Iterate subproblems in reverse to build bottom-up
        for(int l = n-1; l >= 0; l--) {
            for(int r = l+1; r < n; r++) {

                int score = 0; // Local max score for range l...r
                
                // Explore partition points
                for(int mid = l; mid <= r-1; mid++) {
                    // Extract segment sums using prefix arrays
                    int leftSum  = cumSum[mid] - (l-1 >= 0 ? cumSum[l-1] : 0); //[l..mid]
                    int rightSum = cumSum[r] - cumSum[mid]; //mid+1, r

                    // Check which side to drop based on Bob's rules
                    if(leftSum < rightSum) {
                        score = max(score, leftSum + t[l][mid]);
                    } else if(leftSum > rightSum) {
                        score = max(score, rightSum + t[mid+1][r]);
                    } else {
                        // Equality gives Alice the choice
                        score = max({score, leftSum + t[l][mid], rightSum + t[mid+1][r]});
                    }
                }

                // Store computed score for current interval
                t[l][r] = score;
            }
        }

        // Output max score for the entire array
        return t[0][n-1];
    }
};

/*
*
* Dry Run
* Input: stoneValue = [4, 5] -> cumSum = [4, 9]
* DP Table sizes: 3x3 initialized to 0
* l = 1, r = 2 (Does not process since r < n but n=2, wait let's use n=2 explicitly)
* Iterations:
* l = 0: r = 1
*   mid = 0:
*   leftSum = cumSum[0] = 4
*   rightSum = cumSum[1] - cumSum[0] = 5
*   leftSum (4) < rightSum (5) -> smaller sum is kept
*   score = max(0, leftSum + t[0][0]) = 4 + 0 = 4
*   t[0][1] = 4
* Returns t[0][1] which is 4
*
*/

```

## 📌 Key Insights

* The prefix sum approach is mandatory here to prevent an $O(N)$ lookup from dragging the total Time Complexity down to $O(N^4)$.
* In the Bottom-Up approach, realizing that the `L` parameter needs to traverse backwards (`n-1` to `0`) is crucial because computing state `t[l][r]` relies on knowing future segment answers like `t[mid+1][r]` which require larger starting points to be computed first.
