## 📝 Problem Statement

Given a string `s` containing only three types of characters: `'('`, `')'` and `'*'`, return `true` if `s` is valid. 

The following rules define a valid string:
* Any left parenthesis `'('` must have a corresponding right parenthesis `')'`.
* Any right parenthesis `')'` must have a corresponding left parenthesis `'('`.
* Left parenthesis `'('` must go before the corresponding right parenthesis `')'`.
* `'*'` could be treated as a single right parenthesis `')'` or a single left parenthesis `'('` or an empty string `""`[cite: 1].

---

## ⚠️ Constraints

* `1 <= s.length <= 100`[cite: 1]
* `s[i]` is `'('`, `')'` or `'*'`[cite: 1].

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "()"` | `true` | The string represents a perfectly balanced set of parentheses[cite: 1]. |
| **2** | `s = "(*)"` | `true` | The `'*'` can be treated as an empty string `""` to leave a balanced `"()"`[cite: 1]. |
| **3** | `s = "(*))"` | `true` | The `'*'` can be treated as a left parenthesis `'('` to form `"(()))"`, which is balanced[cite: 1]. |
| **4** | `s = "("` | `false` | An unclosed left parenthesis remains, making it invalid[cite: 1]. |

---

## 🎯 Approach

The presence of the `'*'` character introduces multiple branching possibilities since it can represent three different states. We can solve this using several strategies[cite: 1]:

1.  **Recursion + Memoization (Dynamic Programming):** 
    Whenever we encounter a `'*'`, we have three options: treat it as `'('`, `')'`, or empty `""`[cite: 1]. We can explore all three paths recursively. To avoid recomputing overlapping subproblems, we track the current index and the count of open brackets, caching the result in a 2D memoization table[cite: 1].
2.  **Bottom-Up DP (Tabulation):**
    We can convert the memoized recursive approach into an iterative 2D DP table. The table tracks whether a valid string can be formed from a specific index to the end, given a specific number of open brackets[cite: 1].
3.  **Two Stacks (Iterative):**
    We use two separate stacks to store the indices of open brackets `openSt` and asterisks `asterisksSt`[cite: 1]. When we encounter a closing bracket, we prioritize popping from the open bracket stack. If it's empty, we pop from the asterisk stack[cite: 1]. At the end, we match any remaining open brackets with asterisks that appear *after* them (index comparison)[cite: 1].
4.  **Greedy (Constant Space - Optimal):**
    We can make two passes through the string[cite: 1]. First, a left-to-right pass treating all asterisks as open brackets to catch any excess closing brackets[cite: 1]. Second, a right-to-left pass treating all asterisks as closing brackets to catch any excess open brackets[cite: 1]. If the bracket count drops below zero in either pass, the string is invalid[cite: 1].

## 💻 Solution Code

### Approach 1: Recursion + Memoization (Dynamic Programming)

```cpp
// Intuition: Because '*' provides 3 distinct options ('(', ')', or ""), we can use recursion to test all possibilities. Since states overlap (same index and open bracket count), we use a DP table to memoize and prevent redundant calculations.
// Approach: Start at index 0 with 0 open brackets. If we see '(', increment open. If ')', decrement open. If '*', recursively branch into three paths (increment, decrement, or leave open unchanged). If we reach the end of the string, it is valid only if open == 0.
// Time Complexity: O(n^2) where n is the length of the string. There are n indices and the open bracket count can go up to n, making n*n possible states.
// Space Complexity: O(n^2) for the 2D memoization table plus O(n) for the recursive call stack depth.
class Solution {
public:
    
    int t[101][101]; // DP table to memoize states [idx][open_count]
    
    bool solve(int idx, int open, string& s, int n) {
        // Base case: Reached the end of the string
        if(idx == n) {
            return open == 0; // Valid if no unclosed open brackets remain
        }
        
        // Return previously computed result if it exists
        if(t[idx][open] != -1) {
            return t[idx][open] == 1 ? true : false;
        }
        
        bool isValid = false;
        
        // Explore all 3 possibilities if character is an asterisk
        if(s[idx] == '*') {
            if(open > 0)
                isValid |= solve(idx+1, open-1, s, n); // Treating '*' as ')'
            
            isValid |= solve(idx+1, open+1, s, n);     // Treating '*' as '('
            
            isValid |= solve(idx+1, open, s, n);       // Treating '*' as "" (empty string)
            
        } else if(s[idx] == '(') {
            // Must act as an open bracket
            isValid |= solve(idx+1, open+1, s, n);
        } else if(open > 0) {
            // Must act as a closing bracket, valid only if open brackets exist
            isValid |= solve(idx+1, open-1, s, n);
        }
        
        // Cache and return the result
        return t[idx][open] = isValid;
    }
    
    bool checkValidString(string s) {
        int n = s.length();
        // Initialize DP table with -1 (uncomputed)
        memset(t, -1, sizeof(t));
        return solve(0, 0, s, n);
        
    }
};

/*
*
* Dry Run
* Input: s = "(*)"
* 1. solve(0, 0): s[0] == '('. Calls solve(1, 1).
* 2. solve(1, 1): s[1] == '*'. Explores 3 paths:
*    - Path A ('*'=')'): Calls solve(2, 0).
*    - Path B ('*'='('): Calls solve(2, 2).
*    - Path C ('*'=""): Calls solve(2, 1).
* 3. Path A -> solve(2, 0): s[2] == ')'. Open=0, cannot place ')'. Returns false.
* 4. Path B -> solve(2, 2): s[2] == ')'. Calls solve(3, 1). Returns false (open != 0 at end).
* 5. Path C -> solve(2, 1): s[2] == ')'. Calls solve(3, 0). Returns true (idx=3, open=0).
* 6. Since Path C is true, isValid becomes true. Returns true overall.
*
*/
```

### Approach 2: Bottom-Up DP (Tabulation)

C++
```cpp
// Intuition: The recursive memoization can be converted to a bottom-up DP approach to avoid recursion stack overhead. We build the solution from the end of the string backward to the beginning.
// Approach: Create a 2D boolean DP table `t[n+1][n+1]`. `t[i][j]` signifies if the substring from index i to n-1 is valid given j open brackets. We initialize `t[n][0]` as true. We iterate backwards from n-1 down to 0, updating states based on current character and open count.
// Time Complexity: O(n^2) where n is the length of the string, due to nested loops filling the 2D DP array.
// Space Complexity: O(n^2) for storing the 2D boolean table of size (n+1)x(n+1).
class Solution {
public: 
    bool checkValidString(string s) {
        int n = s.size();
        // 2D DP array initialized to false
        vector<vector<bool>> t(n + 1, vector<bool>(n + 1, false));
        
        // State Definition :
        // t[i][j] = if the string from index i to n-1 is valid or not having j open brackets
        // Base case: an empty string with 0 unclosed brackets is valid
        t[n][0] = true;

        // Traverse backwards from the end of the string
        for (int i = n - 1; i >= 0; i--) {
            // Open count can be anywhere from 0 to n
            for (int open = 0; open <= n; open++) {
                bool isValid = false;

                if (s[i] == '*') {
                    // Try treating '*' as '(' (requires open+1 to be valid later)
                    if (open + 1 <= n) isValid |= t[i + 1][open + 1]; 
                    
                    // Try treating '*' as ')'
                    if (open > 0) {
                        isValid |= t[i + 1][open - 1]; 
                    }
                    
                    // Try treating '*' as empty
                    isValid |= t[i + 1][open]; 
                } else {
                    if (s[i] == '(') {
                        // Standard open bracket
                        if (open + 1 <= n) isValid |= t[i + 1][open + 1]; 
                    } else if (open > 0) {
                        // Standard closing bracket
                        isValid |= t[i + 1][open - 1]; 
                    }
                }
                // Store result for current state
                t[i][open] = isValid;
            }
        }

        // Answer is whether the entire string (index 0) is valid with 0 initial open brackets
        return t[0][0];
    }
};

/*
*
* Dry Run
* Input: s = "()"
* n = 2. t[2][0] = true (Base case).
* Loop i = 1 (s[1] = ')'): 
*    open = 1: s[1] == ')' -> checks t[2][0] (true). t[1][1] = true.
* Loop i = 0 (s[0] = '('):
*    open = 0: s[0] == '(' -> checks t[1][1] (true). t[0][0] = true.
* Returns t[0][0] which is true.
*
*/
```

### Approach 3: Two Stacks



C++
```cpp
// Intuition: We can match brackets eagerly using a stack. However, since '*' is a wildcard, we need a separate stack to track asterisks' positions. The index of the asterisk matters because it can only act as a closing bracket for an open bracket that appeared before it.
// Approach: Traverse string left to right. Push indices of '(' to openSt and indices of '*' to asterisksSt. When encountering ')', pop from openSt first; if empty, pop from asterisksSt; if both empty, string is invalid. Finally, match any leftover '(' in openSt with '*' in asterisksSt, ensuring the '(' index is less than the '*' index.
// Time Complexity: O(n) because we iterate through the string once and process leftover elements in the stacks at most once.
// Space Complexity: O(n) in the worst case if the string consists entirely of '(' or '*' characters, requiring us to store all their indices in stacks.
class Solution {
public: 
    bool checkValidString(string s) {
        stack<int> openSt;      // Stack to track indices of '('
        stack<int> asterisksSt; // Stack to track indices of '*'

        // Pass 1: Match all closing brackets eagerly
        for (int i = 0; i < s.length(); i++) {
            char ch = s[i];

            if (ch == '(') {
                openSt.push(i);
            } else if (ch == '*') {
                asterisksSt.push(i);
            } else { // Current char is ')'
                if (!openSt.empty()) {
                    openSt.pop(); // Prioritize matching with a real '('
                } else if (!asterisksSt.empty()) {
                    asterisksSt.pop(); // Fallback to matching with an '*'
                } else {
                    return false; // No '(' or '*' available to match ')'
                }
            }
        }

        // Post-processing: Match remaining open brackets with remaining asterisks
        // Required for cases like - "*(())(*"
        while (!openSt.empty() && !asterisksSt.empty()) {
            // An asterisk can only close an open bracket if it appears AFTER the open bracket
            if (openSt.top() > asterisksSt.top()) {
                return false; 
            }
            openSt.pop();
            asterisksSt.pop();
        }

        // If all open brackets are successfully matched, the string is valid
        return openSt.empty();
    }
};

/*
*
* Dry Run
* Input: s = "(*))"
* 1. i=0, '(': openSt = [0]
* 2. i=1, '*': asterisksSt = [1]
* 3. i=2, ')': openSt is not empty -> pop openSt. openSt = [], asterisksSt = [1]
* 4. i=3, ')': openSt is empty, but asterisksSt is not -> pop asterisksSt. asterisksSt = []
* Loop ends. openSt is empty, so returns true.
*
*/
```

### Approach 4: Greedy (Constant Space - Optimal)

C++
```cpp
// Intuition: A string is invalid if, at any point, there are more closing brackets than available open brackets + wildcards, or vice versa. By verifying left-to-right (checking for excess closing brackets) and right-to-left (checking for excess open brackets), we can ensure complete validity.
// Approach: Iterate left-to-right, treating '*' as '('. If open drops below 0, return false (too many ')'). Iterate right-to-left, treating '*' as ')'. If close drops below 0, return false (too many '('). If both passes survive, the string is perfectly valid.
// Time Complexity: O(n) as we traverse the string exactly two times (left-to-right, then right-to-left).
// Space Complexity: O(1) since we only use two integer variables (`open` and `close`) for counting, requiring constant extra space.
// NOTE: Both loops can be combined into a single loop using `n - i - 1` for the reverse index, but they are kept separate here for conceptual clarity.
class Solution {
public:
    bool checkValidString(string s) {
        int open = 0;
        int close = 0;
        int n = s.length();
        
        // Pass 1: Left to Right - Validate against excess closing brackets
        for (int i = 0; i < n; i++) {
            
            // Treat both '(' and '*' as potential open brackets
            if (s[i] == '(' || s[i] == '*') {
                open++;
            } else { // It's a ')'
                open--;
            }
                
            // Too many ')' encountered without enough matching '(' or '*'
            if (open < 0) {
                return false;
            }
        }

        // Pass 2: Right to Left - Validate against excess open brackets
        for (int i = n - 1; i >= 0; i--) {
            
            // Treat both ')' and '*' as potential closing brackets
            if (s[i] == ')' || s[i] == '*') {
                close++;
            } else { // It's a '('
                close--;
            }
            
            // Too many '(' encountered without enough matching ')' or '*'
            if (close < 0) {
                return false;
            }
        }
        
        // Surviving both directional checks guarantees validity
        return true;
    }
};

/*
*
* Dry Run
* Input: s = "(*))"
* Left-to-Right pass:
* 1. i=0, '(': open=1
* 2. i=1, '*': open=2
* 3. i=2, ')': open=1
* 4. i=3, ')': open=0. Never drops below 0.
* Right-to-Left pass:
* 1. i=3, ')': close=1
* 2. i=2, ')': close=2
* 3. i=1, '*': close=3
* 4. i=0, '(': close=2. Never drops below 0.
* Both passes succeed -> returns true.
*
*/
```

## 📝 Notes & Key Insights
- The DP intuition: The problem transforms standard parenthesis checking into DP simply because of the branching choices introduced by the '*' wildcard[cite: 1].
- Index matters for Wildcards: In the stack approach, pushing characters isn't enough; storing the indices is crucial[cite: 1]. A '*' can only act as a closing parenthesis ')' if it physically appears in the string after the left parenthesis '(' it is attempting to close[cite: 1].
- The dual-pass Greedy brilliance: The constant space greedy approach operates on a beautiful logical principle: if your string can survive a left-to-right pass without ever being overwhelmed by closing brackets, and a right-to-left pass without ever being overwhelmed by open brackets, the wildcards in the middle are guaranteed to be capable of resolving any imbalances[cite: 1].

## 🔍 Further Exploration
- If the constraints were bumped up (e.g., $10^5$), the $O(N^2)$ DP approaches would Result in a Time Limit Exceeded (TLE) error. Knowing the Two Stacks $O(N)$ or the Dual-Pass Greedy $O(N)$ approaches is vital for larger scale inputs.
- The greedy approach can technically be condensed into a single O(N) loop by maintaining the absolute minimum and maximum possible number of open brackets simultaneously as you traverse from left to right.
