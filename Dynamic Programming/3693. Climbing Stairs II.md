## 📝 Problem Statement

You are climbing a staircase with $n + 1$ steps, numbered from $0$ to $n$.

You are also given a 1-indexed integer array `costs` of length $n$, where `costs[i]` is the cost of step $i$.

From step $i$, you can jump only to step $i + 1$, $i + 2$, or $i + 3$. The cost of jumping from step $i$ to step $j$ is defined as:

$$\text{cost} = \text{costs}[j] + (j - i)^2$$

You start from step $0$ with $\text{cost} = 0$.

Return the **minimum total cost** to reach step $n$.

---

## ⚙️ Constraints

- $1 \le n == \text{costs.length} \le 10^5$
- $1 \le \text{costs}[i] \le 10^4$

## 💡 Approach & Explanation

From any current step $i$, we have up to **3 choices** for our next step $j$:
1. Jump to $i + 1$ (if $i + 1 \le n$)
2. Jump to $i + 2$ (if $i + 2 \le n$)
3. Jump to $i + 3$ (if $i + 3 \le n$)

For each valid step $j$, the incremental cost is $\text{costs}[j - 1] + (j - i)^2$ (noting that the input `costs` array is 0-indexed in code).

### 1. Top-Down Recursion with Memoization
We define `solve(i)` as the minimum cost to reach step $n$ starting from step $i$.
- **Base Case:** If $i == n$, return `0` as we have already reached the target.
- **Recursive Relation:** For $j \in \{i+1, i+2, i+3\}$ such that $j \le n$:
  $$\text{cost}(i) = \min_{j} \left( \text{solve}(j) + \text{costs}[j - 1] + (j - i)^2 \right)$$
- To prevent exponential computation due to overlapping subproblems, we memoize state results in a 1D vector `memo` of size $n + 1$.

### 2. Bottom-Up Dynamic Programming
Notice that to compute `dp[i]`, we need future values `dp[j]` where $j > i$.
- We define `dp[i]` as the minimum cost to reach step $n$ from step $i$.
- Set `dp[n] = 0` (Base Case).
- Traverse backwards from $i = n - 1$ down to $0$.
- For each $i$, check jump options $j = i+1, i+2, i+3$ and compute the minimum total cost using previously computed `dp[j]` values.
- Finally, `dp[0]` holds the optimal answer.

## 💻 Solution Code

### Approach 1: Top-Down Recursion + Memoization

```cpp
// Intuition:
// From any step i, we can jump to step i+1, i+2, or i+3. We explore all valid jumps recursively and use memoization to store minimum cost from each step to avoid redundant subproblem calculations.

// Approach:
// 1. Define solve(i): minimum cost to reach step n starting from step i.
// 2. Base Case: If i == n, return 0 as no further cost is required.
// 3. Return memo[i] if already computed.
// 4. Try all valid jumps of length 1, 2, and 3 (j = i+1, i+2, i+3 where j <= n).
// 5. For each valid jump, calculate cost = solve(j) + costs[j-1] + (j-i)^2 and keep track of minimum.
// 6. Memoize and return the result.

// Time Complexity: O(n) - Each state from 0 to n is computed once with at most 3 transitions.
// Space Complexity: O(n) - O(n) call stack depth plus memoization vector of size n+1.

class Solution {
public:
    vector<int> memo;

    int solve(int i, int n, vector<int>& costs) {
        if (i == n)
            return 0; // Base case: reached destination step n
        if (memo[i] != -1)
            return memo[i]; // Return memoized result if already calculated

        int cost = INT_MAX; // Track minimum cost among valid jumps

        int j = i + 1; 
        if(j <= n)                                 // jump of 1
            cost = solve(j, n, costs) + costs[j - 1] + (j - i) * (j - i);

        j = i + 2;                                      // jump of 2
        if (j <= n)
            cost = min(cost, solve(j, n, costs) + costs[j - 1] + (j - i) * (j - i));

        j = i + 3;                                      // jump of 3
        if (j <= n)
            cost = min(cost, solve(j, n, costs) + costs[j - 1] + (j - i) * (j - i));

        return memo[i] = cost; // Store and return min cost for step i
    }

    int climbStairs(int n, vector<int>& costs) {
        memo.assign(n + 1, -1); // Initialize memo table with -1
        return solve(0, n, costs); // Start recursion from step 0
    }
};

/*
*
* Dry Run
*
* Input: n = 4, costs = [1, 2, 3, 4]
* Start solve(0):
*  - solve(4) = 0
*  - solve(3): j=4 -> solve(4) + costs[3] + 1^2 = 0 + 4 + 1 = 5
*  - solve(2):
*    j=3 -> solve(3) + costs[2] + 1^2 = 5 + 3 + 1 = 9
*    j=4 -> solve(4) + costs[3] + 2^2 = 0 + 4 + 4 = 8 -> min(9, 8) = 8
*  - solve(1):
*    j=2 -> solve(2) + costs[1] + 1^2 = 8 + 2 + 1 = 11
*    j=3 -> solve(3) + costs[2] + 2^2 = 5 + 3 + 4 = 12
*    j=4 -> solve(4) + costs[3] + 3^2 = 0 + 4 + 9 = 13 -> min(11, 12, 13) = 11
*  - solve(0):
*    j=1 -> solve(1) + costs[0] + 1^2 = 11 + 1 + 1 = 13
*    j=2 -> solve(2) + costs[1] + 2^2 = 8 + 2 + 4 = 14
*    j=3 -> solve(3) + costs[2] + 3^2 = 5 + 3 + 9 = 17 -> min(13, 14, 17) = 13
* Result: 13
*
*/
```

### Approach 2: Bottom-Up Dynamic Programming (Optimized)

```cpp
// Intuition:
// Since dp[i] depends on future steps dp[i+1], dp[i+2], and dp[i+3], we iterate backward from n-1 down to 0, filling the DP table iteratively without recursion overhead.

// Approach:
// 1. Create a 1D DP table of size n+1 initialized to 0, with base case dp[n] = 0.
// 2. Loop i from n-1 down to 0.
// 3. Evaluate next valid steps j = i+1, i+2, and i+3.
// 4. Calculate total cost for each valid jump: dp[j] + costs[j-1] + (j-i)^2.
// 5. Store the minimum cost in dp[i].
// 6. Return dp[0] as the overall minimum cost to reach step n from step 0.

// Time Complexity: O(n) - Single loop of size n with O(1) transitions per step.
// Space Complexity: O(n) - 1D array of size n+1 to store computed optimal costs.

class Solution {
public:
    int climbStairs(int n, vector<int>& costs) {
        vector<int> dp(n + 1, 0); // DP table where dp[i] is min cost from step i to n

        for (int i = n-1; i >= 0; i--) { // Reverse iteration from n-1 down to 0
            
            int cost = INT_MAX; // Track minimum cost from step i

            int j = i + 1; 
            if(j <= n)                           // jump of 1
                cost = dp[j] + costs[j - 1] + (j - i) * (j - i);

            j = i + 2;                                  // jump of 2
            if (j <= n)
                cost = min(cost, dp[j] + costs[j - 1] + (j - i) * (j - i));

            j = i + 3;                                  // jump of 3
            if (j <= n)
                cost = min(cost, dp[j] + costs[j - 1] + (j - i) * (j - i));

            dp[i] = cost; // Store optimal answer for step i
        }

        return dp[0]; // Optimal answer starting from step 0
    }
};

/*
*
* Dry Run
*
* Input: n = 4, costs = [1, 2, 3, 4]
* dp array size 5 initialized to [0, 0, 0, 0, 0]
* dp[4] = 0
* i = 3: j = 4 -> cost = dp[4] + costs[3] + 1^2 = 0 + 4 + 1 = 5 -> dp[3] = 5
* i = 2: 
*   j = 3 -> cost = dp[3] + costs[2] + 1^2 = 5 + 3 + 1 = 9
*   j = 4 -> cost = min(9, dp[4] + costs[3] + 2^2) = min(9, 0 + 4 + 4) = 8 -> dp[2] = 8
* i = 1: 
*   j = 2 -> cost = dp[2] + costs[1] + 1^2 = 8 + 2 + 1 = 11
*   j = 3 -> cost = min(11, dp[3] + costs[2] + 2^2) = min(11, 5 + 3 + 4) = 12
*   j = 4 -> cost = min(11, dp[4] + costs[3] + 3^2) = min(11, 0 + 4 + 9) = 13 -> dp[1] = 11
* i = 0: 
*   j = 1 -> cost = dp[1] + costs[0] + 1^2 = 11 + 1 + 1 = 13
*   j = 2 -> cost = min(13, dp[2] + costs[1] + 2^2) = min(13, 8 + 2 + 4) = 14
*   j = 3 -> cost = min(13, dp[3] + costs[2] + 3^2) = min(13, 5 + 3 + 9) = 17 -> dp[0] = 13
* Returns dp[0] = 13
*
*/
```

## 📌 Notes & Complexity Summary

- **Time Complexity:** $\mathcal{O}(n)$
  - Each step from $0$ to $n-1$ considers at most 3 choices ($j = i+1, i+2, i+3$), resulting in $\mathcal{O}(3n) = \mathcal{O}(n)$ operations.
- **Space Complexity:** $\mathcal{O}(n)$
  - Both top-down memoization and bottom-up DP require a 1D array of size $n+1$.
- **Space Optimization Note:** Because `dp[i]` only depends on `dp[i+1]`, `dp[i+2]`, and `dp[i+3]`, we could optimize space further to $\mathcal{O}(1)$ by maintaining 3 rolling variables.

---

## Key Insights

1. **Quadratic Jump Cost:** The cost calculation incorporates $(j - i)^2$. Even though a larger jump skips intermediate step costs, the quadratic jump penalty grows quickly ($1, 4, 9$).
2. **Fixed Transition Window:** Since jump size is strictly constrained to $\{1, 2, 3\}$, state transitions are constant time $\mathcal{O}(1)$, yielding linear overall complexity.
3. **1D Subproblem Dependence:** Subproblem $i$ depends exclusively on future states $i+1, i+2, i+3$, making reverse linear iteration optimal for bottom-up execution.
