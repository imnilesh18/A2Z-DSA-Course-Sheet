## 📝 Problem Statement

You are given a **0-indexed** binary string `s` having an **even** length[cite: 1].

A string is **beautiful** if it is possible to partition it into one or more contiguous substrings such that[cite: 1]:
1. Each substring has an **even** length[cite: 1].
2. Each substring contains **only** `'1'`s or **only** `'0'`s[cite: 1].

You can change any character in `s` to `'0'` or `'1'`[cite: 1].

Return the **minimum** number of changes required to make the string `s` beautiful[cite: 1].

---

## 🔒 Constraints

- $2 \le \text{s.length} \le 10^5$[cite: 1]
- `s` has an **even** length[cite: 1].
- `s[i]` is either `'0'` or `'1'`[cite: 1].

## 💡 Approach

Although categorized as **Medium**, this problem relies on a clean parity observation that leads from a straightforward streak-tracking method to a minimal two-character pairing strategy[cite: 1].

### 1. Iterative Streak & Parity Tracking (Intuitive Approach)
Because every valid partition must have an **even length** and contain **identical characters**, we can scan `s` from left to right while tracking[cite: 1]:
- `curr`: The character belonging to the current contiguous streak[cite: 1].
- `count`: The length of the current consecutive streak[cite: 1].
- `changes`: The total number of flips performed[cite: 1].

When examining each character `s[i]`[cite: 1]:
- **If `s[i] == curr`**: The homogeneous streak continues uninterrupted, so we simply increment `count`[cite: 1].
- **If `s[i] != curr`**: The streak is broken, and we inspect the parity of `count`[cite: 1]:
  - **Even Streak (`count % 2 == 0`)**: The preceding segment already satisfies both rules (even length and uniform characters)[cite: 1]. We can safely close that partition right before index `i` without any flip and begin a fresh streak at `s[i]` with `count = 1`[cite: 1].
  - **Odd Streak (`count % 2 != 0`)**: The preceding segment has an odd length and cannot stand alone as a valid partition[cite: 1]. We are forced to flip `s[i]` to match `curr` so that the segment reaches an even length (`count + 1`)[cite: 1]. We increment `changes`, close the completed partition by resetting `count = 0`, and update `curr = s[i]` for the next position[cite: 1].

Because the total string length `n` is guaranteed to be even and every closed partition removes an even number of characters, any final trailing streak at the end of the loop is automatically guaranteed to have an even length[cite: 1].

---

### 2. Adjacent Pair Checking (Optimized Greedy Observation)
Notice two critical facts from the problem rules[cite: 1]:
1. **No limit on the number of partitions**: We can split the string into as many even-length substrings as we want[cite: 1].
2. **Smallest valid even length is `2`**: Any valid partition of even length $2k$ (such as `"0000"`) can always be decomposed into $k$ partitions of length `2` (`"00 | 00"`) without adding or saving any flips[cite: 1].

Conversely, merging two mismatched pairs never saves changes[cite: 1]:
- Consider `"1001"`:
  - Fixing each pair of length `2` independently gives `"11 | 00"` (**2 flips**)[cite: 1].
  - Merging them into a single length-`4` substring requires converting all characters to `"1111"` or `"0000"` (**2 flips**)[cite: 1].

Thus, the global optimum reduces to ensuring that **every non-overlapping adjacent pair** `(s[0], s[1])`, `(s[2], s[3])`, ..., `(s[n - 2], s[n - 1])` consists of two identical characters[cite: 1]. Whenever `s[i] != s[i + 1]`, exactly `1` flip is needed to make the pair uniform[cite: 1].

## 💻 Solution Code

### Approach 1: Brute Force / Iterative Streak & Parity Tracking (C++)

```cpp
// Intuition: Track consecutive streaks of identical characters; whenever a streak breaks on an odd length, flip the current character to complete an even-length valid partition.
// Approach: Iterate through the string while maintaining the active character (curr), its consecutive frequency (count), and flip counter (changes). If the current character matches curr, increment count. Otherwise, if count is even, start a new streak with count = 1; if count is odd, flip s[i] to balance the streak, increment changes, and reset count = 0. Update curr = s[i] whenever a mismatch occurs.
// Time Complexity: O(n), where n is the length of string s, as we traverse the string in a single linear pass.
// Space Complexity: O(1), as only a fixed number of scalar variables are used regardless of input size.
class Solution {
public:
    int minChanges(string s) {
        char curr = s[0]; // Track active character of current streak

        int count = 0;   // Length of current consecutive character streak
        int changes = 0; // Total character flips required
        int n = s.length();

        // Iterate through each character in the string
        for (int i = 0; i < n; i++) {

            if (s[i] == curr) {
                count++; // Extend current homogeneous streak
                continue;
            }

            if (count % 2 == 0) { //Even
                count = 1; // Previous partition is valid; start new streak
            } else { //Odd
                count = 0; // Flip s[i] to complete even partition and reset
                changes++;
            }
            
            curr = s[i]; // Update active character to current position
        }

        return changes;
    }
};

/*
*
* Dry Run
*
Input: s = "1001"
n = 4, curr = '1', count = 0, changes = 0

i = 0: s[0] = '1' == curr ('1') -> count becomes 1
i = 1: s[1] = '0' != curr ('1') -> count (1) is odd -> count = 0, changes = 1, curr = '0'
i = 2: s[2] = '0' == curr ('0') -> count becomes 1
i = 3: s[3] = '1' != curr ('0') -> count (1) is odd -> count = 0, changes = 2, curr = '1'

Loop ends -> return changes = 2
*
*/
```

### Approach 2: Optimized Adjacent Pair Checking (C++)

```cpp
// Intuition: Since there is no limit on the number of partitions and every substring must have an even length, partitioning the string into minimal blocks of size 2 is always optimal.
// Approach: Traverse the string in steps of 2 (i = 0, 2, 4, ..., n - 2) to inspect every non-overlapping adjacent pair. Whenever s[i] and s[i + 1] differ, increment the changes counter by 1 so both characters match.
// Time Complexity: O(n), where n is the length of string s, iterating through n / 2 pairs in a single pass.
// Space Complexity: O(1), using only constant auxiliary space.
class Solution {
public:
    int minChanges(string s) {
        int changes = 0; // Track minimum flips needed across pairs
        int n = s.length();

        // Check every non-overlapping adjacent pair of length 2
        for (int i = 0; i < n; i += 2) {

            if (s[i] != s[i + 1]) {
                changes++; // Flip one character so the pair matches
            }
        }

        return changes;
    }
};

/*
*
* Dry Run
*
Input: s = "100010000111"
n = 12, changes = 0

i = 0: pair "10" -> s[0] != s[1] -> changes = 1
i = 2: pair "00" -> s[2] == s[3] -> changes = 1
i = 4: pair "10" -> s[4] != s[5] -> changes = 2
i = 6: pair "00" -> s[6] == s[7] -> changes = 2
i = 8: pair "01" -> s[8] != s[9] -> changes = 3
i = 10: pair "11" -> s[10] == s[11] -> changes = 3

Loop ends -> return changes = 3
*
*/
```

## 📌 Notes

- **Safe Indexing (`i + 1`)**: Because the problem guarantees that `s.length` is always **even**, accessing `s[i + 1]` when iterating with `i += 2` (`i < n`) will never go out of bounds[cite: 1].
- **Choice of Flip Direction**: When `s[i] != s[i + 1]`, flipping `s[i]` to match `s[i + 1]` or flipping `s[i + 1]` to match `s[i]` yields the exact same result because adjacent pairs of length `2` are completely independent of neighboring pairs[cite: 1].

---

## 🔑 Key Insights

- **Decomposability of Even Partitions**: Every even-length uniform substring of length $2k$ can be split into $k$ uniform substrings of length $2$[cite: 1]. Therefore, minimizing flips for arbitrary even-length partitions is mathematically equivalent to minimizing flips for length-$2$ partitions[cite: 1].
- **Local Decisions Achieve Global Optimality**: Because length-$2$ blocks do not overlap and no bonus is gained by creating longer blocks, greedy local pair matching guarantees the global minimum number of changes[cite: 1].
- **Equivalence of Both Approaches**: Approach 1 dynamically builds variable-length even partitions (`2`, `4`, `6`, ...), while Approach 2 fixes the partition size at `2`—both produce the exact same minimum flip count in $O(n)$ time and $O(1)$ space[cite: 1].
