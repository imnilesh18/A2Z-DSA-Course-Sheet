# 1190. Reverse Substrings Between Each Pair of Parentheses

**Difficulty:** `Medium`  
**Tags:** `String` `Stack` `Bracket Sequences`  
**Problem Link:** [1190. Reverse Substrings Between Each Pair of Parentheses](https://leetcode.com/problems/reverse-substrings-between-each-pair-of-parentheses/description)

---

## 📝 Problem Statement

You are given a string `s` that consists of lower case English letters and brackets[cite: 1]. 

Reverse the strings in each pair of matching parentheses, starting from the innermost one[cite: 1]. 

Your result should not contain any brackets[cite: 1].

---

## ⛔ Constraints

- `1 <= s.length <= 2000`[cite: 1]
- `s` only contains lower case English characters and parentheses[cite: 1].
- It is guaranteed that all parentheses are balanced[cite: 1].

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "(abcd)"` | `"dcba"` | Reversing the entire string inside the single pair of parentheses[cite: 1]. |
| **2** | `s = "(u(love)i)"` | `"iloveu"` | The substring "love" is reversed first, then the whole string is reversed[cite: 1]. |
| **3** | `s = "(ed(et(oc))el)"` | `"leetcode"` | First, we reverse the substring "oc", then "etco", and finally, the whole string[cite: 1]. |

---

## 🧠 Approach

We can solve this problem using two primary methods, evolving from a simple simulation to an optimized linear approach[cite: 1].

### 1. Brute Force (Stack + In-Place Reversal)
The most intuitive thought process is to build our result string character by character while keeping track of where our parentheses opened[cite: 1]. 
- We can skip the open brackets `(` but store the current length of our `result` string in a stack[cite: 1]. This length tells us exactly how many characters to skip when we eventually need to reverse[cite: 1].
- We blindly add normal characters to our `result` string[cite: 1]. 
- When we encounter a closing bracket `)`, we pop the length from our stack and reverse the substring in our `result` from that specific length up to the current end of the string[cite: 1]. 
- Since we process the string from left to right, the inner-most brackets are naturally resolved first (LIFO order), fulfilling the problem's requirements perfectly[cite: 1].

### 2. Optimized "Wormhole" Traversal (Linear Approach)
Reversing the string repeatedly can lead to an $O(n^2)$ time complexity. We can optimize this by realizing that a pair of parentheses essentially acts as a portal that reverses our reading direction[cite: 1].
- In the first pass, we use a stack to find all matching pairs of parentheses and store their indices in a bidirectional map (or array) which we can call `door`[cite: 1].
- In the second pass, we iterate through the string. Whenever we hit an open or closed parenthesis, we teleport our index to its matching pair using our `door` array, and we immediately flip our traversal direction[cite: 1].
- If we hit a normal character, we simply print/append it[cite: 1]. This elegant observation completely bypasses the need to physically reverse strings, dropping our time complexity to $O(n)$[cite: 1].

## 💻 Solution Code (Brute Force & Optimized)

### Brute-force Solution (C++)

```cpp
// Intuition: We can simulate the process by building the result string character by character. When we encounter a closing bracket, we need to reverse the characters that were inside the matching parentheses.
// Approach: 
// 1. Iterate through the string and append characters to a 'result' string.
// 2. When seeing '(', push the current length of 'result' onto a stack. This marks the start index for a future reversal.
// 3. When seeing ')', pop the start index from the stack and reverse the substring in 'result' from that index to the end.
// Time Complexity: O(n^2) - In the worst case, reversing the string repeatedly takes O(n) for each of the O(n) brackets.
// Space Complexity: O(n) - We use a stack to store indices, and a string to store the result, both taking up to O(n) space.
class Solution {
public:
    string reverseParentheses(string s) {
        stack<int> openeBracket; // Tracks the start index of substrings to reverse
        string result;
        for (char currentChar : s) {
            if (currentChar == '(') {
                openeBracket.push(result.length()); // Store current length before entering parenthesis
            } else if (currentChar == ')') {
                int start = openeBracket.top();
                openeBracket.pop(); // Get the start index for the innermost unreversed substring
                reverse(result.begin() + start, result.end()); // Reverse the target substring
            } else {
                result += currentChar; // Append regular characters
            }
        }
        return result;
    }
};

/*
*
* Dry Run
* Input: s = "(u(love)i)"
* 1. '(': stack = [0], result = ""
* 2. 'u': stack = [0], result = "u"
* 3. '(': stack = [0, 1], result = "u"
* 4. 'l','o','v','e': result = "ulove"
* 5. ')': pop 1, reverse from index 1 -> "u" + reverse("love") -> "uevol"
* 6. 'i': result = "uevoli"
* 7. ')': pop 0, reverse from index 0 -> reverse("uevoli") -> "iloveu"
* Output: "iloveu"
*
*/
```

### Optimized Solution (C++)

```cpp
// Intuition: Reversing substrings multiple times is inefficient. We can achieve O(n) time by precomputing the pairs of parentheses and "teleporting" between them, reversing our traversal direction instead of physically reversing the string.
// Approach:
// 1. First pass: Use a stack to pair each '(' with its matching ')' and store the jump mappings in a 'door' array.
// 2. Second pass: Traverse the string using an index 'i' and a 'direction' step (initially +1).
// 3. If we hit a bracket, jump to its pair index using 'door[i]' and reverse the 'direction' (multiply by -1).
// 4. If we hit a normal character, append it to the result.
// Time Complexity: O(n) - We do exactly two linear passes over the string.
// Space Complexity: O(n) - We use a stack for pairing, an array 'door' for mappings, and a string for the result.
class Solution {
public:
    string reverseParentheses(string s) {
        int n = s.length();
        stack<int> openBracket;
        vector<int> door(n);

        // First pass: Pair up parentheses
        for (int i = 0; i < n; i++) {
            if (s[i] == '(') {
                openBracket.push(i); // Record open bracket index
            } else if (s[i] == ')') {
                int j = openBracket.top();
                openBracket.pop();
                door[i] = j; // Map close to open
                door[j] = i; // Map open to close
            }
        }

        // Second pass: Build the result string
        string result;
        int direction = 1; // Left to Right initially
        for (int i = 0; i < n; i += direction) {
            if (s[i] == '(' || s[i] == ')') {
                i = door[i]; // Teleport to the matching parenthesis
                direction = -direction; // Reverse traversal direction
            } else {
                result += s[i]; // Append regular characters
            }
        }
        return result;
    }
};

/*
*
* Dry Run
* Input: s = "(abcd)"
* Pass 1: door maps index 0 <-> index 5
* Pass 2:
* i=0: s[0]='(', jump to door[0]=5. direction = -1.
* i=4: s[4]='d', result = "d"
* i=3: s[3]='c', result = "dc"
* i=2: s[2]='b', result = "dcb"
* i=1: s[1]='a', result = "dcba"
* i=0: s[0]='(', jump to door[0]=5. direction = 1.
* i=6: loop terminates (i < n is false).
* Output: "dcba"
*
*/
```

## 📝 Notes
- In the brute force approach, using a stack to keep track of string lengths rather than raw string slices prevents complicated index tracking[cite: 1].
- Interestingly, although the problem states we must process brackets from the "innermost" outwards, the physical operation of reversing strings makes the order of evaluation flexible[cite: 1]. If you were to evaluate outer brackets first, the double-reversals naturally cancel out, leading to the exact same result[cite: 1].

---

## 🔑 Key Insights
- **The "Wormhole" Technique:** The linear solution visualizes parentheses as connected wormholes. When you enter an open parenthesis traveling right, you teleport to its closing parenthesis and exit traveling left. When you hit a closed parenthesis traveling left, you teleport to its open parenthesis and exit traveling right. This mirrors the mathematical reality of recursive reversals perfectly.
