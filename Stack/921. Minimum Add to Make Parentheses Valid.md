# 921. Minimum Add to Make Parentheses Valid

**Problem Link:** [https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/](https://leetcode.com/problems/minimum-add-to-make-parentheses-valid/)   
**Difficulty:** Medium   
**Tags:** String, Stack, Greedy   

---

## 📝 Problem Statement

A parentheses string is valid if and only if:
- It is the empty string, 
- It can be written as AB (A concatenated with B), where A and B are valid strings, or 
- It can be written as (A), where A is a valid string. 

You are given a parentheses string `s`. In one move, you can insert a parenthesis at any position of the string. 

Return the minimum number of moves required to make `s` valid. 

---

## 🚫 Constraints

- `1 <= s.length <= 1000` 
- `s[i]` is either `'('` or `')'`. 

---

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **Example 1** | `s = "())"`  | `1`  | We need one opening parenthesis at the beginning. |
| **Example 2** | `s = "((("`  | `3`  | We need three closing parentheses at the end. |

---

## 🧠 Approach

When dealing with parenthesis matching problems, using a **Stack** is naturally the first intuitive approach to consider.  

**Step-by-step logic:**
1. We can traverse the given string character by character. If we encounter an opening bracket `(`, we push it to the stack, expecting a future closing bracket. 
2. If we encounter a closing bracket `)`, we check the stack. If there is a matching opening bracket inside, we simply pop it out because they successfully balance each other. 
3. However, if the stack is empty when we see a `)`, it means this closing bracket is currently unmatched. To fix this, we must logically insert a new opening bracket, so we track this by incrementing an `open` counter. 
4. Once we finish traversing the string, any `(` characters left inside the stack are unmatched and will require closing brackets.  
5. The total minimum insertions needed will be the sum of unmatched closing brackets (`open`) and unmatched opening brackets (`stack size`). 

**Optimization:**
While the stack beautifully models the solution, we can notice that we are only ever storing identical `(` characters.  We don't actually need to store them in a data structure; we can simply maintain an integer variable (`size`) to keep a running count of available opening brackets, bringing our space complexity down to $O(1)$. 

---

## 💻 Brute-force Solution (Stack)

```cpp
// Intuition: A stack perfectly models the Last-In-First-Out nature of bracket matching. Unmatched brackets left over directly give us the answer.
// Approach: Iterate through the string. Push '(' to the stack. For ')', pop if a matching '(' exists, else increment the 'open' counter for unmatched ')'. The total moves equal 'open' plus remaining stack size.
// Time Complexity: O(n), where n is the length of the string, as we traverse it exactly once.
// Space Complexity: O(n), in the worst case (all '('), the stack stores n elements.
class Solution {
public:
    int minAddToMakeValid(string s) {
        stack<char> st;
        int open = 0;
        
        for(char &ch : s) {
            if(ch == '(')
                st.push(ch); // Store available open bracket
            else if(!st.empty())
                st.pop();    // Match found, pair them up
            else
                open++;      // Unmatched closing bracket found
        }
        
        return open + st.size(); // Total = unmatched ')' + unmatched '('
    }
};

/*
*
* Dry Run
* Input: s = "())"
* 
* 1. ch = '(', st = ['('], open = 0
* 2. ch = ')', st is not empty -> pop, st = [], open = 0
* 3. ch = ')', st is empty -> open = 1
* 
* Result: open (1) + st.size() (0) = 1
*
*/
```

## 🚀 Optimized Solution (Counter)

```cpp
// Intuition: Since the stack only ever holds '(', we don't need a real stack. We can just keep a numerical count of available '(' brackets to achieve O(1) space.
// Approach: Maintain a 'size' variable for available '(' and an 'open' variable for unmatched ')'. Increment 'size' on '(', decrement on ')' if 'size > 0', else increment 'open'. Return open + size.
// Time Complexity: O(n), where n is the string length, as we iterate through it once.
// Space Complexity: O(1), no extra space used beyond integer variables.
class Solution {
public:
    int minAddToMakeValid(string s) {
        int size = 0; // Simulates the stack size
        int open = 0; // Tracks unmatched closing brackets

        for(char &ch : s) {
            if(ch == '(') {
                size++;      // Equivalent to pushing to stack
            } else if(size > 0) {
                size--;      // Equivalent to popping from stack
            } else {
                open++;      // Found unmatched closing bracket
            }
        }

        return open + size;  // Total moves required
    }
};

/*
*
* Dry Run
* Input: s = "((("
* 
* 1. ch = '(', size = 1, open = 0
* 2. ch = '(', size = 2, open = 0
* 3. ch = '(', size = 3, open = 0
* 
* Result: open (0) + size (3) = 3
*
*/
```

## 📌 Notes
- This problem is an excellent stepping stone for understanding parenthesis parsing before moving on to harder variations.
- State-tracking variables often eliminate the need for auxilliary data structures if the data stored is entirely homogeneous (like identical opening brackets).

## 🔑 Key Insights
- **The Elimination Rule:** A closing bracket `)` instantly cancels out the most recently seen opening bracket `(`.
- **Greedy Validation:** We make a greedy choice to pair off brackets whenever possible. What is left over at the end absolutely *must* be patched via insertions.
