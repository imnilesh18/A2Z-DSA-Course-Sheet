## 📝 Problem Statement

Given a string `s` containing just the characters `'('`, `')'`, `'{'`, `'}'`, `'['` and `']'`, determine if the input string is valid.

An input string is valid if:
1. Open brackets must be closed by the same type of brackets.
2. Open brackets must be closed in the correct order.
3. Every close bracket has a corresponding open bracket of the same type.

## 📊 Examples

| Example | Input | Output | Explanation |
| :---: | :--- | :--- | :--- |
| **1** | `s = "()"` | `true` | The open bracket `(` is properly closed by `)`. |
| **2** | `s = "()[]{}"` | `true` | All types of brackets are correctly opened and closed in order. |
| **3** | `s = "(]"` | `false` | The open bracket `(` is incorrectly closed by `]`. |
| **4** | `s = "([])"` | `true` | The inner brackets are closed before the outer brackets. |
| **5** | `s = "([)]"` | `false` | The brackets are intertwined and not closed in the correct order. |

## 🚫 Constraints

- `1 <= s.length <= 10^4`
- `s` consists of parentheses only `'()[]{}'`.

## 🧠 Approach

<details>
<summary><b>Approach 1: Basic Stack implementation</b></summary>
<br />
The core idea relies on the Last-In-First-Out (LIFO) property of a Stack. As we traverse the string:
<ul>
  <li>If we encounter an open bracket (<code>(</code>, <code>{</code>, <code>[</code>), we push it onto the stack.</li>
  <li>If we encounter a closing bracket (<code>)</code>, <code>}</code>, <code>]</code>), we check if the stack is empty (meaning there's no matching open bracket) or if the top of the stack does not match the corresponding open bracket for our current closing bracket.</li>
  <li>If it's a match, we pop the element from the stack. If it's a mismatch, the string is invalid.</li>
  <li>At the end of the traversal, a completely empty stack indicates a valid, perfectly balanced string.</li>
</ul>
</details>

<details>
<summary><b>Approach 2: Optimized/Tricky Stack</b></summary>
<br />
This is a cleaner, more elegant variation of the stack approach that minimizes conditional logic. Instead of pushing the open bracket onto the stack:
<ul>
  <li>Whenever we encounter an open bracket, we immediately push its <strong>expected closing bracket</strong> onto the stack.</li>
  <li>When we encounter a closing bracket in the string, we simply verify if the stack is empty or if the top of the stack is different from our current closing bracket.</li>
  <li>If they match, we pop the stack. This clever trick bypasses the need to manually map closing brackets to opening brackets during the popping phase, resulting in highly readable code.</li>
</ul>
</details>

## 💻 Solution Code

### 🔹 Brute Force / Basic Approach

```cpp
// Intuition: A Last-In-First-Out (LIFO) order is required to match nested pairs, making a Stack the ideal data structure.
// Approach: Push open brackets onto the stack. When a closing bracket is found, check if it correctly matches the top of the stack. Pop if valid, otherwise return false.
// Time Complexity: O(N) - We traverse the string of length N exactly once.
// Space Complexity: O(N) - In the worst-case scenario (e.g., all open brackets), the stack will store N characters.
class Solution {
public:
    bool isValid(string s) {
        stack<char> st; // Stack to hold open brackets
        
        for(char ch : s) {
            // Push to stack if it's empty or an open bracket
            if(st.empty() || ch == '(' || ch == '{' || ch == '[') {
                st.push(ch);
                continue;
            }
            
            // Verify matching close brackets and pop if valid
            if(ch == ')') {
                if(st.top() == '(')
                    st.pop();
                else
                    return false;
            } else if(ch == '}') {
                if(st.top() == '{')
                    st.pop();
                else
                    return false;
            } else if(ch == ']') {
                if(st.top() == '[')
                    st.pop();
                else
                    return false;
            }
        }
        
        // True if all brackets were perfectly matched
        return st.empty();
    }
};

/*
*
* Dry Run
*
* Input: s = "()[]{}"
* 1. ch = '(' -> push '('. Stack: ['(']
* 2. ch = ')' -> matches st.top() '('. Pop. Stack: []
* 3. ch = '[' -> push '['. Stack: ['[']
* 4. ch = ']' -> matches st.top() '['. Pop. Stack: []
* 5. ch = '{' -> push '{'. Stack: ['{']
* 6. ch = '}' -> matches st.top() '{'. Pop. Stack: []
* 7. Loop ends. st.empty() is true. Return true.
*
*/
```

### 🚀 Optimized / Tricky Approach

```cpp
// Intuition: Pushing the expected closing bracket when encountering an open bracket simplifies matching logic later on.
// Approach: Traverse the string. For every open bracket, push its corresponding close bracket. For any close bracket, check if it matches the top of the stack.
// Time Complexity: O(N) - Single pass through the string.
// Space Complexity: O(N) - In the worst-case scenario, the stack stores N expected closing brackets.
class Solution {
public:
    bool isValid(string s) {
        stack<char> st; // Stack to hold expected closing brackets
        
        for(char ch : s) {
            // Push expected closing bracket for every open bracket
            if (ch == '(')
			    st.push(')');
		    else if (ch == '{')
			    st.push('}');
            else if (ch == '[')
                st.push(']');
            // If it is a closing bracket, verify it matches the expected bracket at the top
            else if (st.empty() || st.top() != ch)
                return false;
            else {
                st.pop(); // Valid match found, pop the stack
            }
        }
        
        // Stack should be empty if all expected brackets were met
        return st.empty();
    }
};

/*
*
* Dry Run
*
* Input: s = "([)]"
* 1. ch = '(' -> push ')'. Stack: [')']
* 2. ch = '[' -> push ']'. Stack: [')', ']']
* 3. ch = ')' -> st.top() is ']', which does NOT equal ')'. Return false.
*
*/
```

## 💡 Key Insights
- **LIFO Pattern:** Problems involving nesting or matching inherently require a Last-In-First-Out mechanism, making Stacks the ultimate tool.
- **Immediate Failsafe:** Checking `st.empty()` before verifying the top of the stack prevents runtime errors (Segmentation Faults) when attempting to access the top of an empty stack.
- **Predictive Matching:** Pushing the *expected* closing bracket instead of the opening bracket (as seen in Approach 2) drastically cuts down conditional boilerplate and improves code hygiene.

## 📝 Notes
- Pay close attention to edge cases like an odd-length string (which can never be valid) or strings containing only closing brackets (e.g., `"]]]]"`).
- In languages like Python or JavaScript, mapping pairs using a HashMap/Dictionary can provide a similarly clean structure to Approach 2.
