# 1614. Maximum Nesting Depth of the Parentheses

---
**Problem Link:** [Maximum Nesting Depth of the Parentheses](https://leetcode.com/problems/maximum-nesting-depth-of-the-parentheses/description)
**Difficulty:** Easy
**Tags:** `String`, `Stack`, `Bracket Sequences`

## 📖 Problem Statement

Given a valid parentheses string `s`, return the nesting depth of `s`[cite: 1]. The nesting depth is defined as the maximum number of nested parentheses present within the string[cite: 1].

A string is considered a Valid Parentheses String (VPS) if it meets one of the following conditions[cite: 1]:
* It is an empty string, or contains a single character not equal to `(` or `)`.
* It can be written as `AB` (A concatenated with B), where both `A` and `B` are VPS.
* It can be written as `(A)`, where `A` is a VPS.

## 📋 Constraints

* `1 <= s.length <= 100`[cite: 1]
* `s` consists of digits `0-9` and characters `'+'`, `'-'`, `'*'`, `'/'`, `'('`, and `')'`[cite: 1].
* It is guaranteed that parentheses expression `s` is a VPS[cite: 1].

## 💡 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `s = "(1+(2*3)+((8)/4))+1"` | `3` | Digit 8 is inside of 3 nested parentheses in the string[cite: 1]. |
| **2** | `s = "(1)+((2))+(((3)))"` | `3` | Digit 3 is inside of 3 nested parentheses in the string[cite: 1]. |
| **3** | `s = "()(())((()()))"` | `3` | Maximum nesting depth reaches 3[cite: 1]. |

## 🧠 Approach

Since the problem guarantees that the input is a valid parentheses string, we don't need to validate the expression. We only care about tracking how "deep" the parentheses go. We can achieve this in two ways:

1.  **Brute Force (Using a Stack):**
    A classic approach for parenthesis problems is using a Stack. When we encounter an open parenthesis `(`, we push it to the stack. When we encounter a close parenthesis `)`, we pop the top of the stack. The size of the stack at any given point represents the current nesting depth. By tracking the maximum stack size during our traversal, we can determine the maximum nesting depth. 

2.  **Optimized (Constant Space):**
    Since we only need to know the *depth* and don't actually need to match specific parenthesis pairs or retrieve prior states, a stack is overkill. We can optimize our space footprint by simply using an integer counter variable `openBrackets`. We increment this counter for every `(` and decrement it for every `)`. We update our maximum depth result using this counter on every iteration.

## 💻 Solution Code

### Brute-force Solution (C++)

```cpp
// Intuition: A stack perfectly models the Last-In-First-Out nature of nested parentheses. The maximum size of the stack directly corresponds to the maximum nesting depth.
// Approach: Traverse the string character by character. Push '(' onto the stack and pop when encountering ')'. Update the maximum depth variable with the current stack size at each step.
// Time Complexity: O(n), where n is the length of the string, as we traverse the string exactly once.
// Space Complexity: O(n), as we allocate extra space for a stack which in the worst-case (all open parentheses) can grow linearly with the string size.
class Solution {
public:
    int maxDepth(string s) {
        int result = 0;
        stack<char> st;
        
        for (char& ch : s) {
            // Push open bracket into stack
            if (ch == '(') {
                st.push(ch);
            } 
            // Pop stack for closing bracket to balance
            else if (ch == ')') {
                st.pop();
            }
            
            // Record the maximum depth seen so far
            result = max(result, (int)st.size());
        }
        
        return result;
    }
};

/*
*
* Dry Run
* Input: s = "(1)+((2))"
* 1. ch = '(' -> push. Stack size = 1. result = max(0,1) = 1.
* 2. ch = '1' -> ignore.
* 3. ch = ')' -> pop. Stack size = 0. result = 1.
* 4. ch = '+' -> ignore.
* 5. ch = '(' -> push. Stack size = 1. result = 1.
* 6. ch = '(' -> push. Stack size = 2. result = max(1,2) = 2.
* 7. ch = '2' -> ignore.
* 8. ch = ')' -> pop. Stack size = 1. result = 2.
* 9. ch = ')' -> pop. Stack size = 0. result = 2.
* Final Result: 2
*
*/
```

### Optimized Solution (C++)

```cpp
// Intuition: We don't need to store the actual parentheses, only their count. A simple counter can effectively mimic the stack size behavior while saving memory.
// Approach: Traverse the string while maintaining an integer counter. Increment the counter for '(' and decrement for ')'. The maximum value this counter reaches is our result.
// Time Complexity: O(n), where n is the length of the string, traversing the string exactly once.
// Space Complexity: O(1), as we are only using constant extra space (two integer variables) regardless of the input size.
class Solution {
public:
    int maxDepth(string s) {
        int result = 0;
        int openBrackets = 0;

        for (char &ch : s) {
            // Increment nesting counter
            if (ch == '(') {
                openBrackets++;
            } 
            // Decrement nesting counter
            else if (ch == ')') {
                openBrackets--;
            }
            
            // Track the maximum nesting depth
            result = max(result, openBrackets);
        }
        
        return result;
    }
};

/*
*
* Dry Run
* Input: s = "()(())"
* 1. ch = '(' -> openBrackets = 1. result = max(0, 1) = 1.
* 2. ch = ')' -> openBrackets = 0. result = 1.
* 3. ch = '(' -> openBrackets = 1. result = 1.
* 4. ch = '(' -> openBrackets = 2. result = max(1, 2) = 2.
* 5. ch = ')' -> openBrackets = 1. result = 2.
* 6. ch = ')' -> openBrackets = 0. result = 2.
* Final Result: 2
*
*/
```

## 📝 Notes
* Pay special attention to typecasting when using `std::stack::size()` combined with `std::max()`. In C++, `size()` returns `size_t` (an unsigned type), while our result variable is an `int`. Ensure you cast `st.size()` to `int` to prevent compilation errors regarding type deduction in `max()`.

## 🔍 Key Insights
* Identifying what data is strictly necessary is crucial for optimizing space complexity. We realize that the characters themselves are irrelevant once identified as brackets, allowing us to drop the `O(N)` stack entirely in favor of an `O(1)` counting variable.
