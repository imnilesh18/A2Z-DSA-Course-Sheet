# 2058. Find the Minimum and Maximum Number of Nodes Between Critical Points

## 📜 Problem Statement

A **critical point** in a linked list is defined as either a **local maxima** or a **local minima**.

*   A node is a **local maxima** if the current node has a value *strictly greater* than the previous node and the next node.
*   A node is a **local minima** if the current node has a value *strictly smaller* than the previous node and the next node.

*Note that a node can only be a local maxima/minima if there exists **both** a previous node and a next node.*

Given a linked list `head`, return an array of length 2 containing `[minDistance, maxDistance]` where `minDistance` is the minimum distance between any two distinct critical points and `maxDistance` is the maximum distance between any two distinct critical points. If there are fewer than two critical points, return `[-1, -1]`.

---

## ⚠️ Constraints

- The number of nodes in the list is in the range `[2, 10^5]`.
- `1 <= Node.val <= 10^5`

## 🧠 Approach & Explanation

To solve this problem, we need to track the distances between the critical points (local maxima and minima). Because a critical point requires both a previous and a next node, the first and last nodes of the linked list can never be critical points. 

### Key Observations:
1.  **Maximum Distance:** The maximum distance will always be the difference in positions between the **first** critical point found and the **last** critical point found in the entire list.
2.  **Minimum Distance:** The minimum distance will always be found between two **adjacent** (consecutive) critical points. 

### Algorithm Strategy:
1.  Initialize pointers/variables to track the previous node, current node, and the current index/position.
2.  Keep track of `firstCriticalIndex` (to help calculate max distance later) and `previousCriticalIndex` (to help calculate the minimum distance dynamically).
3.  Traverse the list. For each node, check if it forms a local maxima or minima by comparing it with its left and right neighbors.
4.  If a critical point is found:
    *   If it's the very first one, record its index.
    *   If we've seen critical points before, calculate the distance from the `previousCriticalIndex` to the current index. Update the overall `minDistance` if this is smaller.
    *   Update `previousCriticalIndex` to the current index.
5.  After the traversal, if we found fewer than two critical points (i.e., `minDistance` was never updated), return `[-1, -1]`. Otherwise, return `[minDistance, previousCriticalIndex - firstCriticalIndex]`.

## 💻 Solution Code

### Approach 1: Simple Pointer Traversal

```cpp
// Intuition: We need to find the shortest and longest distances between any two critical points. The max distance is always between the first and last critical points found. The min distance will always be between two consecutive critical points.
// Approach: Traverse the list maintaining `prev` and `curr` pointers. Track the 1-based index. Whenever a critical point is found, update the `firstCriticalIndex` (if it's the first) or calculate the distance from the `previousCriticalIndex` to update `minDistance`. Max distance is calculated at the end.
// Time Complexity: O(n) where n is the number of nodes in the linked list. We only traverse the list once.
// Space Complexity: O(1) as we only use a constant number of auxiliary variables for pointers and indices.
class Solution {
public:
    vector<int> nodesBetweenCriticalPoints(ListNode* head) {
        int minDistance = INT_MAX; // Initialize to max possible value

        ListNode* prev = head;
        ListNode* curr = head->next;
        int currPosition = 1;      // 1-based indexing for position
        int previousCriticalIndex = 0;
        int firstCriticalIndex = 0;

        while (curr->next != NULL) {
            
            // Check if current node is a local minima or local maxima
            if ((curr->val < prev->val && curr->val < curr->next->val) ||
                (curr->val > prev->val && curr->val > curr->next->val)) {

                    // If it's the very first critical point found
                    if (previousCriticalIndex == 0) {
                        previousCriticalIndex = currPosition;
                        firstCriticalIndex = currPosition;
                    } else {
                        // Update minimum distance with adjacent critical points
                        minDistance = min(minDistance, currPosition - previousCriticalIndex);
                        previousCriticalIndex = currPosition;
                    }
            }

            // Move pointers forward
            currPosition++;
            prev = curr;
            curr = curr->next;
        }

        // Less than two critical points found
        if (minDistance == INT_MAX) {
            return {-1, -1};
        }

        // Max distance is between the last found and the first found
        int maxDistance = previousCriticalIndex - firstCriticalIndex;
        return {minDistance, maxDistance};
    }
};

/*
*
* Dry Run
* Input: head = [5, 3, 1, 2, 5, 1, 2]
* Initialization: prev=5, curr=3, currPos=1, firstCritical=0, prevCritical=0
* Step 1: curr=3 (Not critical). prev=3, curr=1, currPos=2
* Step 2: curr=1 (Critical: 1<3 and 1<2). firstCritical=2, prevCritical=2. prev=1, curr=2, currPos=3
* Step 3: curr=2 (Not critical). prev=2, curr=5, currPos=4
* Step 4: curr=5 (Critical: 5>2 and 5>1). minDist = min(INT_MAX, 4-2) = 2. prevCritical=4. prev=5, curr=1, currPos=5
* Step 5: curr=1 (Critical: 1<5 and 1<2). minDist = min(2, 5-4) = 1. prevCritical=5. prev=1, curr=2, currPos=6
* Loop ends (curr->next is NULL).
* maxDist = 5 - 2 = 3. 
* Result: [1, 3]
*
*/
```

### Approach 2: Value Tracking (Cleaner Code)

```cpp
// Intuition: Instead of pointer manipulation, we can simply track the node values (prev, curr, next) in variables to identify critical points without directly referencing the node objects continuously.
// Approach: Iterate through the list and dynamically shift the values `prevValue = currValue`, `currValue = nextValue`, `nextValue = head->val`. Check the condition for local maxima/minima. Maintain `firstCriticalIndex` and `previousCriticalIndex` to compute the distances.
// Time Complexity: O(n) for a single traversal of the linked list.
// Space Complexity: O(1) auxiliary space, using only integer variables for tracking state.
class Solution {
public:
    vector<int> nodesBetweenCriticalPoints(ListNode* head) {
        int firstCriticalIndex    = 0;
        int previousCriticalIndex = 0;

        // Variables to store shifted node values
        int prevValue = 0;
        int currValue = 0;
        int nextValue = 0;

        int minDistance = INT_MAX;
        int index = 0;
        vector<int> result = {-1, -1};

        while (head != NULL) {
            // Shift values window forward
            prevValue = currValue;
            currValue = nextValue;
            nextValue = head->val;

            // Check if all 3 values are initialized and a critical point condition is met
            if (prevValue != 0 && currValue != 0 && nextValue != 0 && 
                (prevValue > currValue && currValue < nextValue ||
                prevValue < currValue && currValue > nextValue)) {
                
                // First critical point assignment
                if (firstCriticalIndex == 0) {
                    firstCriticalIndex = index;
                } else {
                    // Update min and dynamically update the result array
                    minDistance = min(minDistance, index - previousCriticalIndex);
                    result = {minDistance, index - firstCriticalIndex};
                }
                previousCriticalIndex = index;
            }

            index++;
            head = head->next;
        }

        return result;
    }
};

/*
*
* Dry Run
* Input: head = [1, 3, 2, 2, 3, 2]
* Step 1: head=1 -> prev=0, curr=0, next=1 (No check, variables missing)
* Step 2: head=3 -> prev=0, curr=1, next=3 (No check)
* Step 3: head=2 -> prev=1, curr=3, next=2 (Critical max!). firstCritical=2, prevCritical=2
* Step 4: head=2 -> prev=3, curr=2, next=2 (Not critical)
* Step 5: head=3 -> prev=2, curr=2, next=3 (Not critical)
* Step 6: head=2 -> prev=2, curr=3, next=2 (Critical max!). minDist = min(INT_MAX, 5-2) = 3. result = [3, 5-2=3]. prevCritical=5
* Loop ends.
* Result: [3, 3]
*
*/
```

## 📌 Notes & Key Insights

*   **Boundary Avoidance:** A single-node or two-node linked list will trivially bypass the condition logic because a critical point mandates $3$ nodes minimum (left, center, right). Thus, `curr->next != NULL` is a clean way to ensure bounds.
*   **Optimal Distances:** Finding the maximum distance in an array (or list) of indices is simply `last_element - first_element`. Minimum distance requires finding the smallest difference between adjacent elements. Because we are traversing linearly, the critical indices are naturally discovered in strictly increasing sorted order, making the consecutive difference check highly efficient without extra storage.
