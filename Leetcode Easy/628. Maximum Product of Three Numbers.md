## 📖 Problem Statement

Given an integer array `nums`, find three numbers whose product is maximum and return the maximum product.

## ⚠️ Constraints

* `3 <= nums.length <= 10^4`
* `-1000 <= nums[i] <= 1000`

## 📊 Examples

| Example | Input | Output | Explanation |
| :--- | :--- | :--- | :--- |
| **1** | `nums = [1,2,3]` | `6` | The maximum product is 1 * 2 * 3 = 6. |
| **2** | `nums = [1,2,3,4]` | `24` | The maximum product is 2 * 3 * 4 = 24. |
| **3** | `nums = [-1,-2,-3]` | `-6` | The maximum product is -1 * -2 * -3 = -6. |

---

## 💡 Approach

### The Core Logic
When looking for the maximum product of three numbers in an array, we must account for negative numbers. A product of two large negative numbers results in a large positive number. Therefore, the maximum product will always be the maximum of:
1. The product of the three largest numbers in the array.
2. The product of the two smallest numbers (most negative) and the largest number.

### 1. Brute Force (Sorting)
The most straightforward way to find the top three largest and top two smallest numbers is to sort the array in ascending order. Once sorted, the two smallest numbers will be at indices `0` and `1`, and the three largest numbers will be at indices `n-1`, `n-2`, and `n-3`.
* **Pros:** Easy to write and understand.
* **Cons:** Takes `O(N log N)` time due to sorting.

### 2. Optimized (Single Pass)
Instead of sorting the entire array, we can iterate through the array exactly once to manually keep track of the required values:
* `max1`, `max2`, `max3` (the three largest values)
* `min1`, `min2` (the two smallest values)
By doing this, we reduce the time complexity from `O(N log N)` to `O(N)`, making it much more efficient while using constant space.

## 💻 Solution Code

### Brute Force Solution

```cpp
// Intuition: By sorting the array, the largest numbers are at the end, and the most negative numbers are at the beginning.
// Approach: Sort the array. The answer is the maximum between the product of the last 3 elements or the first 2 elements and the last element.
// Time Complexity: O(N log N) because of the sorting operation.
// Space Complexity: O(1) or O(log N) depending on the sorting algorithm used by the language standard library.

class Solution {
public:
    int maximumProduct(vector<int>& nums) {
        int n = nums.size();
        
        // Sort the array in ascending order
        sort(nums.begin(), nums.end());
        
        // Compare product of top 3 vs product of bottom 2 and top 1
        return max(nums[n-1] * nums[n-2] * nums[n-3], nums[0] * nums[1] * nums[n-1]);
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3, -4, -5]
* Sorted: [-5, -4, 1, 2, 3]
* Option 1 (last 3): 1 * 2 * 3 = 6
* Option 2 (first 2 + last 1): -5 * -4 * 3 = 60
* Result: max(6, 60) = 60
*
*/
```

### Optimized Solution

```cpp
// Intuition: We only need the three largest and two smallest numbers to find the answer. We don't need to sort the entire array.
// Approach: Iterate through the array once, updating variables tracking the top 3 maximums and top 2 minimums. Then compute the maximum possible product.
// Time Complexity: O(N) where N is the length of the array, as we process every element exactly once.
// Space Complexity: O(1) as we only use five integer variables regardless of the input size.

class Solution {
public:
    int maximumProduct(vector<int>& nums) {
        int max1 = INT_MIN; // Largest
        int max2 = INT_MIN; // Second largest
        int max3 = INT_MIN; // Third largest
        int min1 = INT_MAX; // Smallest
        int min2 = INT_MAX; // Second smallest

        for(int &num : nums) {
            // Update maximums if we find a larger number
            if(num > max1) {
                max3 = max2;
                max2 = max1;
                max1 = num;
            } else if(num > max2) {
                max3 = max2;
                max2 = num;
            } else if(num > max3) {
                max3 = num;
            }

            // Update minimums if we find a smaller (or more negative) number
            if(num < min1) {
                min2 = min1;
                min1 = num;
            } else if(num < min2) {
                min2 = num;
            }
        }

        // Return max between 3 largest OR 2 smallest (negatives) * 1 largest
        return max(max1*max2*max3, max1*min1*min2);
    }
};

/*
*
* Dry Run
* Input: nums = [1, 2, 3, -4, -5]
* Initialization: max1, max2, max3 = INT_MIN | min1, min2 = INT_MAX
*
* Step 1 (num = 1): max1=1, max2=MIN, max3=MIN | min1=1, min2=MAX
* Step 2 (num = 2): max1=2, max2=1, max3=MIN | min1=1, min2=2
* Step 3 (num = 3): max1=3, max2=2, max3=1 | min1=1, min2=2
* Step 4 (num = -4): max1=3, max2=2, max3=1 | min1=-4, min2=1
* Step 5 (num = -5): max1=3, max2=2, max3=1 | min1=-5, min2=-4
*
* Result computation:
* Option 1: 3 * 2 * 1 = 6
* Option 2: 3 * -5 * -4 = 60
* Final Return: max(6, 60) = 60
*
*/
```

## 📝 Notes

> **Why do we need the two smallest numbers?**
> In mathematics, the product of two negative numbers yields a positive number. If an array has very large negative numbers (e.g., `-100`, `-50`), their product will be heavily positive (`5000`). Multiplying this by the largest positive number in the array often yields a result far greater than multiplying the three largest positive numbers.

## 🔍 Key Insights

* **Single Pass tracking:** You don't always need sorting to find extremes. Maintaining variables manually is a common optimization pattern that drops `O(N log N)` down to `O(N)`.
* **Boundary tracking order:** When updating variables like `max1`, `max2`, and `max3`, the order of assignment is critical to avoid overwriting values prematurely. Shift values down the chain first (`max3 = max2`, then `max2 = max1`, etc.).
