# 3731. Find Missing Elements

**Problem Link:** [LeetCode - Find Missing Elements](https://leetcode.com/problems/find-missing-elements/)
**Difficulty:** 🟢 Easy
**Tags:** `Array`, `Hash Table`, `Sorting`

<br>

## 📝 Problem Statement

You are given an integer array `nums` consisting of unique integers.

Originally, `nums` contained every integer within a certain range. However, some integers might have gone missing from the array. 

The smallest and largest integers of the original range are still present in `nums`.

Return a **sorted** list of all the missing integers in this range. If no integers are missing, return an empty list.

---

## 🚦 Constraints

* `2 <= nums.length <= 100`
* `1 <= nums[i] <= 100`

---

## 💡 Examples

### Example 1
> **Input:** `nums = [1,4,2,5]`
> **Output:** `[3]`
> **Explanation:** The smallest integer is 1 and the largest is 5, so the full range should be `[1,2,3,4,5]`. Among these, only 3 is missing.

### Example 2
> **Input:** `nums = [7,8,6,9]`
> **Output:** `[]`
> **Explanation:** The smallest integer is 6 and the largest is 9, so the full range is `[6,7,8,9]`. All integers are already present, so no integer is missing.

### Example 3
> **Input:** `nums = [5,1]`
> **Output:** `[2,3,4]`
> **Explanation:** The smallest integer is 1 and the largest is 5, so the full range should be `[1,2,3,4,5]`. The missing integers are 2, 3, and 4.

---

## 🧠 Approach

The problem guarantees that both the minimum and maximum elements of the original range are still present in the array. Since the array contains unique numbers, we can simply determine the boundaries and find out which elements are missing in between.

1.  **Find Boundaries:** Calculate the minimum and maximum values in the `nums` array to establish the target range.
2.  **Optimize Lookups:** Insert all elements of `nums` into a Hash Set. This reduces the time it takes to check if a number exists from `O(N)` to `O(1)`.
3.  **Identify Missing Elements:** Iterate through every integer from the minimum to the maximum value. If the integer is not found in the Hash Set, append it to our result array.
4.  **Sorted Result:** Because our iteration strictly goes from the minimum to the maximum, the missing numbers are naturally discovered and inserted in sorted order, eliminating the need for an explicit sorting step at the end.

// Intuition: We need to find all missing elements in the range from the minimum to the maximum value of the array. Using a Hash Set allows us to look up existing numbers in O(1) time.
// Approach: 
// 1. Find the minimum and maximum elements in the array.
// 2. Insert all array elements into an unordered_set.
// 3. Iterate from the minimum to the maximum element.
// 4. If a number is not in the set, append it to the result vector.
// Time Complexity: O(N + K), where N is the number of elements in nums (to find min/max and build the set) and K is the range (max - min) to iterate through.
// Space Complexity: O(N), for storing the elements in the unordered_set.

class Solution {
public:
    vector<int> findMissingElements(vector<int>& nums) {
        // Find min and max in one line each using STL
        int mn = *min_element(nums.begin(), nums.end());
        int mx = *max_element(nums.begin(), nums.end());

        // Insert all elements into a hash set for O(1) lookup
        unordered_set<int> s(nums.begin(), nums.end());

        vector<int> result;
        // Traverse from mn to mx; missing numbers will be collected in sorted order
        for (int x = mn; x <= mx; ++x) {
            if (s.find(x) == s.end()) {
                result.push_back(x);
            }
        }

        return result;
    }
};

/*
*
* Dry Run
* Input: nums = [5, 1]
* mn = 1, mx = 5
* Hash Set 's' = {5, 1}
* Result array 'result' = []
* Loop x from 1 to 5:
* x = 1: found in 's'
* x = 2: not found -> result = [2]
* x = 3: not found -> result = [2, 3]
* x = 4: not found -> result = [2, 3, 4]
* x = 5: found in 's'
* Output: [2, 3, 4]
*
*/

## 📝 Notes

* Using `std::min_element` and `std::max_element` provides a clean, readable way to find boundaries without writing custom loops.
* An alternative brute-force approach would involve sorting the array first (which takes `O(N log N)`) and then checking the differences between consecutive elements. However, utilizing the Hash Set is generally faster in practice since the problem constraints are small.

---

## 🔍 Key Insights

* **Hash Sets for the Win:** The usage of `std::unordered_set` is the key to optimizing this problem. It allows us to bypass nested loops (which would result in an `O(N * K)` complexity) and perform instant `O(1)` lookups.
* **Implicit Sorting:** By driving the loop from `mn` to `mx`, the algorithm naturally processes numbers in ascending order. This guarantees the result vector is sorted without calling `std::sort()`!

---

## 🚀 Further Exploration

* Consider how this logic would change if the array contained duplicates. The `unordered_set` naturally handles duplicates, but if we used a frequency array or hash map, we'd need to adapt our checks.
* If the range `nums[i]` constraints were massive (e.g., up to $10^9$), an `unordered_set` approach might exceed memory limits, and the problem would likely require a purely analytical or array-based pointer technique.
