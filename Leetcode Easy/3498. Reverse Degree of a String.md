## 📖 Problem Statement

Given a string `s`, calculate its reverse degree.

The **reverse degree** is calculated as follows:
1. For each character, multiply its position in the reversed alphabet (`'a' = 26, 'b' = 25, ..., 'z' = 1`) with its position in the string (1-indexed).[cite: 1]
2. Sum these products for all characters in the string.[cite: 1]

Return the reverse degree of `s`.[cite: 1]

---

## ⚠️ Constraints

- `1 <= s.length <= 1000`[cite: 1]
- `s` contains only lowercase English letters.[cite: 1]

---

## 💡 Examples

### Example 1

| Input | Output |
| :--- | :--- |
| `s = "abc"` | `148` |

**Explanation:**
| Letter | Index in Reversed Alphabet | Index in String | Product |
| :---: | :---: | :---: | :---: |
| 'a' | 26 | 1 | 26 |
| 'b' | 25 | 2 | 50 |
| 'c' | 24 | 3 | 72 |

The reversed degree is `26 + 50 + 72 = 148`.[cite: 1]

### Example 2

| Input | Output |
| :--- | :--- |
| `s = "zaza"` | `160` |

**Explanation:**
| Letter | Index in Reversed Alphabet | Index in String | Product |
| :---: | :---: | :---: | :---: |
| 'z' | 1 | 1 | 1 |
| 'a' | 26 | 2 | 52 |
| 'z' | 1 | 3 | 3 |
| 'a' | 26 | 4 | 104 |

The reverse degree is `1 + 52 + 3 + 104 = 160`.[cite: 1]

## 🧠 Approach & Explanation

To calculate the reverse degree of a given string, we need to mathematically deduce the "reversed alphabet position" for any character and multiply it by its 1-based index in the string. 

1. **Reversed Alphabet Mapping**:
   In a standard 1-based index mapping, `'a'` is `1` and `'z'` is `26`. The offset of any character from `'a'` can be found using `char - 'a'`. 
   To reverse this so that `'a'` maps to `26` and `'z'` maps to `1`, we simply subtract that offset from `26`. 
   Formula: `Reversed Value = 26 - (char - 'a')`

2. **String Position Weighting**:
   The problem specifies that the string index is 1-indexed. Since standard loop iterators (`i`) are 0-indexed, the 1-based position for any character at index `i` is `(i + 1)`.

3. **Accumulation**:
   We iterate through the string, compute the product for each character using `Reversed Value * (i + 1)`, and add it to our running total.

## 💻 Solution Code

### Optimized Solution (C++)

```cpp
// Intuition: We need to calculate a weighted sum of characters based on their reversed alphabet position and 1-based string index. The reversed position of 'a' is 26 and 'z' is 1, which maps to `26 - (char - 'a')`.
// Approach: Initialize a sum variable to 0. Iterate through each character of the string. Calculate its reversed alphabet value, multiply it by its 1-based index (i + 1), and add it to the sum. Return the total sum.
// Time Complexity: O(N), where N is the length of the string, as we traverse it exactly once.
// Space Complexity: O(1), since we only use a few integer variables for calculation.
class Solution {
public:
    int reverseDegree(string s) {
        int result = 0; // Stores the final reverse degree sum
        for (int i = 0; i < s.length(); i++) {
            // (26 - (s[i] - 'a')) gives the reversed alphabet position
            // (i + 1) gives the 1-based index of the character
            result += (26 - (s[i] - 'a')) * (i+1);
        }
        return result;
    }
};

/*
*
* Dry Run
* For s = "abc":
* i = 0, char = 'a': pos = 26 - ('a'-'a') = 26. index = 1. result = 0 + (26*1) = 26.
* i = 1, char = 'b': pos = 26 - ('b'-'a') = 25. index = 2. result = 26 + (25*2) = 76.
* i = 2, char = 'c': pos = 26 - ('c'-'a') = 24. index = 3. result = 76 + (24*3) = 148.
* Return 148.
*
*/
```

## 📌 Key Insights & Notes

- **ASCII Math:** Using ASCII arithmetic `(s[i] - 'a')` is the most efficient way to map character values without relying on auxiliary data structures like HashMaps or Arrays.
- **Integer Bounds:** Given the maximum constraint length of 1000 characters and the max possible single-character product being `26 * 1000 = 26000`, the maximum sum will easily fit within a standard 32-bit signed integer (`int`), so no long-integer data types are required.
- **Further Exploration:** Think about how this problem scales if the constraints were raised to strings of length `10^5`, or if unicode characters were introduced requiring a different base offset approach.
